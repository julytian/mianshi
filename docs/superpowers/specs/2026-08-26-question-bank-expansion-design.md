## 3. 新增模块

### 3.1 微前端

计划 32–35 题，其中 14–16 道深层题。覆盖：

- 微前端适用边界、拆分维度和组织治理。
- qiankun：注册、生命周期、沙箱、样式隔离、通信、路由和常见故障。
- Garfish：运行时、加载机制、沙箱、预加载、子应用治理及与 qiankun 的差异。
- Module Federation：构建时与运行时模型、remote / host、shared、singleton、版本协商、类型和部署。
- Wujie：Web Components + iframe 隔离模型、通信、保活、性能和限制。
- 方案横向对比与选型：qiankun、Garfish、Module Federation、Wujie。
- CSS / JavaScript 隔离、路由同步、跨应用状态、依赖共享、灰度发布和回滚。
- 加载性能、故障降级、可观测性、安全、迁移和遗留系统接入。

内容必须明确区分：

- qiankun / Garfish 以运行时应用编排和隔离为主。
- Module Federation 以模块级远程加载和依赖共享为核心。
- Wujie 以 iframe 隔离结合 Web Components 的渲染容器为核心。

### 3.2 NestJS

计划 35–38 题，其中 15–18 道深层题。定位同时覆盖基础实战、全栈偏前和高级后端主题：

- Module、Controller、Provider、依赖注入与模块可见性。
- Middleware、Pipe、Guard、Interceptor、Exception Filter 的执行顺序与职责。
- DTO、Validation、序列化、统一响应和错误处理。
- REST API、Swagger、版本控制和接口契约。
- JWT、Session、RBAC / ABAC、刷新令牌和安全边界。
- TypeORM / Prisma 的建模、事务、分页、N+1 和性能问题。
- Redis、缓存策略、队列、定时任务、文件上传和消息处理。
- 配置、日志、链路追踪、健康检查、限流、幂等和可观测性。
- 单元测试、集成测试、E2E 测试和测试隔离。
- 部署、容器化、性能分析、集群和优雅停机。
- 微服务 Transport、事件驱动、CQRS、DDD 和模块化单体。
- Metadata、Decorator、Reflector、依赖注入容器等源码机制。
- Vue 前端与 NestJS 的鉴权、类型共享、联调和错误契约。

表达需保持 Node.js / TypeScript 语境，不机械套用 Spring 概念。

### 3.3 前端架构

计划 28–30 题，其中 14–16 道深层题。覆盖：

- 架构目标、约束识别和质量属性。
- 分层、领域拆分、模块边界和依赖方向。
- 状态管理、数据流、接口层、错误模型和权限模型。
- 路由、布局、菜单、微前端和多端架构。
- 组件体系、设计系统、公共能力和平台化建设。
- 性能、稳定性、可观测性、安全和灾备降级。
- Monorepo、依赖治理、构建体系、发布体系和环境治理。
- 技术债识别、架构评审、决策记录和渐进式演进。
- 团队规模、业务阶段与架构复杂度之间的取舍。

## 4. 架构相关模块边界

### 4.1 前端架构

回答「系统应该如何组织和演进」，重点是技术结构、质量属性和治理机制。

### 4.2 架构 / Lead

回答「负责人如何做决策并带团队落地」，重点是人员、排期、协作、质量门禁、事故复盘和技术推动。

### 4.3 前端系统设计

回答「某一具体系统如何端到端设计」，以管理后台、监控平台、组件库、低代码、权限平台等案例展开。

重构时删除重复表述，但保留跨模块链接，形成「架构原则 → Lead 推动 → 案例落地」的阅读路径。

## 6. 深度分层

### 6.1 编号

- 普通题继续使用 `Q1`、`Q2`。
- 深层题统一使用 `D1`、`D2`，便于搜索和制定专项计划。
- 每个核心模块至少有 8 道深层题。
- Vue3、工程化、微前端、NestJS、前端架构至少有 14 道深层题。

### 6.2 深层题模板

```md
### D1. 题目

**考察点：** 面试官希望确认的能力。

::: details 参考答案

#### 基础结论

先给出可在 30–60 秒内表达清楚的结论。

#### 原理深挖

解释运行机制、关键数据结构、调用链或设计原理。

#### 工程场景

结合真实业务规模、故障、迁移或性能治理说明如何落地。

#### 反例 / 踩坑

说明错误方案为何出问题，以及如何识别和修复。

#### 资深回答模板

给出一段强调约束、权衡、验证和结果的口述模板。

:::

**追问链：**

1. ...
2. ...
3. ...
```

### 6.3 原有题升级规则

- 保留准确且有区分度的现有题。
- 对答案偏浅的题补充机制、边界、工程案例和追问。
- 合并高度重复题，避免单纯增加字数。
- 涉及版本差异或框架行为的内容，优先依据官方文档核实。
- 所有答案面向高级 / 资深前端口述，强调约束、取舍、指标和复盘。

## 7. AI 编程实践指南

新增独立实践指南，与 `09-ai-vibe-coding.md` 形成「实践方法 → 面试表达」的双向链接。

### 7.1 Cursor 工作流

- 从需求澄清、设计、计划、实现、验证到提交的完整工作流。
- 上下文工程、文件引用、模型选择、并行代理和审查关卡。
- AI 生成代码的可信度边界、回滚和失败恢复。

### 7.2 前端 Rules

- 解释 `.cursor/rules/*.mdc` 的 frontmatter、`globs` 和 `alwaysApply`。
- Rules 应保持单一职责、简短、可执行，避免塞入整份技术手册。
- 提供可复制示例：
  - Vue3 + TypeScript 组件规范。
  - Pinia / Vue Router 规则。
  - Ant Design Vue 后台规则。
  - Vant / uni-app 多端规则。
  - 测试、可访问性、安全和性能规则。

### 7.3 前端 Skills

- 解释个人 Skill 与项目 Skill 的目录、触发描述和适用边界。
- 说明 `SKILL.md`、渐进式披露、引用文件和工具脚本。
- 提供可复制示例：
  - Vue 组件开发 Skill。
  - 前端代码审查 Skill。
  - 性能排查 Skill。
  - 管理后台页面生成 Skill。
  - 小程序发布检查 Skill。

### 7.4 Hooks 与 MCP

- Hooks 用于确定性的流程约束；Rules / Skills 用于上下文和工作流指导。
- MCP 用于连接 API 文档、浏览器、监控、设计稿等外部信息。
- 给出选型边界、安全风险、密钥管理和失败降级。

### 7.5 Vue 项目完整示例

以 Vue3 + TypeScript + Pinia + Vue Router + Ant Design Vue 项目为例，展示：

1. 如何拆 Rules。
2. 如何组织项目 Skills。
3. 如何让 AI 按需求 → 测试 → 实现 → 审查推进。
4. 如何约束 AI 不臆造 API、不跳过验证、不改无关文件。

AI / vibe coding 题库扩至 26–28 题，新增 Rules、Skills、Hooks、MCP、上下文工程、代理协作和前端项目实践相关面试题。

## 8. 资深前端简历套件

### 8.1 写作指南

- 针对高级 / 资深前端、Tech Lead、全栈偏前 3 种岗位调整关键词和证据。
- 强调业务结果、技术复杂度、个人贡献、架构取舍和团队影响。
- 避免职责罗列、工具堆砌、无法验证的百分比和空泛「负责」表述。

### 8.2 Markdown 模板

模板包含：

- 基本信息与一句话定位。
- 核心优势。
- 技术能力。
- 工作经历。
- 项目经历。
- 管理 / 架构影响力。
- 开源、文章、演讲和 AI 工程实践（按需）。
- 教育经历。

### 8.3 示例简历

提供一份完整资深前端示例，覆盖 Vue3、TypeScript、管理后台、H5、uni-app / 小程序、工程化、微前端、AI 编程和 Java / NestJS 全栈协作。

所有公司、项目、规模和指标均明确标注为「可替换示例」，不得暗示为用户真实经历。

### 8.4 项目改写清单

使用「背景 / 难点 / 决策 / 行动 / 指标 / 复盘」把普通职责改写为资深表达，并提供前后对照示例。

### 8.5 ATS 检查

- 单栏结构、标准标题、纯文本可读性。
- JD 关键词映射，但不机械堆词。
- 日期、职位、公司、技术名词一致。
- 控制页数和信息密度。
- 检查夸大、敏感数据和保密信息。

## 11. 质量验收

### 11.1 自动检查

- 每道 `Q` / `D` 题都有 `::: details 参考答案`。
- 深层题必须包含基础结论、原理深挖、工程场景、反例 / 踩坑、资深回答模板和追问链。
- 不存在 `TODO`、占位文本或空答案。
- 题库总量为 380–410 题。
- 所有内部链接可构建。
- `pnpm docs:build` 返回成功。
- AI 实践指南中的 Rules / Skills 示例结构符合 Cursor 规范。
- 简历示例中所有虚构数据均标注为可替换示例。

### 11.2 人工抽检

- 每个模块至少抽检 20%。
- 检查重复题、概念错误、版本过时和无效扩写。
- 核查微前端各方案的机制边界和选型依据。
- 核查 NestJS 内容使用 Node.js / TypeScript 语境。
- 核查深层题是否具有真实工程取舍，而非仅增加篇幅。
- 核查 AI 实践指南是否可直接用于 Vue 前端项目。
- 核查简历内容是否突出资深证据，而非技术名词堆叠。
