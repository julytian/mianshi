> **怎么用：** 先盖住答案，自己口述 1～2 分钟（取舍、边界、踩坑），再点开 `参考答案` 对照补洞。追问用来模拟面试官加压；踩坑是实战里最容易翻车的点。中英文术语之间请习惯留空格，口述时也建议如此。

### Q1. `unknown` 和 `any` 怎么选？

**考察点：** 类型安全边界、收窄习惯、与第三方脏数据对接

::: details 参考答案
`any` 是「放弃检查」：传进去、传出来都畅通，编译器闭嘴，责任全在你。`unknown` 是「我知道这是未知」：你可以接住任意值，但**用之前必须收窄**（`typeof` / 类型守卫 / 断言在边界上一次做完）。

实战习惯：外部输入（API、`JSON.parse`、`localStorage`、SDK 回调）先标 `unknown`，在边界模块收窄成业务类型，再往内层传。内层业务代码尽量不见 `any`。库类型烂到没法修时，用局部 `any` + 注释「为何逃逸」比全局 `any` 干净。

面试别说「永远不用 `any`」——那不诚实。要说「逃逸点可控、尽量窄、别传染」。
:::

**追问：**
1. `unknown` 赋给别的类型时，为什么比 `any` 更安全？
2. 和 `Record<string, unknown>`、`object` 相比，你怎么接「任意 JSON 对象」？
3. 项目里已经满屏 `any`，你怎么做渐进治理而不拖垮排期？

**踩坑：** `as unknown as T` 双断言等于手动 `any`，只适合「我比编译器更懂」的极少数边界；滥用等于自我安慰。

### Q2. 泛型约束（`extends`）解决什么问题？口述一个真实场景

**考察点：** 泛型约束、keyof、默认类型参数

::: details 参考答案
无约束的 `T` 几乎什么都能进，你在函数里就不敢碰字段。`T extends { id: string }` 是在说：「我只关心有 `id` 的东西，其余字段保留推断」。

常见场景：表格 `getRowKey<T extends { id: string | number }>`、深取字段 `getProp<T, K extends keyof T>(obj: T, key: K): T[K]`、请求封装 `request<T = unknown>(...)`。约束写「最少需要的形状」，别写成整个业务 Entity——否则复用立刻死。

默认类型参数（`T = void`）适合「多数调用方不关心返回值」的 API；约束和默认一起用时，先想清楚「推断失败时掉到哪」。
:::

**追问：**
1. `K extends keyof T` 和 `K extends string` 差在哪？
2. 约束过宽 / 过窄分别会带来什么代码味道？
3. 条件类型 `T extends U ? X : Y` 和约束有什么分工？

### Q3. 常用 Utility Types 你会主动用哪些？哪些在项目里反而添乱？

**考察点：** `Partial` / `Required` / `Pick` / `Omit` / `Record` / `ReturnType` / `Parameters`

::: details 参考答案
高频有用：`Pick`/`Omit` 做表单编辑 DTO 与列表 VO 的差集；`Partial` 做 PATCH；`Record<Union, V>` 做穷尽映射；`ReturnType`/`Parameters` 从已有函数抽类型，避免双份维护。

添乱的：层层 `Partial<Omit<Pick<...>>>` 让人读不懂「到底必填什么」；用 `Partial` 掩盖本该明确的创建 vs Update 模型；`Exclude`/`Extract` 嵌套过深变成「类型体操表演」。

原则：Utility 是手术刀，不是乐高。超过两层嵌套，宁可写一个命名清晰的 `type UserUpdate = { ... }`。
:::

**踩坑：** `Partial` 后所有字段可选，和「字段存在但值可为 null」不是一回事——后端常混用，前端要对齐语义。

### Q4. 闭包与作用域：你会怎么讲「闭包有啥用、有啥坑」？

**考察点：** 词法作用域、自由变量、内存与过期状态

::: details 参考答案
闭包就是函数带着定义时的词法环境跑。用途：工厂函数私有状态、事件处理器记住配置、hooks/composables 里的「实例级」变量、柯里化配置。

坑不在「闭包本身」，而在**抓住了过期的值**：循环里 `var` + 异步；React/Vue 里闭包捕获了旧 props/state；定时器没清导致组件卸了还改状态；长生命周期闭包（全局 EventBus、module 单例）挂着大对象导致泄漏。

口述结构：先说用途 → 再说「抓住引用还是值」→ 再举一个过期闭包事故。
:::

**追问：**
1. `let` 在 `for` 循环里为什么能「修好」经典闭包题？
2. 模块顶层变量算不算闭包？和函数闭包有何异同？
3. 如何排查「闭包泄漏」而不是凭感觉怪闭包？

### Q5. 事件循环：宏任务、微任务，画一条时间线说明 `Promise` / `queueMicrotask` / `setTimeout`

**考察点：** 浏览器事件循环、微任务队列排空、渲染时机直觉

::: details 参考答案
一次大致模型（浏览器）：执行同步 JS → 清空微任务队列（`Promise.then`、`queueMicrotask`、`MutationObserver`）→ 可能渲染 → 取一个宏任务（`setTimeout`、I/O、UI 事件等）→ 再清微任务……

经典口述：

```js
console.log('a')
setTimeout(() => console.log('b'), 0)
Promise.resolve().then(() => console.log('c'))
console.log('d')
// a d c b
```

`async/await` 在 `await` 之后的代码本质是微任务续体。别背「所有 Promise 都比 setTimeout 早」的绝对口号——嵌套、`await` 拆分、以及 Node 与浏览器细节会变；面试给「同步 → 微任务清空 → 宏任务」就够用，再补一句「别用定时器做精确时序」。
:::

**追问：**
1. 微任务里再塞微任务会怎样？会不会饿死渲染？
2. `requestAnimationFrame` 相对微任务大概在哪一档？
3. Vue 的 `nextTick` 和微任务的关系你怎么理解？

**踩坑：** 在微任务里疯狂 `await` 链式干活，主线程长时间不交给浏览器，页面会「卡住」——看着像性能问题，其实是调度问题。

### Q6. `this` 绑定规则：你会怎么一口气压住追问？

**考察点：** 默认 / 隐式 / 显式 / `new` / 箭头函数、严格模式

::: details 参考答案
优先级口头版：`new` > `bind/call/apply` 显式 > 对象调用隐式 > 独立调用（严格模式 `undefined`，非严格指向全局）。箭头函数**没有自己的 this**，继承外层词法 this——所以适合回调，不适合需要动态 this 的方法（除非你故意）。

类字段箭头、Vue Options API 的 methods（别用箭头）、React class 里 bind——都是同一套规则的不同皮肤。面试官扔一段「解构出方法再调用」——隐式绑定丢失，this 飘走。
:::

**追问：**
1. `obj.fn()` 和 `const f = obj.fn; f()` 差在哪？
2. `bind` 多次，以哪次为准？
3. 为什么说「箭头函数不能当构造函数」？

### Q7. 深拷贝的边界在哪？什么时候不该自己写？

**考察点：** 引用类型、循环引用、特殊对象、结构化克隆

::: details 参考答案
「深拷贝」不是一个函数，是一组产品决策：要不要拷函数、Symbol、原型、Date、Map/Set、DOM、File、循环引用？

`JSON.parse(JSON.stringify(x))`：丢函数/`undefined`/Symbol，Date 变字符串，撑不住循环引用——只适合「纯 JSON 数据快照」。手写递归要处理循环（`WeakMap` 记忆）、容器类型、以及「拷到哪一层算深」。

现代优先：`structuredClone`（见 Q21）。业务上更多时候要的是**不可变更新局部字段**（immer / 展开运算符），不是整树深拷贝。整树拷贝贵，还容易拷漏响应式代理。
:::

**追问：**
1. Vue 里对 `reactive` 对象深拷贝要注意什么？
2. 为什么「深拷贝解决了所有引用共享问题」是错的？

**踩坑：** 把 Proxy / 组件实例 / 路由对象塞进深拷贝，轻则报错，重则静默丢行为。

### Q8. 防抖和节流：场景怎么拆？实现上你会盯哪些细节？

**考察点：** debounce / throttle、leading/trailing、取消与卸载

::: details 参考答案
防抖：动作停了再触发——搜索联想、窗口 resize 后重算布局、表单自动保存。节流：固定频率最多一次——滚动埋点、拖拽跟手、按钮防连点（有时用节流或锁）。

实现细节比「setTimeout 模板」更重要：`leading`/`trailing` 要不要首尾都触发；`this`/`arguments` 透传；返回 Promise 时后到的调用如何取消前一次；组件卸载 `cancel`；和 `AbortController` 组合取消进行中的请求。

口述别只背定义，给一对业务例子 +「卸载必 cancel」。
:::

**追问：**
1. 搜索框防抖 300ms，用户选中联想项时还要不要立刻请求？
2. 节流期间最后一次触发丢失，怎么补 trailing？
3. 和「请求序号 / 忽略过期响应」怎么配合？

### Q9. Promise 并发控制：如何限制最多 N 个同时进行？

**考察点：** 并发池、队列、失败策略、与 `Promise.all` 区别

::: details 参考答案
`Promise.all` 是「全开火」；并发池是「工人数固定，做完一个再取下一个」。实现直觉：维护执行中计数 + 等待队列；或用 async 池循环 `await Promise.race(executing)`。

业务点：失败是 fail-fast 还是收集错误继续？要不要重试？结果顺序要不要与输入对齐（占位数组按 index 回填）？取消（`AbortSignal`）怎么传到每个任务？

管理后台批量导出、图片压缩上传、对后端打一批详情接口——都是经典场景。N 的取值看后端限流和浏览器连接数，不是越大越快。
:::

**追问：**
1. `allSettled` 和并发池怎么组合？
2. 如何保证输出顺序与任务数组一致？
3. 中途用户离开页面，池子怎么停？

**踩坑：** 在池子外又包一层无限制的 `map(async ...)`，等于没限流。

### Q10. `async/await` 错误处理，你在项目里的惯例是什么？

**考察点：** try/catch 粒度、错误上抛、边界消化、浮游 Promise

::: details 参考答案
分层：底层库/请求封装把「可预期业务错误」收成统一类型（code/message），不可预期的保留 cause；页面/用例边界 `try/catch` 做 UX（toast）；中间层该抛就抛，别到处吞。

`async` 函数返回的是 Promise——别忘了调用方 `await` 或 `.catch()`，否则变成 unhandled rejection。并行用 `Promise.all` 时一个失败整组挂，看要不要 `allSettled`。在循环里 `await` 是串行，故意并发要用 `map` + 限制。

空 `catch (e) {}` 是事故温床；至少打日志或上报，并决定是否 rethrow。
:::

**追问：**
1. 什么时候该在拦截器吞错，什么时候必须抛到页面？
2. `for await` 和普通 `for` + `await` 的适用场景？
3. 如何统一处理「取消」与「真正失败」？

### Q11. ESM 和 CJS 互操作，你会怎么讲给同事听？

**考察点：** 模块系统、默认导出互操作、双包陷阱

::: details 参考答案
CJS：`require`/`module.exports`，运行时加载，同步为主。ESM：`import`/`export`，静态可分析，浏览器原生友好，利于 tree-shaking。

坑在互操作：`import x from 'cjs-pkg'` 到底拿到 `module.exports` 还是 `.default`，取决于打包器与 `esModuleInterop`；Node 的 `"type": "module"`、双包（CJS+ESM 两份入口）容易「instanceof 失效」或加载到两份拷贝。

前端 Vite/现代工具链默认 ESM 心智；写库时注意 `exports` 字段条件导出。面试讲清楚「静态结构 vs 运行时导出」比背语法有用。
:::

**踩坑：** 同一依赖被打进两份（CJS/ESM 各一），Vue 插件或 context 对不上号——很像「玄学 bug」。

### Q12. Tree-shaking 的直觉：什么能摇掉，什么摇不掉？

**考察点：** 副作用、命名导出、barrel file、CSS/JSON

::: details 参考答案
摇树依赖：ESM 静态结构 + 打包器判定无副作用。命名导出、纯函数模块友好；`import *`、动态 `import()` 路径不确定、有顶层副作用（改全局、polyfill、CSS 副作用导入）会保守保留。

`export * from './x'` 的大 barrel 经常让分析变钝，开发爽、体积疼。副作用标注（`sideEffects` in package.json）是库作者的责任；业务侧少写「为了方便全部 re-export」。

直觉口令：能静态看到「没用到的绑定」且模块无副作用 → 可摇；靠运行时才能知道用啥 → 难摇。
:::

**追问：**
1. 为什么 lodash 全量 `import _` 和 `lodash-es` 按函数导入差很多？
2. CSS Modules / 全局 CSS 跟 tree-shaking 是什么关系？

### Q13. Vue 里 props / emits 的 TypeScript 写法，你推荐哪套？

**考察点：** `defineProps`/`defineEmits` 泛型、运行时声明与纯类型声明、校验边界

::: details 参考答案
`<script setup lang="ts">` 下优先类型声明：

```ts
const props = defineProps<{ modelValue: string; size?: 'sm' | 'md' }>()
const emit = defineEmits<{ 'update:modelValue': [value: string]; change: [id: number] }>()
```

需要运行时校验/默认值时用对象写法或 `withDefaults`。别把复杂业务类型塞进 props 还不拆——子组件会变成上帝。emits 类型写清 payload，避免 `emit('xxx', any)`。

和外部类型同步：props 用业务 `type`，不要在组件里复制粘贴一份接口字段。
:::

**追问：**
1. 类型-only props 和运行时 props 同时存在时要注意什么？
2. `v-model` 多参在类型上怎么建模？

**踩坑：** 解构 `props` 会丢失响应性（要用 `toRefs`/`storeToRefs` 那套心智）；类型对了运行时仍可能传入多余字段——TS 不挡运行时。

### Q14. 前后端类型怎么同步？你见过哪些靠谱与不靠谱方案？

**考察点：** OpenAPI/Swagger、代码生成、契约测试、漂移治理

::: details 参考答案
靠谱方向：以 OpenAPI（或等价 IDL）为契约，前端用 openapi-typescript / 自研生成 `types` + 轻量 client；CI 校验契约变更；后端改字段先改契约。

不靠谱：口口相传；前端手写「猜的」interface；把后端 Java DTO 源码当唯一真相却无生成流水线；生成一次再手改生成物。

折中：核心实体生成，边缘页面手写；或 Zod/io-ts 在边界校验，类型从 schema 推断——运行时兜底比「纯 TS 信仰」更抗炸。
:::

**追问：**
1. 后端字段突然变可选，前端生成类型更新了但页面没改，怎么防？
2. 枚举/字典类数据跟类型同步怎么做？

**踩坑：** 生成类型是 `string`，业务当联合类型用——类型绿了，运行时脏数据照样穿模。

### Q15. 可选链 `?.` 的坑有哪些？

**考察点：** 短路语义、与赋值/调用组合、掩盖空值根因

::: details 参考答案
`a?.b.c` 在 `a` 空时短路；但 `a?.b.c` 若 `a` 有而 `b` 空，访问 `.c` 仍炸——位置要对。`obj?.()` 是「对象为空则不调用」；和 `obj?.method?.()` 不同。

最大产品坑：满屏 `?.` 把「本不该为空」的数据问题吞成 `undefined`，页面空白却不报错，排障更难。该在边界断言/校验的，别在深渲染链上一路可选下去。

和 `??` 组合常见：`a?.b ?? default`——先弄清「没有」和「有但为 null」的语义。
:::

**踩坑：** `left?.[index] = value` 这类可选链赋值限制；以及把 `?.` 当「防御性编程勋章」滥用。

### Q16. 空值合并 `??` 和 `||` 差在哪？什么时候会踩？

**考察点：** nullish coalescing、假值陷阱

::: details 参考答案
`||` 把 `0`、`''`、`false`、`NaN` 都当「没有」；`??` 只把 `null`/`undefined` 当没有。表单里数量 `0`、开关 `false`、允许空字符串，几乎必须用 `??` 或显式判断。

`??=` 适合惰性默认赋值。注意和可选链：`a ?? b ?? c` 可读性尚可，再长就提取变量。和默认参数 `fn(x = 1)`：默认参数不吃 `null`（`fn(null)` 不会回落到 1），`??` 可以补这层。
:::

**追问：**
1. 后端用 `0` 表示「不限」、用 `null` 表示「未设置」，前端默认值怎么写才不容易错？
2. `??` 和 `?.` 优先级相关括号你怎么记？

### Q17. `Map` / `Set` 相对普通对象 / 数组，什么时候更合适？

**考察点：** 键类型、插入顺序、去重、频繁增删查

::: details 参考答案
`Set`：去重、成员存在性（`has` O(1) 均摊），别再用 `array.includes` 扫超级大列表做热点路径。`Map`：键可以是对象引用；频繁增删；需要保证插入顺序迭代；避免 `Object` 把数字键转字符串、或和原型链搅在一起。

对象字面量仍适合「固定形状的记录」、JSON 序列化友好结构。需要 `JSON.stringify` 时 Map/Set 要自己转换。

选型口令：结构化字段用 object；集合语义与任意键用 Map/Set。
:::

### Q18. `WeakMap` / `WeakSet` 适合解决哪类问题？

**考察点：** 弱引用、元数据挂载、防泄漏

::: details 参考答案
键必须是对象，且不阻止 GC。典型：给 DOM 节点或第三方实例挂私有元数据，而不想用可枚举字段污染；库在外部对象上存「已处理标记」；实现深拷贝时的循环引用表（遍历期间）。

不能迭代、不能取 size——这是特性不是缺陷：你不该依赖「弱集合里现在有谁」。需要枚举用 `Map`。

和 Vue 响应式：框架内部大量用弱连接思路管理依赖；业务里少直接碰，但面试能讲清「为何不阻 GC」就加分。
:::

**踩坑：** 把原始类型当 WeakMap 键——直接不行；用完仍被别处强引用，弱也救不了泄漏。

### Q19. Iterator / Generator：前端日常要掌握到什么深度？

**考察点：** 可迭代协议、`for...of`、生成器懒序列、`yield*`

::: details 参考答案

### Q20. `Proxy` 对比 `Object.defineProperty`，为什么 Vue3 换了？

**考察点：** 拦截能力、数组/新增属性、性能与兼容性叙事

::: details 参考答案
`defineProperty` 要在初始化时递归劫持已有属性；新增属性、删除、数组索引/长度等不完整或很别扭（Vue2 的 `$set` 历史包袱）。`Proxy` 代理整个对象，`get/set/has/deleteProperty` 等陷阱更齐全，懒代理也更自然。

代价：环境要支持 Proxy（现代浏览器没问题）；代理身份与原对象不同（`===`、部分库检测）；也不是免费午餐，仍需合理设计依赖收集。

口述抓「能力完整性 + 开发体验」，别只背「Proxy 更快」——快不快看场景。
:::

### Q21. `structuredClone` 能做什么、不能做什么？

**考察点：** 结构化克隆算法、与 JSON 拷贝对比

::: details 参考答案
`structuredClone` 能处理更多内建类型（Date、Map、Set、ArrayBuffer、循环引用等），比 JSON 往返靠谱，是浏览器/平台提供的深克隆。

不能：函数、DOM 节点、部分浏览器对象、带方法的 class 实例（通常丢原型方法，只留数据）。传 `transfer` 可转移可转移对象所有权。

在 Worker 消息、跨上下文时同一套算法也在起作用。业务里：纯数据树优先它；要保留原型行为就别指望克隆。
:::

**踩坑：** 克隆 Vue Proxy 可能丢响应式或抛错——先 `toRaw` 再决定是否该克隆。

### Q22. `AbortController` 怎么用在实战请求里？

**考察点：** 取消、竞态、与防抖/路由切换结合

::: details 参考答案
创建 `AbortController`，把 `signal` 传给 `fetch`/axios；需要取消时 `abort()`。路由切换、搜索防抖新请求发出前、组件卸载——取消上一次，避免「慢请求回写新页面」。

和错误处理：abort 通常表现为特定错误（`AbortError`），UI 层别当失败 toast。多个请求可共享一个 signal，或分层（页面级 + 请求级）。

这是并发与正确性工具，不是性能银弹；但能显著减少竞态 bug。
:::

### Q23. Type narrowing：除了 `typeof`，你还靠什么收窄？

**考察点：** 控制流分析、自定义类型守卫、断言函数

::: details 参考答案
`typeof` / `instanceof` / `in` / 相等判断（含判别字段）都会触发控制流收窄。复杂对象用自定义谓词：`function isUser(x: unknown): x is User`。`asserts x is T` 用于「失败就抛」的校验函数。

别滥用 `as`——那是关闭检查。收窄失败时先问数据模型是否该用判别联合（下一题），而不是强转。
:::

**踩坑：** 解构后收窄不一定保留；通过函数调用「传出去再回来」可能刷新成宽类型——注意引用是否被编译器跟踪。

### Q24. 可辨识联合（Discriminated Unions）怎么设计才好用？

**考察点：** 字面量 tag、穷尽检查、`never`

::: details 参考答案
用一个字面量字段（`type: 'success' | 'error'`）做 tag，各分支携带不同载荷。`switch (res.type)` 里每条分支类型自动收窄；`default` 里把值赋给 `never` 做穷尽检查，新增分支编译期炸——这是联合类型的工程价值。

比一堆可选字段（`data?`/`error?` 同时存在）清晰得多。API 结果、UI 状态机、弹窗互斥内容都很合适。
:::

### Q25. `satisfies` 运算符解决什么痛？和注解类型有何不同？

**考察点：** TS `satisfies`、推断保留、校验形状

::: details 参考答案
`const cfg = { ... } satisfies Config`：检查值符合 `Config`，但**变量推断仍保留字面量细节**（例如键的字面量联合、具体字符串字面量），不会被拓宽成 `string`。

对比 `: Config` 注解——通过检查，但推断常被拓宽，后续 `cfg.mode` 可能丢掉自动补全的字面量信息。适合路由表、主题 token、权限码表「既要符合接口，又要保留精确键」。

老项目无 `satisfies` 时，可用 `as const` + 满足函数校验曲线救国。
:::

**踩坑：** 以为 `satisfies` 会「变成」注解类型去传给只接受宽类型的 API——它主要影响检查与推断，不是运行时转换。

### Q26. 模块扩充（Module Augmentation）轻量场景怎么讲？

**考察点：** `declare module`、扩展第三方类型、全局接口合并

::: details 参考答案
第三方库类型缺字段、或你给 `vue`/`express`/`axios` 挂自定义属性时，用 `declare module 'xxx' { interface ... }` 做合并，而不是改 `node_modules`。

原则：扩充放在独立 `shim.d.ts` / `types/*.d.ts`，范围尽量小；能 wrapper 出自己的类型就别改全局。接口合并是开放的，类型别名不行——这点常考。

滥用会让「真实运行时有没有这个字段」变模糊，最好有运行时赋值点与类型放一起评审。
:::

### Q27. 数组 vs 对象：热点路径上性能与 API 怎么选？

**考察点：** 局部性、查找复杂度、引擎优化直觉、可读性优先

::: details 参考答案
数组：有序序列、栈队列、密集索引；引擎对 packed array 很友好。按 id 高频查找，先建成 `Map`/`Record<id, Item>`，别在渲染热路径 `find` 扫几千条。对象/Map：字典语义；注意属性添加形态变化导致隐藏类/退化（不必背细节，知道「形状稳定更友好」）。

前端多数瓶颈在 DOM、网络、不合理渲染，不在 `[]` vs `{}`。先量再优化；但「列表 + 字典双视角」是正规军做法（列表保序，Map 保查）。
:::

### Q28. 你怎么向面试官证明「你会用 TypeScript」而不是「只会写类型注解」？

**考察点：** 综合表达、边界收窄、与运行时分工、和团队规范
