### 示例统一业务平台（示例）｜前端 Tech Lead（示例）

`2022.02—2024.12（示例）`  
技术栈：Vue 3、TypeScript、Ant Design Vue、Vant、uni-app、微信小程序、Java Spring Boot、NestJS（均为示例）

**背景**

多个示例业务线分别维护后台、H5 和微信小程序，权限、表单、状态与接口错误处理不一致。本人示例职责为前端方案、关键模块和跨团队协作，不代表独立完成全部系统。

**难点**

- 多角色、多组织权限与动态流程叠加，配置错误会影响业务操作。
- Web、H5、uni-app 和小程序能力不同，复用过度会增加条件分支。
- Java Spring Boot 核心服务与 NestJS BFF 并存，错误模型和发布节奏不同。

**决策**

将领域类型、校验和请求契约作为共享层，端特有交互保留在应用层；没有选择“一套组件运行所有端”。微前端只用于需要独立发布且团队边界明确的模块，并保留版本兼容与回滚入口。

**行动**

- 设计示例权限模型、动态表单协议和 API 类型生成流程。
- 与 Java、NestJS 协作者统一分页、错误码、鉴权过期和链路标识。
- 建立契约测试、关键路径端到端测试、灰度清单和发布后观测。
- 通过评审模板和结对方式帮助示例团队成员理解边界，而非只下发规范。

**结果**

- “重复业务组件减少 24%”仅为示例指标；示例口径为代码仓库中被至少 2 个应用重复维护、功能等价的组件数量，比较治理立项与验收两个快照，需保留盘点表和判定规则。
- “跨端需求平均交付周期缩短 18%”仅为示例指标；示例口径为需求系统中同时涉及至少 2 个端、状态为完成的需求，从进入开发到生产发布的自然日中位数，比较前后各 2 个季度，并说明需求复杂度变化可能造成偏差。

**复盘**

共享层初期包含了部分端特有状态，导致升级协调成本增加。后续按领域契约和 UI 适配重新划界，并增加破坏性变更检查。真实使用时应替换为本人经历中的失败与改进。

### 示例前端性能与稳定性治理（示例）｜技术负责人（示例）

`2023.03—2024.06（示例）`  
技术栈：Vue 3、Vite、Web Vitals、前端监控平台（示例）

**背景**

“示例运营后台”在特定网络和大数据量页面中加载慢，版本发布后缺少统一观测。项目目标是建立可持续诊断与回归机制，而非完成一次性优化。

**难点**

- 实验室数据与真实用户数据差异明显；
- 页面同时受接口、资源、渲染和第三方脚本影响；
- 发布频繁，优化结果可能受到业务改版干扰。

**决策**

先统一真实用户监控口径，再按用户影响与修复成本排序；没有直接以首页 Lighthouse 单次得分作为全站结论。对高风险拆包策略先灰度，并保留旧产物回滚。

**行动**

- 按路由、版本、设备和网络维度采集 LCP、INP、错误率与资源耗时。
- 通过性能剖析定位长任务，拆分重计算与非首屏资源，并限制第三方脚本加载时机。
- 把性能预算、Source Map 上传检查和告警确认纳入发布流程。

**结果**

- “P75 LCP 从 3.8 秒降至 2.4 秒”仅为示例指标；示例口径为监控平台中指定核心路由、移动设备、4G 网络且完成加载的真实会话，比较优化前后各 28 天，并按版本排除灰度交叉期。
- “前端未捕获异常会话率从 1.6% 降至 0.7%”仅为示例指标；示例口径为发生至少一次未捕获异常的会话数除以有效会话数，时间窗为治理前后各 8 周，需说明采样率和监控 SDK 升级影响。

**复盘**

初期告警阈值过于敏感，产生噪声。后续按核心路由和版本设置分层阈值，并将告警有效率纳入月度复盘。示例数字不得直接沿用。

### 示例 AI 辅助研发治理（示例）｜推动者（示例）

`2024.07—2025.01（示例）`  
技术栈：Cursor Rules、Cursor Skills、TypeScript、CI（示例）

**背景**

示例团队开始使用 AI 辅助开发，但上下文缺失、生成结果不一致，且存在误改和敏感信息风险。

**决策**

将 AI 定位为受约束的研发辅助工具：Rules 提供项目级规则，Skills 承载可重复流程；高风险业务、权限和数据处理仍要求人工设计与评审。

**行动**

- 编写目录边界、TypeScript、测试和敏感信息规则，并记录规则适用范围。
- 建立任务拆分、改动自检和评审 Skills，输出必须进入既有 CI。
- 以抽样评审记录缺陷类型，不用主观“节省大量时间”作为结论。

**结果**

“模板类改动一次评审通过率从 62% 提升至 79%”仅为示例指标；示例口径为代码评审平台中标记为模板类、首次评审未要求实质修改的合并请求占比，比较试点前后各 6 周，同时记录样本量与人员构成。该结果不能归因于 AI 单一因素。

**复盘**

规则过长会降低命中质量，且旧规则可能与代码演进冲突。后续按场景拆分并设置维护人和季度复核日期。
