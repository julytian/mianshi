# 工程与质量速记

> **真源：** [03 工程化](/interview/questions/03-engineering)、[20 性能体验](/interview/questions/20-performance-ux)、[21 测试质量](/interview/questions/21-testing-quality)、[09 AI 编程](/interview/questions/09-ai-vibe-coding) 为唯一真源；冲突时以题库为准。
>
> **用法：** 面试前遮住口述稿先自讲，再对结论卡与追问速答。证据坑位请填入你自己的项目指标，勿背他人数字。[AI 编程指南](/interview/guides/ai-coding/cursor-workflow) 仅作补充操作材料，不另开第二套标准答案。

## 一句话定位

本域讲清「构建与发布门禁 + Core Web Vitals / RUM 治理 + 按风险分层的测试组合 + AI 辅助时的质量责任」。资深面试要的是**可回滚的交付证据**，不是工具名堆砌。你应能在五分钟内把体积归因、性能预算、测试层级与灰度停止线串成一条发布故事。

## 核心结论卡

1. **结论：** 环境变量按「构建期注入」与「运行时可替换」分开；Vite 只有 `VITE_` 前缀进客户端包。  
   **边界：** 密钥永不进前端包；一次构建多环境靠不可变制品 + 运行时配置 schema，而不是每个环境重打一次业务逻辑。  
   **证据坑位：** 〔填〕预发 / 生产配置注入方式与一次误打包密钥的复盘。

2. **结论：** 体积膨胀先归因：路由懒加载、重复依赖、错误 sideEffects、未拆的巨型库。  
   **边界：** 分析要用生产构建产物；dev server 体积不是发布证据。  
   **证据坑位：** 〔填〕一次 bundle 归因前后的主包 / 异步包对照。

3. **结论：** 代码分割兼顾首屏、瀑布与长期缓存；文件不是越小越好，hash 级联要可控。  
   **边界：** 动态 `import` 字符串要静态可分析；过度拆包会换来请求瀑布。  
   **证据坑位：** 〔填〕关键路由的 chunk 图与首屏请求数。

4. **结论：** ESLint 管对错与约定，Prettier 管格式；冲突以「格式归 Prettier、逻辑归 ESLint」收场。  
   **边界：** Husky + lint-staged 是本地快反馈，不能替代 CI 门禁。  
   **证据坑位：** 〔填〕本地钩子与 CI 任务清单对照。

5. **结论：** Monorepo 卖的是任务图、共享约束与 affected；组织边界不清时上仓只会放大耦合。  
   **边界：** pnpm 的内容寻址与严格依赖图能减少幽灵依赖，但要配好 workspace 协议与发布策略。  
   **证据坑位：** 〔填〕是否上 Monorepo 的决策表：团队数 / 发布频率 / 共享包数。

6. **结论：** LCP 看最大内容绘制，INP 看交互到下一帧，CLS 看布局稳定性；优化要绑 RUM 长尾。  
   **边界：** Lab 用于复现，RUM 用于决策；不要用实验室满分代替真实用户分层。  
   **证据坑位：** 〔填〕核心页面 LCP / INP / CLS 的 P75 与设备分层。

7. **结论：** 首屏治理按阶段拆：TTFB、关键资源、主线程、渲染、业务数据；每步有预算与回滚。  
   **边界：** Resource Hints 滥用会抢带宽；第三方默认不进关键路径。  
   **证据坑位：** 〔填〕一次首屏治理的前后 RUM 与回滚开关。

8. **结论：** 缓存分层：HTML 短缓存或再验证，哈希 JS/CSS 长缓存，API 按业务新鲜度；发布要保证入口只引用已上传资源。  
   **边界：** 回滚靠切换入口 / 保留旧哈希，而不是幻想全网瞬间清 CDN。  
   **证据坑位：** 〔填〕一次可回滚发布的入口切换与客户端恢复观察。

9. **结论：** 生产 Source Map 应进受控 artifact，不默认公开到 CDN；还原错误要版本与 map 精确匹配。  
   **边界：** 隐藏 map 不等于「没有 map」；调试链路要可审计。  
   **证据坑位：** 〔填〕一次线上错误还原到源文件行号的记录。

10. **结论：** 灰度要有分群黏性、观测窗口、停止线与回滚动作；Feature Flag 与分支策略配合，避免长期幽灵分支。  
    **边界：** 切流量秒级 ≠ 所有客户端秒级恢复；要看恢复分位数。  
    **证据坑位：** 〔填〕一次灰度停止线触发与回滚演练。

11. **结论：** 测试按风险选层：unit / component 保纯逻辑，集成保协作，E2E 保关键用户任务；不追求固定金字塔比例。  
    **边界：** 同一行为多层无价值重复会拖慢反馈；Flaky 是未受控状态的证据。  
    **证据坑位：** 〔填〕关键链路的测试层级地图与 flaky 清零窗口。

12. **结论：** Vue 组件测用户可见行为，少绑实现细节；composable 要测生命周期与卸载清理。  
    **边界：** fake timers、`flushPromises`、`nextTick` 语义不同，不能靠 sleep 碰运气。  
    **证据坑位：** 〔填〕一次竞态 / 取消单测的不变量断言。

13. **结论：** MSW 适合网络边界；契约用版本化 schema + consumer-driven contract，再配少量部署后 E2E。  
    **边界：** 覆盖率不是质量本身；a11y 自动化不能单独宣称符合 WCAG。  
    **证据坑位：** 〔填〕契约破坏如何在 CI 被挡住的一次记录。

14. **结论：** AI 编程要任务拆分、上下文边界与人工验收；Rules / Skills 是约定，不是强制安全边界。  
    **边界：** 幻觉 API、越权路径、密钥进仓库必须人工挡；敏感信息不进 prompt。  
    **证据坑位：** 〔填〕团队 AI 规范条目与一次幻觉拦截案例。

15. **结论：** 依赖升级按风险与可达性治理：锁文件、安装脚本、审计、SBOM；避免「从不升」或「一次炸」。  
    **边界：** `npm audit` 告警要区分可达利用路径，不是分数焦虑。  
    **证据坑位：** 〔填〕一次依赖 CVE 处置：影响面、升级或缓解、回归范围。

16. **结论：** 镜像、探针、K8s 滚动与 CDN 回滚的细则见 [运维与部署速记](/interview/review/sheets/07-devops)；本域只守「不可变制品 + 可解释门禁」接口。  
    **边界：** 静态站优先对象存储 + CDN，勿在本域重复背完整 Deployment 话术。  
    **证据坑位：** 〔填〕本仓制品晋级到运维发布面的衔接点说明。

17. **结论：** CI 用任务图、并行、affected 缩短反馈；远程缓存要输入完备与防投毒边界。  
    **边界：** 「这台机器才能编过」必须容器化构建消除；容器与 agent 细节详见运维速记。  
    **证据坑位：** 〔填〕MR 到绿灯的中位时长与瓶颈任务。

18. **结论：** 质量门禁要可解释：测什么、阈值、owner、例外期限与补偿控制；紧急放行必须限时可审计。  
    **边界：** 重试把红灯变绿不是门禁，是掩盖。  
    **证据坑位：** 〔填〕一次紧急例外单与事后补偿完成记录。

## 高频追问速答

1. **`VITE_` 前缀到底防什么？**  
   它防的是「任意服务端环境变量被打包进浏览器」。只有带此前缀的变量会暴露给客户端代码，其余留在 Node 构建环境。这不等于密钥安全：凡是进了客户端的值都可被用户看见。密钥应留在服务端或构建机密存储；多环境应用一次构建加运行时配置，避免每个环境重编业务并漏配。

2. **为什么 Lab 满分不能直接宣称体验达标？**  
   实验室环境可控，便于复现与对比，但设备、网络、采样与用户路径与真实流量不同。决策应看 RUM 分层长尾，Lab 用来定位与验证假设。Core Web Vitals 要绑页面、版本、设备档与样本量；没有基线、owner 与回滚的「优化」无法验收，也容易优化错人群。

3. **首屏优化你按什么顺序动手？**  
   先用同一次 trace 拆 TTFB、关键资源发现与下载、主线程长任务、渲染与业务数据就绪，再按预算砍最大项。通常先保证 HTML / 关键 CSS / 关键请求路径干净，再谈图片、字体与第三方。每项改动要有前后对比与回滚开关，避免同时改十处却说不清因果。

4. **E2E flaky 你怎么治？**  
   先保证 worker 身份与数据命名空间隔离，再用 trace、网络、日志区分产品竞态、选择器不稳、环境抖动。Flaky 是未受控状态的证据，不是「再多打几次重试」。要有 owner 与期限：修复、隔离或删测；用固定 sleep 碰绿的测试应从门禁剔除，直到写成显式等待条件。

5. **灰度停止线怎么定？**  
   先定义观测窗口内的错误率、关键任务成功率、性能 SLO 与客诉代理指标，再设自动或人工停止阈值与回滚动作。分群要黏性，避免同一用户反复进出。控制面切入口可以很快，但客户端恢复看分位数；没有旧资源保留与入口可切，就谈不上可回滚灰度。

6. **组件测试为什么少断言内部状态？**  
   绑定 `data`、私有函数或具体 DOM 结构会让重构必挂，测试变成实现快照。更稳的是断言用户可见文本、角色、禁用态与发出的事件 / 请求。composable 则要覆盖挂载后订阅、依赖变更与卸载清理。时间与异步要用可控时钟和显式 flush，保证「最新结果获胜、取消后无写回」。

7. **AI 生成代码你上线前查什么？**  
   先核对接线是否真存在：路由、权限码、环境变量、依赖版本与类型是否通过。再查越权、注入、密钥与日志脱敏；用测试与契约证明关键路径，而不是只看「能演示」。提示词要给边界与验收标准；发现幻觉 API 立即停用并补回归。团队用统一 Rules，但不把模型指令当安全控制面。

8. **静态站部署选型你怎么一句收口？**  
   只需哈希静态资源时，对象存储加 CDN 通常优于强行进集群占 Deployment；SSR / 平台只收镜像时再上 Kubernetes。本域先讲清 HTML 短缓存、资源长缓存与可切入口；多阶段镜像、非 root、探针与滚动细则指向 [运维速记](/interview/review/sheets/07-devops)，避免两册各背一套完整发布话术。

## 反例 / 红线

- 用开发服务器体积或未压缩产物当性能与体积证据。
- 密钥进前端包、Source Map 默认公开到 CDN、锁文件形同虚设。
- 无停止线、无旧资源保留的「灰度」；用重试把红灯测绿。
- 覆盖率数字代替风险覆盖；只用 axe 宣称符合 WCAG。
- 把 AI 输出直接合入主干，不做权限与幻觉审查。
- Monorepo 无任务图与所有权，变成共享泥球。

## 5 分钟口述稿

「工程与质量我按发布链路讲：本地反馈、CI 门禁、产物与缓存、灰度观测、线上 RUM。

构建侧先分清客户端可见配置与密钥；体积用生产产物归因，分割要兼顾首屏和长期缓存。ESLint / Prettier / husky 管本地速度，CI 才是权威门禁；Monorepo 有任务图和 affected 才值得上。

性能上 LCP、INP、CLS 绑 RUM 长尾，Lab 负责复现。首屏按阶段拆预算，第三方默认隔离。发布上 HTML 短缓存、哈希资源长缓存，灰度有停止线和可切入口，Source Map 进受控存储。

测试按风险选层，组件测行为不测私有实现，E2E 治 flaky 靠隔离而不是重试。AI 辅助要拆任务、审越权与幻觉，Rules 不能替代安全边界。最后用自己项目的门禁时长、一次灰度回滚和一次 CWV 治理收口。」
