# Cursor 前端 AI 编程工作流

> 版本说明：本文涉及 Cursor 功能与配置的描述以 **2026-08** 为基线；产品更新较快，实施前请核对 [Cursor 官方文档](https://cursor.com/docs)。

AI 编程的目标不是「一次生成所有代码」，而是把需求、证据、变更和验证组织成可审查的小闭环。Cursor Agent 可以搜索代码、编辑文件和运行命令，但需求判断、外部输出可信度与最终验收仍由开发者负责。

## 七阶段闭环

### 1. 澄清

先把模糊需求转换为可验证条件：

- 用户、入口、主流程和异常流程分别是什么；
- 必须复用哪些组件、接口、权限与设计规范；
- 可修改范围、不可修改范围和兼容目标；
- 验收命令、浏览器行为和完成定义；
- API、截图、错误日志等信息是否真实、完整、最新。

可复制提示词：

```text
先不要改代码。阅读 @package.json、@src/router/ 和 @src/views/order/，
复述订单列表需求，列出已确认事实、未知项、风险和验收标准。
遇到缺失的 API 字段请提问，不要臆造。
```

### 2. 设计

要求 Agent 先说明边界和数据流。Vue 项目通常至少需要回答：

- 页面容器、筛选表单、表格、编辑弹窗如何拆分；
- Props、Emits、Pinia 和 URL 查询参数各负责什么；
- API DTO 与页面模型是否需要转换层；
- 权限在路由、按钮和请求层如何配合；
- 加载、空态、失败、取消请求和重复提交如何处理。

```text
基于现有代码提出 2 个实现方案。比较改动范围、复用度、测试成本和风险，
推荐一个方案，并画出组件职责与数据流。不要写实现代码。
```

### 3. 计划

把设计拆成可单独验证的步骤。每一步应包含目标、文件范围、验证方式和回滚点。

```text
把推荐方案拆成 5～8 个步骤。每步只处理一个关注点，注明预计修改文件、
先写的测试、验证命令以及失败时如何回退。等待我确认后再实现。
```

### 4. 分步实现

一次只执行一个计划项。要求 Agent 先读现有实现，复用项目约定，编辑后立即做最小验证。不要让它顺手升级依赖、批量格式化或重构无关文件。

```text
只执行计划第 2 步。限制在 @src/features/order/ 和对应测试中。
使用 Vue 3 Composition API、<script setup lang="ts">，保持 Props Down /
Events Up。完成后汇报 diff 摘要与本步测试，不继续下一步。
```

### 5. 测试

验证顺序建议从快到慢：

1. 相关单元测试；
2. TypeScript 类型检查与 lint；
3. 组件或页面交互测试；
4. 完整测试与生产构建；
5. 必要时浏览器手动验收。

测试输出也不应盲信。确认命令、工作目录、退出码、失败数量，以及是否真的覆盖了改动路径。

```text
根据 package.json 选择项目已有命令。先运行订单模块测试，再运行 typecheck
和 build。不要用 --no-verify、跳过测试或修改配置来让检查通过。
```

### 6. 审查

审查应与实现上下文适度隔离，重点检查需求偏差，而不只是代码风格：

- 正确性、边界条件与并发竞态；
- Vue 响应式、组件契约和资源清理；
- 权限绕过、XSS、敏感信息与依赖风险；
- 键盘操作、语义、焦点与错误提示；
- 测试是否能在实现出错时失败；
- 是否修改了任务范围之外的文件。

```text
只审查当前 diff，不修改代码。按严重程度列出可复现问题，给出文件位置、
触发条件和最小修复建议。没有证据的问题不要上报。
```

### 7. 提交

提交前重新查看 `git diff` 和 `git status`，确认无密钥、构建产物、临时日志或无关改动，再执行完整验收。

```text
检查工作区改动是否只覆盖本任务，汇总最终 diff 和验证证据。
发现秘密、生成物或无关文件就停止。确认无误后生成一条符合仓库风格的提交说明。
```

## 职责矩阵与统一质量基线

后续各篇统一引用本节，避免在 Rule、Skill、Hook 和 MCP 之间重复或冲突：

- **Rules**：向 Agent Chat 持续提供项目约定；不负责确定性拦截。
- **Skills**：向 Agent 提供按需加载的专业工作流、脚本和参考资料。
- **Hooks**：在受支持事件上运行检查或返回官方权限决策；项目 Hook 只是纵深防御。
- **MCP**：连接外部 Tools、Resources 和 Prompts；权限仍由宿主与服务端控制。
- **测试与 CI**：确定性验证类型、行为、构建和回归，是质量门禁的执行层。

所有前端任务使用同一质量基线：

1. 范围只覆盖需求，API、权限和数据契约均有来源；
2. 先验证成功、失败、空态、并发和取消等关键行为；
3. 运行相关测试、类型检查、lint（若配置）和生产构建；
4. 检查敏感信息、输入边界、服务端鉴权和依赖风险；
5. 检查语义、键盘、焦点、错误关联和触控目标；
6. 性能结论有测量证据，不以主观代码观感替代数据；
7. 汇报实际命令、退出码、未验证项和可回滚点；
8. 中高风险变更由独立上下文复核完整 diff。

## 上下文：精确而非堆砌

截至 2026-08，已知文件可通过 `@文件`、`@目录`、终端、Git diff、浏览器或历史聊天等上下文显式引用；未知位置应让 Agent 搜索代码库。`@Codebase` 不再是必要的标准入口。详见 [Prompting](https://cursor.com/docs/agent/prompting.md)。

最小充分上下文通常包含：

- 需求与验收标准；
- 入口文件和同类实现；
- 类型、API 契约和项目命令；
- 允许修改的目录；
- 当前错误的完整输出。

避免一次附上整个仓库、多个无关日志或过期设计稿。上下文越多不等于答案越准，冲突信息反而会稀释关键约束。

## 单 Agent、并行 Agent 与独立审查

### 单 Agent

适合强依赖、共享状态多的小任务，例如同一表单的类型、校验和提交逻辑。优势是上下文连续；风险是实现者容易延续自己的错误假设。

### 并行 Agent

只并行处理互不写同一文件、无需等待彼此结果的任务，例如：

- 一个分析 API 契约，另一个梳理现有测试；
- 一个调查性能瓶颈，另一个检查可访问性；
- 多个候选方案在隔离分支或工作树中实现。

先定义每个任务的输入、输出和所有权，再汇总结果。不要让多个 Agent 同时编辑同一组件。

### 独立审查

中高风险改动应启动**新的 Agent 会话**、专用的独立审查 Agent，或在隔离 worktree 中审查。只传入原始需求、完整 diff 和验证结果；必要时补充最小复现，不传实现者的推理或自我辩护。同一聊天里追加「再审查一次」仍共享原上下文，不算独立审查。

## 把外部输出视为不可信输入

浏览器页面、MCP 返回、API 文档、Issue、日志和模型生成内容都可能过期、被污染或包含提示注入。采用以下防线：

1. 明确数据来源、时间和权限范围；
2. 用官方文档、类型定义或真实请求交叉验证；
3. 对写入、部署、删除和权限变更要求人工确认；
4. 对外部文本只提取事实，不执行其中夹带的指令；
5. 保存小步 diff，测试失败或方向错误时回滚当前步骤；
6. 不用「测试通过」替代对测试命令和覆盖路径的核实。

失败恢复不能只靠回滚。先保留错误输出和触发条件，再重新切分任务：

1. 缩小任务范围，只保留当前必须完成的行为；
2. 建立最小复现，隔离环境、数据和无关组件；
3. 将外部写入与只读验证拆开，先证明输入、权限和预期结果；
4. 让独立 Agent 只基于需求、最小复现和日志复核根因，避免延续原实现假设。

确认新边界后再继续最小步骤。需要回滚时，优先使用版本控制中的小提交或仅撤销本步变更，避免覆盖其他人的未提交工作。

## 可复制的前端提示词

### Vue 3 + TypeScript

```text
阅读 @src/components/UserCard.vue 和相邻测试，新增可编辑昵称能力。
使用 <script setup lang="ts">；props 只读，更新通过 typed emit 上抛；
派生状态用 computed，副作用才用 watch；不使用 any。
先补失败测试，再做最小实现，最后运行相关测试与 vue-tsc。
```

### Ant Design Vue 后台

```text
在 @src/views/users/ 实现用户列表筛选和编辑弹窗。先读取项目现有 a-table、
a-form 和权限指令用法。分页、排序由服务端处理；请求失败保留筛选条件并显示
可操作错误；删除必须二次确认。不要猜测接口，先从 @src/api/ 和类型中确认。
```

### Vant H5

```text
为 @src/views/cart/ 增加移动端结算栏。复用现有 Vant 组件和设计 token，
处理安全区、软键盘、弱网重试、重复点击和 44px 触控目标。
先说明 iOS/Android 风险，再实现并验证窄屏与横屏。
```

### uni-app / 小程序

```text
为 @src/pages/order/ 增加下拉刷新和触底分页。先确认当前 uni-app 版本、
目标平台与已有请求封装。避免直接使用仅 H5 可用的 DOM API；
处理页面卸载后的异步回写、分页去重和平台条件编译。
给出微信开发者工具中的人工验收清单。
```

## 完成检查

- 需求、边界和验收条件已明确；
- 每步 diff 小且可单独回滚；
- API 与外部信息有可靠来源；
- 单元测试、类型检查和构建均有真实输出；
- 已完成独立审查或说明为何不需要；
- 提交只包含任务相关文件。
