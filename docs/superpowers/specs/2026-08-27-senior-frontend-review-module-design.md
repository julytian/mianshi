# 资深前端复习模块设计

## 1. 背景与目标

站点已具备：

- 九大能力域、26 个题库、630 道主问题及全部追问答案；
- 7 / 14 / 30 / 60 天学习路线；
- 模拟面试、简历套件、运维与 AI 指南。

仍缺少独立的「复习」层：面试前无法按能力域速记、按高频战场完整复述，也无法用专门的临场日程调度速记与专题。

本次目标：

1. 新增复习模块，与学习路线、题库形成三层分工。
2. 提供 9 篇域速记册 + 12 篇高频专题完整讲义。
3. 提供面试前 3 / 7 / 14 天回炉计划。
4. 以题库为唯一真源，避免第二套互相打架的口径。
5. 采用分批交付：先骨架与样板，再扩写全部内容并部署。

## 2. 已确认决策

| 项 | 选择 |
| --- | --- |
| 形态 | D：速记册 + 专题讲义 |
| 深度 | 完整第二套可讲讲义（非纯索引） |
| 真源 | 题库为唯一真源；冲突时改复习层 |
| 粒度 | 9 域速记 + 12 高频专题 |
| 日程 | 面试前 3 / 7 / 14 天回炉计划 |
| 交付 | 方案 2：骨架 → 样板 → 批量扩写 → 日程填满与发布 |

## 3. 三层职责

| 层 | 职责 | 不做什么 |
| --- | --- | --- |
| 学习路线 | 长期能力建设（7 / 14 / 30 / 60 天） | 不负责面试前压缩回炉 |
| 题库 | 版本事实、边界、主答案与追问答案的唯一真源 | 不改成速记文风 |
| 复习模块 | 完整可讲的浓缩讲义 + 临场日程 | 不发明与题库冲突的新口径 |

冲突处理：

1. 版本基线、API 语义、安全边界、平台差异以对应题库为准。
2. 复习层只允许浓缩、重组、补口述脚手架与案例坑位。
3. 发现冲突时优先修正复习文；仅当题库确有错误时才改题库，并单独提交说明。

## 5. 内容标准

### 5.1 速记册（9 篇）

每篇必须包含：

1. 本域一句话定位；
2. 核心结论卡 12～20 条：结论 → 边界 → 一句话项目证据坑位；
3. 高频追问速答 6～10 条，各约 80～150 字；
4. 反例 / 红线；
5. 必链题库（模块 + 关键 Q/D 题号）；
6. 5 分钟口述稿。

篇幅：每域约 2500～4500 字中文，完整可讲。

域与题库映射：

| 速记 | 题库 |
| --- | --- |
| Web 与计算机基础 | 01 / 16 / 17 / 18 / 10 |
| 框架与数据 | 02 / 23 / 24 / 25 |
| 工程与质量 | 03 / 20 / 21 + AI 指南 |
| 后台与业务前端 | 04 / 05 |
| 移动端与跨平台 | 06 / 19 |
| 架构与系统设计 | 14 / 11 / 12 |
| 运维与部署 | 26 + DevOps 教程 |
| 全栈、数据与 AI | 07 / 13 / 15 / 09 + Prisma 教程 |
| 领导力与求职 | 08 / 22 + 简历 / 模拟 |

### 5.2 专题讲义（12 篇）

每篇必须包含：

1. 战场是什么 / 面试官想听什么；
2. 知识地图（机制链路）；
3. 完整讲解（可讲 15～25 分钟）；
4. 工程取舍与故障案例模板；
5. 追问树（主问 → 2～3 层 → 收口）；
6. 题库深挖入口（Q/D 清单）；
7. 15 分钟口述验收清单。

篇幅：每专题约 4000～8000 字。

专题与主映射：

| 专题 | 主映射题库 |
| --- | --- |
| JS 运行时与异步 | 01 |
| TypeScript 类型系统 | 01 |
| 浏览器渲染与性能底座 | 17 / 20 |
| 网络与 Web 安全 | 18 |
| Vue3 响应式与渲染 | 02 |
| Nuxt SSR / 同构 | 23 / 02 |
| Vite 与 Webpack 构建器 | 24 / 25 / 03 |
| 性能、测试与质量门禁 | 20 / 21 / 03 |
| 微前端与前端架构 | 12 / 14 / 11 |
| 全栈数据与 Nest / Prisma | 13 / 15 / 07 |
| Hybrid / 小程序 / H5 | 19 / 06 / 05 |
| Lead、行为与项目答辩 | 08 / 22 |

版本口径必须与题库一致，例如：

- Vite 8 + Rolldown / Oxc；
- Nuxt 4.5，默认 Vite builder，Nitro；
- Prisma 7 + NestJS 11；
- Webpack 5；内置 Module Federation 与独立 MF 2.0 区分。

### 5.3 面试前 3 / 7 / 14 天

共同规则：

- 每天 90～150 分钟；
- 只调度速记、专题、模拟、故事 / 简历；
- 完成标准：可口述 + 记录卡点；
- 任务 ID 使用新前缀，禁止复用 60 天 ID：
  - `r3-d1-…`
  - `r7-d1-…`
  - `r14-d1-…`

定位：

| 计划 | 用途 |
| --- | --- |
| 3 天 | 已约面，只扫速记 + 主故事 + 1 场模拟 |
| 7 天 | 回炉薄弱域 + 2 个专题 + 1～2 场模拟 |
| 14 天 | 九域速记扫完 + 高频专题各过一遍 + 终场模拟 |

## 6. 文风与排版

- 中文技术文档规范：中英文之间空格、数字与单位空格；
- 结论先行，再给边界与证据坑位；
- 禁止把示例故事写成用户真实经历；
- 禁止占位文案（`TODO`、待补充、内容建设中）；
- 站内链接使用真实路径；页内锚点必须对照 VitePress slug，不得猜测。

## 7. 分批交付

### Batch 0：骨架

- 更新 `docs/.vitepress/config.ts` 导航；
- 创建复习总览；
- 创建 3 / 7 / 14 天计划骨架（可执行规则 + 空日或最小占位结构）；
- 首页 / 总览增加复习入口；
- `pnpm docs:build` 通过。

### Batch 1：样板

- 速记样板：`sheets/02-framework-data.md`；
- 专题样板：`topics/05-vue-reactivity.md`；
- 人工口述验收：5 分钟速记稿、15 分钟专题稿可独立完成；
- 与 02 / 23 / 24 / 25 题库口径交叉核对。

### Batch 2：补齐 8 篇速记

- 完成其余 `sheets/01`～`09`（除已完成的样板）；
- 每篇满足第 5.1 节结构。

### Batch 3：补齐 11 篇专题

- 完成其余 `topics/01`～`12`（除已完成的样板）；
- 每篇满足第 5.2 节结构。

### Batch 4：日程填满与发布

- 填满 3 / 7 / 14 天具体任务与链接；
- README / 首页 / 总览统计口径如需提及复习模块则更新；
- 全站构建、死链检查；
- 合并推送并验证 GitHub Pages。

## 8. 验收标准

1. 侧栏与顶部存在独立「复习」入口。
2. 9 篇速记、12 篇专题、3 档回炉计划齐全且无占位。
3. 复习文不计入 630 题门禁，但构建不得因复习页死链失败。
4. 抽查版本口径与题库一致（至少 Vite 8、Nuxt 4.5、Prisma 7、MF 区分）。
5. 样板篇可通过「不打开题库」完成对应时长口述。
6. 3 / 7 / 14 天任务 ID 与 60 天无冲突。
7. 线上可打开复习总览、任一篇速记、任一篇专题、任一日程。

## 9. 非目标

- 不把复习文做成可交互闪卡应用；
- 不新增第 27+ 题库文件；
- 不重写 60 天学习路线；
- 不在复习层引入与题库并行的追问答案校验集合。

## 10. 风险与缓解

| 风险 | 缓解 |
| --- | --- |
| 与题库口径漂移 | 真源规则 + 样板交叉审查 + 发布前抽查 |
| 长文维护成本 | 分批交付；结构模板固定；只浓缩不另开体系 |
| 构建体积与搜索索引变大 | 观察 VitePress 产物；必要时再评估搜索范围，不先删内容 |
| 锚点猜错 | 对照构建 HTML 的 heading id 校验 |

## 11. 实施下一步

规格确认后：

1. 使用 `writing-plans` 编写实施计划；
2. 在隔离 worktree / 功能分支执行 Batch 0～4；
3. 每批构建验证；全部完成后合并并部署 GitHub Pages。
