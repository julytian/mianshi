# TypeScript 类型系统

> **真源：** [01 JS/TS](/interview/questions/01-js-ts)（主：`unknown` / 泛型 / Utility / 收窄 / 联合 / 条件类型与方差）。版本口径不得与题库冲突。
>
> **目标时长：** 15～25 分钟可讲完主线。证据坑位填你自己的项目指标。

## 战场是什么 / 面试官想听什么

战场不是背 Utility 清单，而是证明你能把「外部脏数据 → 边界校验 → 内部不可达非法状态」讲成闭环：

**`unknown` 接入 → 收窄 / Schema → 业务联合与穷尽 → 泛型最小约束 →（可选）生成契约与方差安全 API。**

面试官想听四类能力：

1. **边界感：** `any` 与 `unknown` 的责任差；双断言等于手动 `any`。
2. **模型感：** 可辨识联合、`never` 穷尽、Create / Update 模型不靠层层 `Partial` 糊弄。
3. **推断感：** `satisfies` 与注解拓宽；条件类型分布与 `infer` 的使用边界。
4. **工程取舍：** 何时生成类型、何时 Zod、何时砍掉类型体操；如何证明「会用 TS」而不只是「写了注解」。

口述红线（与题库冲突即扣分）：

- 「永远不用 `any`」式绝对承诺；
- 把 `as unknown as T` 当常规收窄；
- 把 TS 可赋值说成类型论完全安全（尤其方法双变、可写数组协变）；
- 把条件类型当运行时分支；
- 用满屏 `?.` 吞掉本不该为空的数据错误。

十年经验口径下，面试官还在听你能不能用「约束 → 方案 → 取舍 → 验证 → 防护」讲一次 `any` 传染或线上类型谎言事故。类型系统的价值不在「注解越多越好」，而在于让非法状态在编译期不可达，并在 I/O 边界用运行时校验补上类型无法证明的洞。口述时主动承认：类型不是测试；会砍掉拖垮 IDE 的体操，也是资深能力。

## 知识地图

```text
边界输入              内部模型                 API / 组件               工程闭环
unknown + 校验   →   可辨识联合 / never   →   泛型最小 extends    OpenAPI / Zod 生成
收窄守卫 / asserts    Pick Omit Partial        props / emits 类型    any 治理与预算
satisfies 保留字面量   条件类型 + infer         方差：读写分离        类型测试 / IDE 预算
```

主线口诀：

1. **外部先 `unknown`**（别让 `any` 进腹地）
2. **用联合表达互斥状态**（别一堆可选字段）
3. **约束写最小形状**（别绑死整个 Entity）
4. **Utility 是手术刀**（超过两层就命名类型）
5. **推断要保留细节时用 `satisfies`**
6. **类型不是测试**（运行时校验补洞）

## 完整讲解

### 1. `unknown` / `any`：逃逸点可控

`any` 是放弃检查：读、写、调用都畅通，错误会传染。`unknown` 是「已知未知」：可接任意值，但用之前必须收窄（`typeof` / 自定义谓词 / 边界断言一次做完）。除赋给 `unknown` / `any` 外，未收窄不能当具体类型用——这就是它比 `any` 安全的结构性原因，不是风格偏好。

实战：API、`JSON.parse`、`localStorage`、SDK 回调先标 `unknown`，边界模块收窄成业务类型再往内传。内层业务代码尽量不见 `any`。库类型烂到没法修时，局部 `any` + 注释「为何逃逸」优于全局 `any`。`as unknown as T` 双断言等于手动 `any`，只适合极少数「比编译器更懂」的边界；滥用等于自我安慰。

任意 JSON：先 `unknown`，确认非空非数组对象后再 `Record<string, unknown>`；完整 JSON 值用递归 `JsonValue`。`object` 只排除原始值，不能安全按字符串键读；`Record` 又表达不了数组、字符串等完整 JSON。若接口真接受任意 JSON，边界做运行时校验再往内传稳定业务类型。证据坑位：〔填〕API 边界校验模块与一次 `any` 传染事故复盘。

渐进治理：先 lint / 统计阻止新增裸 `any` → 外部边界改 `unknown` + 校验 → 高频公共函数与事故模块 → 暂时逃逸注明原因与负责人；用错误率与 `any` 数量趋势验收，不幻想一次清零。面试别说「永远不用 `any`」——要说「逃逸点可控、尽量窄、别传染」。

### 2. 泛型约束、Utility 与「最少形状」

无约束的 `T` 几乎什么都能进，函数里不敢碰字段。`T extends { id: string }` 只声明关心 `id`，其余保留推断。场景：表格 `getRowKey<T extends { id: string | number }>`、深取字段 `getProp<T, K extends keyof T>(obj: T, key: K): T[K]`、请求封装 `request<T = unknown>(...)`。约束写「最少需要的形状」，别写成整个业务 Entity——否则复用立刻死。约束过宽 → 实现里狂断言、可选链或运行时猜测；过窄 → 调用方被迫拼无关字段、复制完整实体。默认类型参数（如 `T = void`）适合「多数调用方不关心返回值」的 API；约束和默认一起用时，先想清「推断失败掉到哪」。

`K extends keyof T` 才能写 `T[K]`；`K extends string` 不能证明可索引。`keyof` 可能含 `number` / `symbol`，底层只要字符串时用 `Extract<keyof T, string>`，不要用断言掩盖键域差异。条件类型与约束分工：约束限制传入，条件类型计算输出——例如 `<T extends object>` 拒原始值，而 `T extends readonly unknown[] ? ...` 为不同结构选结果。

高频 Utility：`Pick` / `Omit` 做表单编辑 DTO 与列表 VO 差集；`Partial` 做 PATCH；`Record<Union, V>` 做穷尽映射；`ReturnType` / `Parameters` 从已有函数抽类型，避免双份维护。添乱的是层层 `Partial<Omit<Pick<...>>>` 让人读不懂必填什么、用 `Partial` 掩盖 Create vs Update、过深 `Exclude` / `Extract` 表演。原则：Utility 是手术刀不是乐高；超过两层嵌套，宁可写命名清晰的 `type UserUpdate = { ... }`。注意：`Partial` 后「字段可选」≠「值可为 null」——后端常混用，前端要对齐语义。证据坑位：〔填〕Create / Update / Patch 三套 DTO 与一次字段语义事故。

### 3. 收窄、可辨识联合与 `satisfies`

除 `typeof` 外：`instanceof` / `in` / 相等判断（含判别字段）都会触发控制流收窄。复杂对象用自定义谓词 `function isUser(x: unknown): x is User`；`asserts x is T` 用于「失败就抛」的校验函数。别滥用 `as`——那是关闭检查。收窄失败时先问数据模型是否该用判别联合，而不是强转。

可辨识联合：用一个字面量字段（`type: 'success' | 'error'`）做 tag，各分支携带不同载荷。`switch (res.type)` 里每条分支自动收窄；`default` 里把值赋给 `never` 做穷尽检查，新增分支编译期炸——这是联合类型的工程价值。比一堆可选字段（`data?` / `error?` 同时存在）清晰得多。API 结果、UI 状态机、弹窗互斥内容都很合适。

`const cfg = { ... } satisfies Config`：检查值符合 `Config`，但**变量推断仍保留字面量细节**（键的字面量联合、具体字符串），不会被 `: Config` 注解拓宽成 `string`。后续 `cfg.mode` 仍能享受精确补全。适合路由表、主题 token、权限码表。老项目无 `satisfies` 时，可用 `as const` + 满足函数校验曲线救国。

可选链 / 空值：见第 6 节串讲；这里强调产品坑——满屏 `?.` 把数据问题吞成 `undefined`，页面空白却不报错，排障更难。该在边界校验的契约，不要在深渲染链上一路可选下去。

### 4. 条件类型、`infer` 与方差边界

条件类型 `T extends U ? X : Y` 按可赋值选分支；约束限制「能传入什么」，条件类型计算「得到什么」。不要把条件类型当运行时分支。裸类型参数上的条件会对联合**分布**；要整体判断用元组包裹 `[T]`。忘记分布会导致 `(A | B)[]` 与 `A[] | B[]` 语义错位。`infer` 做结构提取（如 `T extends readonly (infer U)[] ? U : T`）；对重载函数常从最后签名推断，不执行真正重载解析。`never` 在分布中会被消去。用 `any` 参与条件判断还可能得到意外联合结果。

适合库内抽取 Promise 结果、事件载荷、函数参数或过滤联合；业务只服务一个 DTO 时显式接口往往更可维护。公共库给复杂类型配类型测试（`tsd` / `expectTypeOf`）与命名中间类型；递归过深会拖慢编辑器并触发实例化深度错误——复杂度已越界就要砍。资深收口：「先判断是否需要按联合成员映射，再决定裸 `T` 还是 `[T]`；`infer` 用来提取既有结构，不用来炫技。」

方差口述最小集：纯生产者常协变、纯消费者常逆变、读写常不变——但 **TypeScript 实际可赋值 ≠ 完全安全模型**。对照直觉：

- 函数属性参数在 `strictFunctionTypes` 下更接近逆变：能处理 `Animal` 的消费者可以赋给需要处理 `Dog` 的位置；反向通常报错。
- 方法参数仍可能双变兼容：可赋值不代表类型论安全。
- `ReadonlyArray<Dog>` 可赋给 `ReadonlyArray<Animal>`（只读观察协变）；可写 `Dog[]` 赋给 `Animal[]` 在 TS 里可能被允许，随后 `push` 一只「猫」会破坏原数组元素契约。

事件总线、回调注册、只读容器和状态写入器最能暴露方差问题。设计 API 时分离 `ReadonlyState<T>` 与 `Dispatch<TAction>`，比到处传可读写大对象安全。不要为消报错直接双断言。复杂递归映射若让 IDE 卡顿或错误不可读，就已越过收益边界。

### 5. Vue props / emits、前后端同步与「证明你会 TS」

`<script setup lang="ts">` 优先类型版：

```ts
const props = defineProps<{ modelValue: string; size?: 'sm' | 'md' }>()
const emit = defineEmits<{ 'update:modelValue': [value: string]; change: [id: number] }>()
```

需要运行时校验与默认值再用对象写法或 `withDefaults`。复杂业务类型不要整坨塞进 props——子组件会变上帝。emits 写清 payload，避免 `emit('xxx', any)`。与外部类型同步：props 引用业务 `type`，别在组件里复制粘贴字段。

前后端同步靠谱方向：OpenAPI（或等价 IDL）为契约，用 openapi-typescript / 自研生成 types + 轻量 client，CI 校验契约变更；后端改字段先改契约。不靠谱：口口相传、手猜 interface、拿后端 Java DTO 源码当真相却无流水线、改生成物。折中：核心实体生成，边缘手写；或 Zod / io-ts 在边界校验并由 schema 推断——运行时兜底比纯 TS 信仰抗炸。证据坑位：〔填〕契约生成流水线与一次字段漂移拦截。

模块扩充：第三方缺字段或给 `vue` / `axios` 挂自定义属性时，用 `declare module` 合并，放独立 `shim.d.ts`，范围尽量小；能 wrapper 就别改全局。接口可合并、类型别名不行。滥用会让「运行时有没有这字段」变糊，类型与赋值点应一起评审。

证明「会用 TS」：边界 `unknown` + 校验；联合穷尽表达非法不可达；泛型减重复不过度体操；与生成 / Vue 形成闭环；并承认类型不是测试、过高复杂度会拖迭代——会砍复杂度也是能力。用「订单状态可辨识联合 + OpenAPI + switch 穷尽」一类真例子收尾，比背手册加分。

### 6. 日常语法陷阱如何接到类型故事

可选链与空值合并常被当成「语法糖题」，资深应把它们接回类型与产品语义：`a?.b.c` 在 `b` 空时仍可能炸——短路位置要对；`obj?.()` 与 `obj?.method?.()` 不同。满屏 `?.` 会把「本不该为空」吞成空白页，排障更难——该在边界断言 / 校验的，别在深渲染链一路可选。`||` 把 `0` / `''` / `false` / `NaN` 当没有；`??` 只认 `null` / `undefined`。表单数量、开关、允许空串几乎必须 `??`。默认参数不吃 `null`（`fn(null)` 不会回落到默认值），可用 `??` 补。`satisfies` 则解决「既要符合接口，又要保留字面量键」——路由表、主题 token、权限码表是典型；`: Config` 注解常把键拓宽成 `string`，自动补全与穷尽检查一起丢。

把这些点串起来的口述句式：「语法糖服务语义；语义先在类型模型里表达清楚，再在边界用运行时校验兜底。」

## 工程取舍与故障案例模板

| 步骤 | 你要说清的内容 |
| --- | --- |
| **约束** | 外部脏数据比例、迭代速度、IDE 性能、契约所有权 |
| **方案** | unknown 边界、联合模型、生成 vs Zod、体操预算 |
| **取舍** | 严格性 vs 排期；生成物新鲜度 vs 手写灵活 |
| **验证** | 类型测试正反例、线上谎言事故复现、`any` 趋势 |
| **复发防护** | lint、CI 契约门禁、禁止双断言惯例 |

**案例骨架 A — 「满屏 `any`，改一处炸一片」**

- 约束：不能停需求清零。
- 方案：禁新增 → 边界 `unknown` → 高频模块治理。
- 取舍：短期双轨类型。
- 验证：〔填〕`any` 计数与相关缺陷率趋势。
- 防护：PR 检查 + 逃逸注释模板。

**案例骨架 B — 「PATCH 用 `Partial<Entity>` 把必填搞丢」**

- 约束：创建与更新字段集不同。
- 方案：显式 `UserCreate` / `UserUpdate`；Utility 最多两层。
- 取舍：多几个命名类型。
- 验证：正反赋值用例；表单必填与类型一致。
- 防护：DTO 评审清单。

**案例骨架 C — 「可写数组协变埋雷」**

- 约束：只读列表 API 却返回可变数组类型。
- 方案：对外 `ReadonlyArray` / 只读视图；写入走独立 dispatch。
- 取舍：调用方不能再随便 `push`。
- 验证：类型测试禁止危险赋值。
- 防护：公共 API 方差审查。

**案例骨架 D — 「条件类型拖垮 IDE」**

- 约束：库要推导复杂事件载荷。
- 方案：命名中间类型 + 类型测试；业务侧改显式接口。
- 取舍：少一点「自动魔法」。
- 验证：打开关键文件的类型检查耗时 〔填〕。
- 防护：复杂度预算与文档示例。

**案例骨架 E — 「满屏可选链，线上空白无报错」**

- 约束：后端字段偶发缺失，前端用 `?.` 防炸。
- 方案：边界 Schema 校验失败显式错误态；渲染层只处理已收窄类型。
- 取舍：多一次校验与错误 UI。
- 验证：缺字段夹具下必须进错误分支，不得静默空白。
- 防护：lint 限制过深可选链；契约测试。

把案例讲清楚的关键句式不是「我们上了 TypeScript」，而是「哪一类非法状态从此不可编译 / 不可静默」，以及「运行时仍在哪一层兜底」。

- L1：为何先 `unknown` 而不是 `any` / `object`？

    - L3：与运行时 Zod 如何分工？收口：非法状态不可达 + 边界仍校验。

**主问：泛型约束你怎么拿捏？**

- L1：最小形状 vs 整个 Entity。  
  - L2：`keyof` 与 `Extract`？约束 vs 条件类型分工？  
    - L3：分布条件与元组包裹？收口：正反类型用例。

**主问：`satisfies` 和注解差在哪？**

- L1：拓宽丢失字面量的后果。  
  - L2：路由表 / token 表场景。  
    - L3：无 `satisfies` 时曲线？收口：既要符合接口又要精确键。

**主问：TS 里协变逆变你怎么讲才不翻车？**

- L1：生产者 / 消费者直觉。  
  - L2：方法双变、可写数组陷阱。  
    - L3：API 如何分离读写？收口：可赋值 ≠ 类型论安全。

## 15 分钟口述验收清单

开始前准备一张纸，按时勾选；任一勾不上就回去补题库对应题。

1. **（1 分钟）战场句：** 外部 `unknown` → 收窄 → 内部联合穷尽；类型不是测试。
2. **（2 分钟）any 治理：** 逃逸可控、双断言危险、渐进顺序。
3. **（2 分钟）泛型与 Utility：** 最小约束、两层手术刀、Create/Update 分离。
4. **（2 分钟）收窄与联合：** 谓词、`never` 穷尽、互斥状态建模。
5. **（2 分钟）satisfies / ?? / ?.**：拓宽差异、`0`/`false` 陷阱、可选链吞错。
6. **（2 分钟）条件类型与方差：** 分布、`infer` 用途、可写数组 / 方法双变红线。
7. **（2 分钟）工程闭环：** OpenAPI / Zod、Vue props 类型、模块扩充克制。
8. **（2 分钟）案例收口：** 「约束 → 方案 → 取舍 → 验证 → 防护」讲自己的类型事故（〔填〕）。

临场提示：若面试官只问「你会 TypeScript 吗」，不要从语法清单起讲，直接抛一条你主导过的边界治理或契约生成故事，再用联合穷尽与方差红线回答追问。数字与模块名一律用自己的 〔填〕，不要背范文里的假指标。准备时把题库 Q1 / Q24 / D5 各遮稿口述一遍，能在两分钟内讲完「未知输入如何变成不可达非法状态」，本专题就算过关。宁可少写注解，也要把边界与穷尽讲清楚。

自检口令（必须能脱口而出）：

- 「`unknown` 为何比 `any` 安全？」→ **未收窄不能当具体类型用，迫使边界证明形状。**
- 「`Partial` 等于可 null 吗？」→ **不等于；可选与 null 是不同语义。**
- 「TS 允许赋值就安全吗？」→ **不一定；方法双变与可写数组是反例。**
- 「条件类型是运行时 if 吗？」→ **不是；只在类型层计算。**
- 「怎样证明你会 TS？」→ **边界校验 + 联合穷尽 + 契约生成闭环，并能砍复杂度。**
