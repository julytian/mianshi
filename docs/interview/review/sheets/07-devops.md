# 运维与部署速记

> **真源：** [26 DevOps](/interview/questions/26-devops)，以及 [Docker](/interview/guides/devops/docker)、[Jenkins](/interview/guides/devops/jenkins)、[Kubernetes](/interview/guides/devops/k8s) 指南为唯一真源；冲突时以题库为准。
>
> **用法：** 面试前遮住口述稿先自讲，再对结论卡与追问速答。证据坑位请填入你自己的项目指标，勿背他人数字。

## 一句话定位

本域讲清「前端 CI/CD 门禁 + 不可变制品与镜像安全 + Kubernetes / CDN 发布与回滚」。资深面试要的是**可证明来源与可秒级切回的发布面**，不是只会点 Jenkins 绿勾。你应能在五分钟内把流水线阶段、多阶段镜像、滚动更新与静态资源缓存契约串起来，并说明静态站与 SSR 在探针、弹性上的差异，以及客户端缓存恢复时延。

## 核心结论卡

1. **结论：** CI 保证可重复构建与质量证据，CD 保证可控晋级与回滚；二者靠不可变制品衔接。  
   **边界：** 「流水线绿了」≠「来源可信」；要锁文件、完整性与权限隔离。  
   **证据坑位：** 〔填〕MR → 制品 → 环境的晋级图。

2. **结论：** 前端流水线阶段至少含安装、类型检查、单测、构建、安全扫描、产物上传；门禁卡什么要写清。  
   **边界：** 本地 husky 不能替代 CI；紧急例外限时可审计。  
   **证据坑位：** 〔填〕门禁清单与一次红灯真实拦截。

3. **结论：** Jenkins 凭据与前端密钥隔离：最小权限、不可回显、按环境分凭证。  
   **边界：** 声明式 Pipeline 优先可读可审；复杂逻辑抽共享库仍要可追踪。  
   **证据坑位：** 〔填〕凭证命名与一次密钥泄漏演练（或桌面推演）。

4. **结论：** Docker 多阶段：Node 构建，最终阶段只拷静态或最小运行时；非 root、尽量只读、`.dockerignore` 先行。  
   **边界：** 多阶段不会自动去掉 Source Map；要显式别拷进生产镜像。  
   **证据坑位：** 〔填〕镜像体积、用户、只读与 map 是否存在的检查记录。

5. **结论：** 静态 SPA 健康检查探可达入口；不要用「能 curl 到任意 JS」当业务健康。  
   **边界：** SSR / Node 还要 readiness 与优雅退出，不能套静态站直觉。  
   **证据坑位：** 〔填〕探针配置与一次就绪失败回滚。

6. **结论：** K8s 中 Deployment 管副本与滚动，Service 稳入口，Ingress 管对外路由与 TLS。  
   **边界：** 只切 Service 不等于完整蓝绿 / 金丝雀体验面。  
   **证据坑位：** 〔填〕一次滚动发布与 `kubectl rollout undo` 演练。

7. **结论：** ConfigMap 放非密运行时配置，Secret 放敏感；前端运行时配置要 schema 校验。  
   **边界：** Secret 仍可能误进镜像或 CI 日志，要扫描与规范。  
   **证据坑位：** 〔填〕运行时配置注入方式与误提交拦截。

8. **结论：** 滚动更新时旧 Pod 与新哈希资源可能短暂不一致；入口 HTML 与资源发布顺序要契约化。  
   **边界：** HTML 短缓存、资源长缓存；回滚保留旧哈希。  
   **证据坑位：** 〔填〕一次「HTML 新、chunk 404」事故与修复。

9. **结论：** 静态站优先对象存储 + CDN；K8s Nginx 适合平台约束或要统一治理时。SSR 才强依赖 Pod 弹性。  
   **边界：** HPA 对静态 Nginx 与 Node SSR 策略不同，不能同一套直觉。  
   **证据坑位：** 〔填〕静态 vs SSR 的部署形态对照表。

10. **结论：** 构建缓存 `node_modules` / pnpm store 要按锁文件键控；远程缓存防投毒。  
    **边界：** 「这台 agent 才能编过」必须容器化消除。  
    **证据坑位：** 〔填〕冷构建 / 热构建时长与缓存命中率。

11. **结论：** 蓝绿是两套环境切换；金丝雀是按比例放量并观察。前端还要考虑客户端缓存恢复时延。  
    **边界：** 控制面切换快 ≠ 用户全量恢复快。  
    **证据坑位：** 〔填〕金丝雀停止线与客户端恢复分位数。

12. **结论：** liveness 防死锁重启，readiness 控流量，startup 护慢启动；静态站与 SSR 选型不同。  
    **边界：** 乱配 liveness 会造成重启风暴。  
    **证据坑位：** 〔填〕三类探针对照表。

13. **结论：** 供应链：冻结锁文件、禁用危险生命周期脚本（按策略）、签名制品、缩小凭据面。  
    **边界：** 共享缓存与过宽 PR 权限是投毒面。  
    **证据坑位：** 〔填〕一次依赖 / 流水线风险收敛措施。

14. **结论：** Nuxt / Node SSR 在 K8s 要处理 SIGTERM、排空连接与超时；不要当纯静态副本。  
    **边界：** 进程内状态与 SSE 长连接要有退出策略。  
    **证据坑位：** 〔填〕优雅退出超时与在途请求观察。

15. **结论：** 前端 CDN 失效与版本发布绑定：入口切换 + 旧资源保留窗口。  
    **边界：** 全网 purge 不是默认回滚手段。  
    **证据坑位：** 〔填〕回滚演练：切换入口后错误率曲线。

16. **结论：** 生产镜像基线：Node 22 slim 构建、nginx alpine 运行（版本以仓库为准）；Buildx 与缓存挂载提速。  
    **边界：** 不要把 `vite dev` 打进生产镜像。  
    **证据坑位：** 〔填〕Dockerfile 审查清单勾选记录。

17. **结论：** Jenkins / CI agent 用声明 Node / pnpm 版本的容器构建，工作区用完即弃，消除「某台机器才能编过」。  
    **边界：** 长期物理节点会积累全局工具链、脏依赖与残留凭据。  
    **证据坑位：** 〔填〕容器化构建前后「环境漂移」事故对比。

18. **结论：** 前端发布观察窗口要同时看错误率、关键任务、资源 404 与 CWV 代理指标，而不是只看 Pod Ready。  
    **边界：** 集群健康不等于用户侧缓存与 CDN 已收敛。  
    **证据坑位：** 〔填〕一次发布后 30 分钟观察清单与结论。

## 高频追问速答

1. **CI 绿了为什么还不够？**  
   绿灯只说明在当时权限与脚本下命令通过，不证明依赖未被投毒、凭据未被滥用、制品与提交一一对应。还需要锁文件、完整性校验、最小权限、不可变制品哈希与可审计晋级。PR 来自外部时更要隔离执行环境。面试应能画出「代码 → 构建 → 签名 / 上传 → 环境」的信任边界，而不是只报插件名字。

2. **多阶段构建后为何还会泄露 Source Map？**  
   多阶段只隔离构建工具链，不会自动理解哪些文件敏感。若最终阶段 `COPY` 了整个 `dist`，而构建配置把 `.map` 打进产物，map 仍会进镜像或被 Nginx 对外提供。正确做法是生产 map 进受控 artifact，镜像内显式排除，并在发布检查中扫描。能构建成功不等于镜像内容安全。

3. **滚动更新时 chunk 404 怎么解释？**  
   典型是新 HTML 已指向新哈希资源，但部分节点或 CDN 尚未具备该对象，或旧 HTML 缓存指向已清理资源。发布契约应先上传资源再切换入口，回滚保留旧哈希一个窗口，HTML 短缓存。只扩副本或只重启 Pod 解决不了对象缺失。要用同一版本的入口与资源清单做验收。

4. **静态站还放不放进 Kubernetes？**  
   若平台只收镜像或要统一 Ingress 治理，可以 Nginx 镜像托管；若只是静态资源，对象存储加 CDN 通常更省、更贴合长缓存模型。SSR / Node 才真正需要进程与探针。选型表应包含运维成本、回滚方式与缓存策略，避免「所有前端都必须进集群」的口头禅。

5. **金丝雀和只切 Service 差在哪？**  
   金丝雀要按比例放量、观察业务与性能停止线，再扩大或回滚；还要处理前端缓存导致的双版本共存。只改 Service 选择器可能瞬间切全部流量，缺少观察窗口。蓝绿则是两套环境切换，回滚快但成本高。前端场景要额外度量客户端恢复分位数，不能只看集群事件。

6. **前端容器为什么强调非 root？**  
   非 root 降低容器逃逸与误写文件系统的影响面，配合只读根文件系统可强制配置经挂载注入。监听非特权端口（如 8080）是常见做法。这不是形式主义：生产被入侵时，权限面直接决定爆炸半径。健康检查、资源限制与 seccomp 等应一起讲，而不是只改 `USER` 一行。

7. **pnpm store 缓存怎么才算安全？**  
   缓存键必须包含锁文件与关键工具版本，避免脏命中；共享缓存要权限隔离，防止投毒写入。完整安装仍应校验完整性。命中率要服务可复现，而不是「快但不确定」。agent 差异用容器镜像统一，消除「只有某台机器能编过」。缓存是加速层，不是信任根。

8. **SSR 优雅退出你怎么讲？**  
   收到终止信号后停止接新请求，等待在途请求完成或超时，再关闭服务器。K8s 要配够 `terminationGracePeriodSeconds`，readiness 先失败以摘流。长连接、队列与定时器要有明确 owner。静态 Nginx 的退出模型更简单，不能把两套直觉混用。演练时应观察切断流量后错误是否可接受。

## 反例 / 红线

- 密钥进镜像 / CI 日志；生产镜像含 Source Map 或 `node_modules` 工具链。
- 用 `vite dev` 或特权 root 跑生产。
- 无旧资源保留窗口的强制 purge 当回滚。
- 把流水线绿灯当成供应链安全已证明。
- 静态站与 SSR 共用同一套 HPA / 探针话术。
- 「这台 Jenkins 节点才能构建」长期不治理。
- 发布只看 Pod Ready，不看 HTML / chunk 一致性与用户侧错误。

「运维我按信任链讲：CI 产出不可变制品，CD 晋级与回滚，凭据最小权限。前端镜像多阶段、非 root、不进 map；静态优先 CDN，SSR 才强调 Pod 与优雅退出。K8s 分清 Deployment、Service、Ingress 与三类探针。发布契约是先资源后入口，HTML 短缓存，回滚留旧哈希；金丝雀有停止线。构建必须容器化，避免 agent 漂移。供应链守锁文件与缓存投毒面。发布后观察窗口同时看 404、错误率与用户侧恢复，不把 Pod Ready 当唯一成功信号。收口用一次 chunk 404 修复和一次 rollback 演练。」
