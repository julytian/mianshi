# 移动端与跨平台速记

> **真源：** [06 uni-app / 小程序](/interview/questions/06-uniapp-miniprogram)、[19 Hybrid App](/interview/questions/19-hybrid-app) 为唯一真源；冲突时以题库为准。
>
> **用法：** 面试前遮住口述稿先自讲，再对结论卡与追问速答。证据坑位请填入你自己的项目指标，勿背他人数字。

## 一句话定位

本域讲清「小程序双线程与分包治理 + uni-app 多端条件编译边界 + Hybrid Bridge / WebView 生命周期与热更新合规」。资深面试要的是**平台约束下的可发布链路**，不是「一套代码到处跑」口号。你应能在五分钟内把主包体积、登录隐私、Bridge 安全与容器差异串成故事。

## 核心结论卡

1. **结论：** 微信小程序逻辑层与渲染层分离，频繁 `setData` 与大数据传输是首要性能税。  
   **边界：** 优化优先减字段、合并更新、局部更新；虚拟列表与真机渲染为准，开发者工具只能作参考。  
   **证据坑位：** 〔填〕一次 `setData` 体积与首开 / 滚动指标对照。

2. **结论：** 主包有体积硬顶；分包、预下载与独立分包要按首开与二跳指标一起决策。  
   **边界：** 预下载不是越多越好；公共代码下沉与图片外置要进发布清单。  
   **证据坑位：** 〔填〕主包 / 分包体积表与二跳耗时。

3. **结论：** 条件编译用于平台差异，能力适配放适配层；禁止业务文件变成井号地狱。  
   **边界：** 生命周期语义在 Vue / 小程序 / App 间不同，不能假设一一对应。  
   **证据坑位：** 〔填〕平台适配层目录约定与一次语义泄漏事故。

4. **结论：** 小程序登录是 code → 服务端换会话 → 前端持可控会话；隐私授权按需、可拒绝、可引导设置页。  
   **边界：** 用户信息与手机号等能力受政策与组件约束，不能按旧「一键拿资料」口述。  
   **证据坑位：** 〔填〕登录态续期与隐私弹窗拒绝路径验收。

5. **结论：** `rpx` 按屏宽折算；与 H5 rem/vw 混用时要固定设计稿基准，原生组件层级与样式受限。  
   **边界：** input / video / map / canvas 有层级与同层渲染坑，布局要以真机为准。  
   **证据坑位：** 〔填〕含原生组件页面的真机层级问题复盘。

6. **结论：** 发布链路分开发 / 体验 / 审核 / 灰度；合法域名、隐私指引、订阅消息都要进门禁。  
   **边界：** 审核驳回常因隐私文案、权限声明与实际采集不一致。  
   **证据坑位：** 〔填〕一次审核驳回原因与整改清单。

7. **结论：** npm / 插件是供应链：锁版本、可回滚、评估主包占用；不要随手加未审计包。  
   **边界：** 小程序插件有权限与类目限制；H5 能用的包不等于小程序能用。  
   **证据坑位：** 〔填〕依赖准入表与一次插件回滚。

8. **结论：** Hybrid 典型是原生壳 + WebView 内容；适合活动页、中低频业务与快速迭代，强离线 / 重交互要慎选。  
   **边界：** Android WebView 与 iOS WKWebView 在文件、Cookie、生命周期、返回栈上有差异。  
   **证据坑位：** 〔填〕选型表：Hybrid / PWA / RN / Flutter / 原生。

9. **结论：** JSBridge 请求—响应要有 id、方法名、版本、错误码与超时；能力探测先于调用。  
   **边界：** 不可信 Web 内容必须鉴权、鉴来源、限制可调 API 面。  
   **证据坑位：** 〔填〕Bridge 协议文档与一次越权调用拦截。

10. **结论：** Native 返回栈与 Web 路由要协议化同步；物理返回 / 手势返回不能只靠前端 `history.back`。  
    **边界：** 保活 WebView、单例与重建模式影响状态恢复，选型要讲清楚。  
    **证据坑位：** 〔填〕多层 Web 页与原生页交错返回的验收用例。

11. **结论：** Hybrid Cookie / SSO 受系统 WebView 分区与 ITP 类策略影响；不要假设与系统浏览器一致。  
    **边界：** 文件、相机、定位权限走系统授权，Web 侧只能配合说明与降级。  
    **证据坑位：** 〔填〕登录态在双端 WebView 的差异记录。

12. **结论：** 启动白屏治理：WebView 池、预加载、离线包与关键资源优先；要能量化首屏可见。  
    **边界：** 预加载过多会伤冷启动与内存；需预算。  
    **证据坑位：** 〔填〕冷启动到首屏可交互分位数。

13. **结论：** 资源热更新要合规：签名校验、差分、灰度、可回滚；应用商店政策红线不能碰。  
    **边界：** 把整包当「随意热更新」口述会直接翻车。  
    **证据坑位：** 〔填〕热更新范围说明与一次回滚演练。

14. **结论：** 跨端监控要串联 Web 错误、Bridge 失败、原生崩溃与同一 trace；否则无法归因。  
    **边界：** 只看 JS error 会漏容器杀进程与桥超时。  
    **证据坑位：** 〔填〕一次跨端故障的关联日志样例。

15. **结论：** uni-app App、Capacitor、Cordova 定位不同：厂商生态、插件成熟度与长期维护成本要进选型。  
    **边界：** 「一套代码」省的是业务表达，不是测试矩阵。  
    **证据坑位：** 〔填〕目标端清单与必测真机矩阵。

16. **结论：** 支付、分享、`open-type` 必须在用户手势内触发，结果以服务端确认；防刷与幂等在后端。  
    **边界：** 前端成功回调不等于账务成功。  
    **证据坑位：** 〔填〕支付结果核对与分享场景验收。

## 高频追问速答

1. **为什么小程序特别怕乱 `setData`？**  
   逻辑层与渲染层分进程通信，`setData` 要序列化传输；字段多、频率高会直接拖慢首开与滚动。优化应只传差异字段、合并更新、控制列表窗口，并在真机看性能面板。开发者工具流畅不等于低端安卓可接受。口述时要能举一次把整对象改成必要字段后的指标变化，而不是只说「少 setData」。

2. **分包是不是切得越细越好？**  
   不是。分包要同时服务主包体积上限、首开路径与二跳体验。切太碎会增加跳转等待与重复依赖；预下载策略也要按用户路径预算。独立分包适合弱依赖入口，但公共能力下沉与资源外置要配套。决策用主包体积、首开与关键二跳耗时一起验收，而不是只看能否上传成功。

3. **条件编译怎么避免井号地狱？**  
   平台差异收口到适配层或少量平台文件，业务代码保持统一 API。生命周期与能力差异写成明确映射表，禁止在每个页面复制大段 `#ifdef`。新增端时先补适配与测试矩阵，再放开业务。面试官若追问「H5 与微信差异」，应讲登录、存储、路由、样式单位与原生组件限制，而不是只说用了 uni-app。

4. **Bridge 安全最小集是什么？**  
   调用前做能力与版本协商；校验页面来源与登录态；限制可调用原生 API 白名单；参数校验与超时；敏感操作二次确认。日志带 trace，两端可关联。不可信 H5（如外部活动页）应降权或隔离。没有鉴权的「任意 JS 调原生」等于把应用能力暴露给页面注入，不能用「内网包」当借口。

5. **Hybrid 返回键乱跳怎么治？**  
   先定义单页 Web、多页 Web、原生页交错时的栈协议：谁负责 pop、何时拦截、何时交给系统。前端路由变更要通知原生，原生返回要通知前端。保活 WebView 与销毁重建的状态策略要一致，避免「页面还在但 JS 上下文已新」。验收必须覆盖 Android 实体返回与 iOS 手势返回，并在真机 WebView 而不是桌面浏览器完成。

6. **热更新可以说到什么程度？**  
   只能更新政策允许的资源范围，并具备签名校验、灰度、监控与回滚。把可执行逻辑或整包绕过商店规则口述，是合规红线。工程上要说明差分包、版本号、失败落回本地可信版本。面试重点是「如何保证用户不被坏包卡住」，而不是吹嘘可以天天热更任意代码。

7. **小程序登录与隐私怎么讲才不过时？**  
   登录以 wx.login code 换服务端会话为主线，前端存储可控 session 并处理过期。用户资料、手机号、位置等按场景申请，提供拒绝与引导设置路径，文案与实际采集一致。旧的「一进页面就授权拿头像昵称」不再是合格答案。发布前核对隐私指引、权限声明与接口调用是否同集。

8. **跨端选型你会怎么一句话收口？**  
   先列目标端、团队技能、离线与性能预算、插件依赖与商店合规，再选 Hybrid、小程序、PWA 或高成本原生 / RN / Flutter。uni-app 降低的是多端表达成本，测试与平台差异不会消失。没有真机矩阵与回滚方案的「一套代码」只是演示。最终用冷启动、崩溃率、桥失败率与发版周期验收，不为简历追新。

## 反例 / 红线

- 把开发者工具流畅当成真机性能证据。
- 业务文件铺满条件编译；假设生命周期跨端一一对应。
- Bridge 无白名单、无来源校验；把热更新说成可绕过商店任意改包。
- 忽略隐私指引与真实采集不一致导致的审核与合规风险。
- 只测系统浏览器，不测 WKWebView / Android WebView 差异。
- 支付成功只信前端回调。

## 5 分钟口述稿

「跨端我先讲约束：小程序有双线程和主包上限，Hybrid 有双端 WebView 差异和商店合规。小程序侧抓 `setData`、分包与真机性能；登录走 code 换会话，隐私按需授权。uni-app 用适配层消化条件编译，不把业务写成井号。Hybrid 侧 Bridge 要版本、白名单与 trace；返回栈与原生协议对齐；启动用预加载但有预算；热更新讲签名、灰度、回滚，不碰红线。选型用目标端与验收指标，不为简历追框架。收口用主包体积、桥失败率和一次真机返回栈修复。」
