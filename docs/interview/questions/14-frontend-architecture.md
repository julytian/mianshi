# 前端架构面试题库

> **怎么用：** 先盖住答案，按 **约束识别 → 分层与边界 → 质量属性 → 演进路径** 自己口述 2～3 分钟，再点开 `参考答案` 对照补洞。追问用来模拟面试官加压；踩坑是实战里最容易翻车的点。中英文术语之间请习惯留空格，口述时也建议如此。

**编号规则：** 普通题使用 `Q1`、`Q2`……深层题使用 `D1`、`D2`……按章节目录顺序连续编号；D 题嵌入对应主题章节，不设独立「深层题」章节。

## 适合岗位 / 定位

面向 **5 年+ 前端**、**前端架构师** 与 **技术骨干**，回答「系统应该如何组织和演进」。重点是 **依赖方向、质量属性与治理原则**。

**与相邻模块的边界：**

- [工程化](/interview/questions/03-engineering) 偏 **工具链与流水线实操**（Vite / Webpack、CI、体积分析、环境变量）；本模块（14）偏 **依赖方向、质量属性与治理原则**，不涉及具体构建配置细节。
- [架构 / Lead](/interview/questions/08-architecture-lead) 聚焦带人与排期决策；[前端系统设计](/interview/questions/11-frontend-system-design) 以端到端案例展开。

## 后续章节目录

1. **架构基础** — 目标与约束、质量属性、分层与依赖方向
2. **模块与数据** — 领域拆分、状态与数据流、接口层、错误模型与权限模型
3. **依赖治理与发布体系** — Monorepo 边界、依赖方向、发布契约与环境治理（架构视角，非工具配置）
4. **性能与稳定性** — 性能预算、可观测性、安全边界与灾备降级
5. **演进治理** — 技术债识别、架构评审、决策记录与渐进式演进
6. **架构演进与多团队边界** — 从业务约束推导架构、平台化取舍、多团队协作边界
