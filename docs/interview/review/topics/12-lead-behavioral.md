# Lead、行为与项目答辩

> **真源：** [08 架构 / Lead](/interview/questions/08-architecture-lead)（主）；项目与行为见 [22 项目答辩与行为](/interview/questions/22-project-behavioral)。简历 / 故事 / 模拟仅作素材入口，**不覆盖题库口径**。版本与示例阈值不得当成你的真实业绩。
>
> **目标时长：** 15～25 分钟可讲完主线。证据坑位填你自己的项目指标。

## 战场是什么 / 面试官想听什么

战场不是堆管理黑话或背框架明星度，而是证明你能让**正确的事以可交付质量发生**：

**约束澄清 → 选项与风险 → 决策留痕 → 门禁与节奏 → 带人协作 → 用可核验证据讲结果与复盘。**

面试官想听四类能力：

1. **决策感：** 选型、砍范围、还债、门禁豁免都有维度、Owner、退出条件与复审点。
2. **证据感：** 指标带定义、单位、聚合、基线、时间窗；比例再讲分子分母；归因区分「我做 / 我推 / 机制产」。
3. **组织感：** CR、值班、多端人力、跨团队冲突、无职权影响力——讲推动而非职称。
4. **诚信感：** 脱敏、不编造、不把示例数字说成亲历；保密与不会时如何收口。

口述红线（与题库冲突即扣分）：

- 跟风最火技术；把团队业务结果全部归为自己；
- 用加班时长证明能力；用平均值或挑窗报喜；
- 门禁「重试变绿」当通过；安全红线被职级绕过；
- 把题库 / 简历模板里的示例公司、比例、天数说成自己的；
- 泄露未授权内部材料，或用「保密」掩盖没有证据。

文中天数、比例、团队规模若出现在题库，皆为**示例阈值**；你必须替换为自己的基线与口径。

Lead 合题的加分点通常不在「管过几个人」，而在：你是否留下过可检索的决策记录、是否能在冲突中收敛选项、是否能在事故中先止损再归因、是否能把指标讲到可核验。把这四句当成开场自我校正清单。

## 知识地图

```text
Lead 决策面                 交付与质量                  人与组织                    求职表达
选型打分 / ADR        →   估期砍范围 / 债分级    →   新人 30 天 / CR      →   自我介绍主线
质量属性与约束表           红黄灯门禁 / 发布豁免       多端人力 / on-call        STAR-L 3/5/10
跨团队收敛 / 路线图        复盘与事故指挥               绩效反馈 / hiring bar     反问与诚信边界
```

主线口诀：

1. **先约束与质量属性，再选工具**
2. **债与范围都要计价，不靠隐性加班**
3. **门禁保护用户与数据，例外限时补偿**
4. **影响力 = 试点收益 + 可退出 + 结果共担**
5. **项目答辩讲个人边界与证据链**
6. **不会 / 不能说时给替代路径，不编造**

## 完整讲解

### 1. 选型、技术债、估期与砍范围

选型维度：问题匹配、团队曲线、生态生命周期、迁移退出、合规与包体等非功能约束。流程：短 PoC → 书面选/不选理由 → 局部试点 → 推广；留下 ADR（上下文、选项、后果、复审条件）。权重先由业务约束确定，再用代表页验证交付周期与缺陷，避免个人熟悉度冒充组织最优。

技术债：利息（故障、发版阻断、人效）× 本金；P0 跟版本强绑。产品说「不能重构」时，把债翻译成本版本具体风险，最小包只保同路径护栏与可观测；不投则书面风险与复审日。预算来自范围取舍，不靠承诺加班。重写巨石时按可验证切片迁移，新旧兼容，指标未改善就暂停。

估期给范围、假设、依赖与缓冲；必砍时按价值 / 风险 / 依赖透明化，守住安全与数据底线。单点英雄式承诺不可持续。变更要显性计价：目标变化、已完成工作、对日期与质量的影响，以及新增/替换/延期哪个范围。

**机制：** 选型用约束表+短 PoC+ADR；债按利息×本金分级，P0 跟版本；估期带假设与缓冲，必砍时守安全与数据底线。

**失败形态：** 跟风最火技术；用加班还债；重写巨石无切片与退出条件。

**验收：** ADR 可检索；不投债有书面风险与复审日；变更单能说出对日期/质量的影响。

### 2. Code Review、质量门禁与工程底线

CR 挡正确性、安全、契约破坏、可回滚；风格工具化。必须改与建议改分标，避免警察式争论。对 AI 生成大段补丁，先查分层越界、权限遗漏、测试空白与秘密进仓，再谈命名审美。

门禁：类型/构建失败、核心单测、已确认可达的高危漏洞、未授权暴露——红灯。依赖告警结合可达性与暴露面；黄灯例外要 Owner、替代验证、回滚、补偿截止日。跳过权双人审批，不按职级豁免安全红线。CI 优化先砍重复安装与无效串行，但不得为分钟数删除真正防生产风险的检查。类型债务治理：新代码严格、遗留区分区收敛，豁免有到期日，防止 `any` 转移风险。

多仓 / Monorepo：产物与 git SHA 可追溯；sourcemap 与发布记录可查；设计系统语义化版本与迁移支持，避免业务永久钉死旧版。预发与生产差异导致的逃逸，要有环境契约与生产烟测，不能把「预发过了」当免责依据。

**机制：** CR 挡正确性/安全/契约/可回滚；红灯不可「重试变绿」；黄灯例外要 Owner、替代验证、回滚、补偿截止日；安全红线不按职级豁免。

**失败形态：** 警察式风格争论；为 CI 分钟数删防生产检查；`any` 豁免无到期日。

**验收：** 例外审计；AI 补丁过分层/权限/测试/秘密清单；预发契约+生产烟测。

### 3. 带人、多端并行、值班与仪式裁剪

新人 30 天：环境一天内通、小闭环任务、结对、生产权限渐进；只扔文档 ≠ onboarding。多端（后台 / H5 / 小程序）按能力与风险分人，设集成节奏与唯一优先级入口；uni-app 与否用复用率、审核节奏、体验差异 PoC 决定。共享核心变更要有窗口，避免人人全栈救火却无人负责集成。

前端 on-call：轮值、升级矩阵、runbook、补偿休息；监控关联发布版本。第三方脚本事故先止损隔离，再查 CSP / 开关。审核值班与线上 on-call 权限不同，勿用「值班」模糊无限在线。Scrum / 看板裁剪：保留能暴露风险的仪式，删空转；用吞吐量与阻塞基线验证，不为仪式感服务。站会只同步阻塞与风险，细节进异步文档。

**机制：** 新人 30 天小闭环+权限渐进；多端唯一优先级入口；on-call 有升级矩阵与补偿休息；仪式用吞吐量验证，不为仪式感。

**失败形态：** 只扔文档当 onboarding；人人全栈救火无人集成；用「值班」模糊无限在线。

**验收：** 新人首周可合并；阻塞看板；值班轮值表与 runbook。

### 4. 复盘、事故指挥、跨团队与路线图

合格复盘：时间线、影响、根因（机制而非个人羞辱）、已验证修复、跟项 Owner 与到期日。Lead 作事故指挥官：冻结发布、分并行排查组、对外统一口径、恢复后观察窗口再复盘。归属不清时先按症状切前端版本 / 网关 / 数据 / 第三方，禁止「不是我」拒绝协作。白屏突增类事故：五分钟内确认版本相关性，一组回滚一组查 CDN/配置，客服周期性同步影响与恢复预期。

无正式职权推架构：共同痛点基线 → 愿试点团队 → 低风险可退出方案 → 迁移支持降低采用成本 → RFC 收反对意见；升级带着证据。跨团队僵持：量化等待与故障，PoC 比较选项，明确决策权与 Owner。影响力来自承担落地与结果，不是绕过正式 Owner。

三年路线讲业务能力与风险下降，不讲「明年全面微前端」；用触发阈值决定是否上运行时拆分。向业务要债预算：利息对业务结果，给不处理 / 最小止血 / 分期选项；若仍不投，由有权者书面接受风险并设复审触发器，保护团队不靠隐性加班还债。

**机制：** 事故先止损再归因；复盘写机制根因与跟项到期日；跨团队用量化+PoC+明确决策权；路线图讲能力与风险阈值，不讲「明年全面微前端」。

**失败形态：** 羞辱个人当复盘；「不是我」拒协作；无职权却空喊架构。

**验收：** 五分钟内版本相关性确认；跟项关闭率；RFC 收反对意见。

### 5. 组件库、产品博弈、招聘与绩效

组件库：先统一 token / a11y / 原语，再按平台拆包；breaking 语义化；用重复开发与缺陷基线谈投资，不空喊基建情怀。与产品博弈：把审美争成设备与 INP / 无障碍约束；需求变更显性计价。hiring bar：级别校准看问题复杂度、影响范围、自主性与证据质量（见题库 D1）。绩效：事实、影响、改进计划与时间盒；尖锐反馈对人对事分离（D2 / D6）。培养同事靠可验证任务与反馈节奏，不靠年终一次性谈话。

**机制：** 组件库先 token/a11y/原语；与产品把审美争成设备与 INP/无障碍约束；hiring bar 看复杂度/影响/自主性/证据；绩效事实+时间盒改进。

**失败形态：** 空喊基建情怀；需求变更不计价；年终才给尖锐反馈。

**验收：** 采用率与缺陷护栏复审；同题同评分维度面试；四周改进计划可验证。

### 6. 项目答辩：STAR-L 与 3 / 5 / 10 分钟

经历题用 STAR-L 准备（背景、任务、行动、结果、复盘），面试时讲事实，不念字母。先做一页脱敏证据地图：时间轴、系统边界、我的责任、两个关键决策、一个失败点、结果证据、保密边界。三个版本共享主线：3 分钟约保留一个决策；5 分钟两个决策；10 分钟可画简图并预留约两分钟追问。实际时长按语速校准，不追求固定字数。

- **3 分钟：** 为何重要、我负责什么、结果与复盘。  
- **5 分钟：** 加架构/方案取舍与关键行动。  
- **10 分钟：** 加时间线、备选、上线治理、追问入口；预留追问。

指标写法：「对象 + 定义 + 单位 + 聚合 + 基线/对照 + 时间窗 + 排除项」；比例再加分子分母。延迟说分位数；不能把计数强套成比例。区分实验因果 / 相关 / 定性验收。个人贡献链：问题识别 → 决策 → 产出 → 协作 → 发布观测；业务结果通常是共因。被打断先答问题，再用一句路标回主线；时间不够宁可删背景，也不省略个人边界与结果证据。

失败题：情景与你的决策、影响、你做了什么、学到的机制改进——避免甩锅或英雄叙事。冲突题：共同目标、选项代价、试验或数据、升级路径。需求频繁变更：变更单计价与护栏，不用加班时长证明。

**机制：** STAR-L 准备、面试讲事实；3/5/10 共享主线；指标写全口径（定义/单位/聚合/基线/时间窗）；区分我做/我推/机制产。

**失败形态：** 念字母模板；把题库示例数字说成亲历；平均值或挑窗报喜；被打断后回不到个人边界。

**验收：** 一页脱敏证据地图；追问能展开分子分母；失败题讲机制改进。证据坑位：〔填〕你的主项目口径卡。

### 7. 自我介绍、动机、规划、反问与诚信

自我介绍：先结论（层级、主能力、问题域）→ 2～3 条与 JD 相关证据 → 岗位匹配；不从毕业年逐段背简历，不为高职级夸大职责。离职原因：前向、专业、不贬低前雇主。规划：近 18 个月可验证贡献 + 能力曲线，避免空喊「三年变 CTO」。反问：团队最大交付风险、成功画像、技术债/质量现状、协作方式——展示判断力。面试最后用简洁收尾确认下一步，不临时加戏。

诚信：技术不确定就声明前提与验证计划；无该级别经历就承认并给较小事件或行动方案；拒发内部原件，可画脱敏抽象图；薪酬按当地规则与个人边界处理。禁止把网上案例说成亲历、虚报规模与指标。题库与简历里的可替换括号必须换成真实事实，示例比例不是你的业绩。

素材入口（不覆盖真源）：[简历指南](/interview/resume/senior-frontend-guide)、[简历模板](/interview/resume/senior-frontend-template)、[故事模板](/interview/stories/template)、[故事示例](/interview/stories/examples)、[模拟脚本](/interview/mocks/scripts)、[评分卡](/interview/mocks/scorecard)、[反问](/interview/mocks/reverse-questions)。速记：[领导力速记](/interview/review/sheets/09-leadership)。

**机制：** 介绍先结论再证据；规划近 18 个月可验证贡献；反问成功画像与交付风险；不确定就声明前提与验证计划。

**失败形态：** 从毕业年背简历；贬低前雇主；把网上案例说成亲历；用保密掩盖无证据。

**验收：** JD 匹配句可核对；保密边界清晰；不会时给替代路径。

### 8. 性能与体验：Lead 如何排优先级而不是运动式一周

先用真实用户分位数与转化基线说话，不凭感觉禁营销脚本。逐项列收益、加载成本、数据权限与故障隔离，约定 LCP / INP / 错误率护栏与回退开关。优化立项写清用户问题、基线、目标窗口、资源上限、停止线；达到可接受预算或边际收益低于其他需求就停。口径漂了先查采样与版本，再改代码；不挑有利窗口宣称成功。组织上把性能纳入 CR 与版本扫描，而不是年底突击。

**机制：** 用分位数与转化基线立项；写清目标窗口、资源上限、停止线；口径漂先查采样与版本。

**失败形态：** 运动式一周禁脚本；挑有利窗口宣称成功；感觉优化无护栏。

**验收：** LCP/INP/错误率护栏与回退开关；达预算或边际收益低则停。

### 9. 前后端边界、环境契约与组件库落地阻力

低频可并行且一致性要求低时，前端聚合可接受；主链路瀑布、弱网、敏感数据或多端重复编排时，用扇出与延迟基线推动 BFF / 服务端聚合，并明确契约 Owner。环境漂移用最小契约（配置结构、种子、Schema、依赖健康）+ 契约测试止血。组件库遇阻力：绑定业务试点的最小投资包，承诺采用率与缺陷护栏复审；资源被挤占就同步延期后果，不要求维护者业余补齐。

**机制：** 主链路瀑布/敏感数据推 BFF 并明确契约 Owner；环境用最小契约+契约测试止血；组件库用试点包换采用率。

**失败形态：** 前端聚合无限扇出；「预发过了」免责；维护者业余补齐。

**验收：** 扇出与延迟基线；契约测试红灯；采用率复审。

### 10. 招聘标准、反馈与多项目优先级

级别校准看：问题复杂度、影响半径、自主性、沟通与证据质量——用同一题目与评分维度，避免「感觉资深」。表现不达预期：对齐事实与影响，四周可验证改进计划，区分缺技能、缺上下文与动机问题。多项目争排期：价值 / 风险 / 依赖 / 机会成本表，唯一优先级入口；口头加塞必须走变更计价。影响他人决策时准备选项代价，而不是只重复立场。

**机制：** 同题同评分维度校准级别；不达预期给四周可验证计划；多项目用价值/风险/依赖表与唯一优先级入口。

**失败形态：** 「感觉资深」；口头加塞；只重复立场无选项代价。

**验收：** 评分表可复核；改进计划到期验收；变更计价记录。

### 11. 产品判断与「为什么是你」

技术工作要连到用户任务与业务护栏：减少步骤、降低错误、缩短确认时间、支撑活动峰值。能说清你拒绝过什么需求、用什么证据说服、结果如何验证——这比罗列做过的框架更像 Lead。自我介绍收束到「我希望下一阶段承担的结果」与 JD 要点对齐；反问优先问成功画像、最大交付风险、质量与债现状，展示你入职后如何判断，而不是只问福利。

**机制：** 技术工作连到用户任务与业务护栏；能说清拒绝过什么、用何证据说服、如何验证。

**失败形态：** 只罗列框架；说不清个人边界；反问只问福利。

**验收：** 至少一个「拒绝需求→证据→结果」故事；反问展示判断力。证据坑位：〔填〕你为什么匹配该 JD 的三句证据。

## 工程取舍与故障案例模板

| 步骤 | 你要说清的内容 |
| --- | --- |
| **约束** | SLA、窗口、团队规模、职权、保密 |
| **方案** | 选项 A/B/C、试点范围、门禁与回滚 |
| **取舍** | 速度 vs 风险；一致性 vs 团队自治 |
| **验证** | 同窗口基线、样本量、归因声明 |
| **复发防护** | ADR、跟项、复审触发器、豁免审计 |

**案例 A — 「跟风上新框架，交付变慢」**

- 约束：招聘叙事想要「现代化」。
- 方案：约束表打分 + 代表页 PoC；不匹配则不选。
- 取舍：简历关键词 vs 可维护。
- 验证：交付周期与缺陷对照。
- 防护：ADR + 复审条件。

**案例 B — 「门禁总被领导跳过」**

- 约束：大促热修。
- 方案：双人审批例外单；安全红线不可常规豁免；事后补偿扫描。
- 取舍：短期速度 vs 系统性风险。
- 验证：例外次数与逾期票据。
- 防护：频繁特批则改门禁或排期机制。

**案例 C — 「项目答辩数字被追问崩了」**

- 约束：简历写了提升比例。
- 方案：改口为完整口径或定性验收；区分个人/团队。
- 取舍：少报漂亮数 vs 诚信。
- 验证：监控/实验/工单来源。
- 防护：证据卡先于背稿。

**案例 D — 「跨组接口僵持两周」**

- 约束：上线窗口临近。
- 方案：量化扇出与等待；三方案 PoC；明确决策人。
- 取舍：前端聚合债 vs 等 BFF。
- 验证：SLA 与协作等待基线。
- 防护：契约 Owner 与升级路径。

**案例 E — 「新人第一周就改生产权限模块」**

- 约束：人力紧、权限域敏感。
- 方案：前 30 天渐进权限；先可回滚小闭环；结对与 checklist。
- 取舍：短期吞吐 vs 事故半径。
- 验证：首月独立 PR 与事故为零。
- 防护：onboarding 任务分级写进手册。

证据坑位（填你的数）：

- 主项目职责边界与时间窗〔填〕。
- 关键指标定义 / 基线 / 结果〔填〕。
- 一次选型或事故复盘跟项完成率〔填〕。
- 门禁例外未偿还数〔填〕；新人首月可独立 PR 数〔填〕。

行为与 Lead 合题的终局不是表演强势，而是证明你能把约束说清、把选项摊开、把结果留证、把改进变成机制。先准备证据卡再背稿；任何漂亮比例都要经得起「定义、窗口、来源、归因」四连问。把主项目边界、一次门禁例外偿还和一次复盘跟项完成率带进答辩，比背管理术语更像负责人。

## 追问树

**主问：你怎么做技术选型？**

- L1：维度与 PoC。  
  - L2：失败如何退出？  
    - L3：ADR 里最少写什么？收口：复审条件。

**主问：讲一个主项目（5 分钟版）**

- L1：重要性 + 个人边界。  
  - L2：两个决策与备选。  
    - L3：指标口径与归因。收口：复盘一条。

**主问：门禁什么必须红灯？**

- L1：安全、数据、构建/核心测试。  
  - L2：例外谁批？  
    - L3：CI 加速能否删检查？收口：风险价值排序。

**主问：没有职权如何推动改造？**

- L1：痛点基线与试点。  
  - L2：降低采用成本。  
    - L3：何时升级？收口：可退出 + 结果共担。

**主问：失败经历怎么讲？**

- L1：情景与你的决策。  
  - L2：影响与行动。  
    - L3：机制改进。收口：不甩锅不编造。

## 15 分钟口述验收清单

1. **（1 分钟）战场句：** 决策质量 + 可核验证据；示例数字不是我的业绩。
2. **（2 分钟）选型与债：** 维度、ADR、利息计价。
3. **（2 分钟）门禁与 CR：** 红灯清单、例外治理。
4. **（2 分钟）组织：** 带人 / 多端 / 值班任选一条讲透。
5. **（3 分钟）主项目：** 按 3～5 分钟版 STAR-L，含口径。
6. **（2 分钟）失败或冲突：** 机制改进收口。
7. **（1 分钟）反问：** 准备 2 个有判断力的问题。
8. **（2 分钟）工程收口：** 一次推动落地的决策故事（数字〔填〕）。

自检口令：

- 「示例 30% 能否直接说？」→ **不能；换自己的口径与基线。**
- 「团队 GMV 能否全归我？」→ **不能；区分贡献类型。**
- 「重试绿了算门禁过？」→ **不算。**
- 「保密能否当没有证据的挡箭牌？」→ **不能；给脱敏可核验替代。**

若时间只够一分钟收口：报岗位匹配结论、用一条带口径的主项目结果、点明一次取舍或复盘机制、准备一个有判断力的反问。够用了。细节被追问时回到证据卡，不临时编比例。
