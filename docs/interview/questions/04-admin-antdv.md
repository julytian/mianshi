# Ant Design Vue 中后台题库

> **怎么用：** 先盖住答案，自己口述 1～2 分钟（权限边界、表格封装、线上事故），再点开 `参考答案` 对照补洞。追问用来模拟面试官加压；踩坑是实战里最容易翻车的点。中英文术语之间请习惯留空格，口述时也建议如此。

本模块偏「十年经验口述」：少背 Ant Design Vue 组件 API，多讲**权限怎么不漏、表格怎么不卡、表单怎么可配置还敢改**。

### Q1. 中后台权限模型你会怎么设计？RBAC 讲到哪一层够用？

**考察点：** RBAC / ABAC、角色与资源、前端展示权 vs 后端强制权

::: details 参考答案
先想：前端权限只是「别让用户点到不该点的」；真正拦枪的是后端。口述必须把这两层拆开。

常见落地是 **RBAC**：用户 → 角色 → 权限码（菜单 / 路由 / 按钮 / API）。角色解决「一批人长得像」；权限码才是真正判断单元。菜单权限决定「能不能看见入口」；路由权限决定「直链能不能进」；按钮权限决定「页内能不能操作」——三者码表最好同源，别各写一套字符串。

什么时候升级到 ABAC / 数据权限？同一角色但「只能看本部门订单」「只能改自己创建的草稿」——这是资源属性 + 主体属性，前端最多做字段脱敏与筛选默认值，**过滤条件必须以后端为准**。

十年经验说法：权限模型先简单（角色 + 权限码），复杂规则沉到后端策略引擎；前端维护一份「码 → 是否可见」的计算函数，全站复用，禁止页面里散落 `if (role === 'admin')`。
:::

**追问：**
1. 超管「全部权限」你是前端写死还是后端下发 `*`？各有什么风险？
2. 权限码用字符串还是分层编码（如 `order:list:export`）？怎么做兼容演进？
3. 多租户 SaaS 下，角色是租户内还是平台级？前端路由表怎么切？

**踩坑：** 只藏按钮不拦路由——用户改 URL 仍进页；或只拦路由不藏按钮——体验差且接口仍可能被直接调。前后端必须同一套码。

### Q2. 动态路由你怎么从「后端菜单」落到 Vue Router？

**考察点：** 菜单树 → 路由表、组件映射、404 / 403、刷新后还原

::: details 参考答案
流程口述：登录后拉菜单 / 权限 → 前端把后端节点映射成 `RouteRecordRaw` → `router.addRoute` → 再放行导航。关键不是 API 形状，而是**组件怎么安全解析**。

常见两种：
1. **后端只给 path + 组件名字符串**，前端维护 `componentMap`（`OrderList: () => import('...')`）——安全，可审查；
2. **后端给相对路径**，前端 `import.meta.glob` 扫 views 再匹配——灵活，但要防路径穿越与漏扫。

刷新页面：权限与动态路由在内存，必须在 `beforeEach` 里做「未加载则先拉权限再 addRoute，然后 `next({ ...to, replace: true })`」——这是高频坑。404 要最后挂；无权限走 403 页而不是空白。

布局路由（`Layout` + `children`）通常前端固定外壳，业务页动态挂 children。口述强调：**动态的是业务树，不是整棵路由哲学重写**。
:::

**追问：**
1. `addRoute` 后为什么有时第一次导航还是 404？
2. 微前端或多 layout（侧栏 / 顶栏 / 空白页）时，动态路由挂在哪一层？
3. 路由 `meta` 里你会放哪些字段？哪些绝不能信前端伪造？

**踩坑：** 组件 map 用了同步 `import`，首屏把所有后台页打进主包——动态路由≠懒加载，要确认是 `() => import()`。

### Q3. 你会怎么封装一个「类 ProTable」的列表页？边界画在哪里？

**考察点：** 查询区 + 表格 + 分页约定、插槽扩展、反模式

::: details 参考答案
目标：把「搜、表、页、刷新、列设置」收敛成约定，让业务页只声明**列、请求、操作**。

我习惯的契约：
- `api`：`(params) => Promise<{ list, total }>`，统一分页字段转换（`current/pageSize` ↔ 后端）；
- `columns`：列定义 + 可选 `valueType`（金额、字典、日期）；
- `search`：字段 schema 或从 columns 推导；
- 插槽：`toolbar`、`bodyCell`、行操作；
- 命令式：`reload()`、`getSelected()`、重置查询。

封装原则：**约定优于配置地狱**。能覆盖 80% CRUD 列表即可；超复杂筛选、行内编辑、树表、可编辑单元格别硬塞进 ProTable——拆专用页或提供「无头模式」只包请求与分页。

口述金句：ProTable 是**减少样板**，不是第二个低代码平台。团队要有「什么时候不准用封装」的清单。
:::

**追问：**
1. 查询参数与 URL query 同步吗？刷新还原筛选你怎么做？
2. 多 Tab 列表共用一个封装时，缓存与请求竞态怎么处理？
3. 列设置（显隐 / 排序）持久化到 localStorage 还是用户配置中心？

**踩坑：** 封装里偷偷改响应结构或吞错——业务页调试时「接口明明有数据表格空」，查半天真凶是适配层。

### Q4. 大数据量表格卡顿，你会按什么顺序排查和优化？

**考察点：** 渲染成本、分页 vs 虚拟滚动、列过多、单元格重渲染

::: details 参考答案
先归因再动手：是**行数**、**列数 / 复杂单元格**、还是**频繁整表重渲染**？

顺序：
1. **业务层**：默认分页，禁止一次拉 1 万行「图省事」；导出走异步任务；
2. **渲染层**：单元格别塞重型组件；字典用纯文本 / 轻量 tag；避免每行 `deep watch`；
3. **表格层**：固定列、横向滚动时注意合成层；必要时虚拟滚动（见 Q11）；
4. **数据层**：行 key 稳定；更新用局部 patch，别每次 `dataSource = res.list` 换全新深对象树还附带巨型 computed。

口述要有数字感：200 行 × 30 列 × 每格一个组件 ≈ 6000 个 VNode，比「AntDV 慢」更接近真相。十年经验：先砍复杂度，再谈虚拟列表。
:::

**追问：**
1. 为什么「只是加了个自定义 filterDropdown」整表就抖？
2. `rowSelection` 跨页勾选状态你怎么存？
3. 服务端排序 / 筛选与前端排序如何分工？

**踩坑：** 用 `v-if` 控制整表销毁重建代替刷新——数据一多必闪白；优先改 `dataSource` 或 `key` 策略要克制。

### Q5. Schema 表单（配置化表单）你怎么落地？和「手写 a-form」怎么选？

**考察点：** JSON Schema / 自研 schema、校验、联动、可维护性

::: details 参考答案
Schema 表单适合：**字段多、常改、多端/多租户差异大**的中后台录入。手写 Form 适合：**强交互、复杂步进、高度定制布局**。

落地要点：
- 字段描述：`name`、`label`、`component`、`props`、`rules`、`visible`/`disabled` 表达式；
- 联动：依赖字段变化时重算可见性与选项（要防循环依赖）；
- 校验：复用 async-validator / Zod 一类，前后端规则尽量同源文档；
- 布局：栅格、分组、分步——schema 表达布局别无限嵌套。

风险：配置膨胀后「没人敢改」；调试比 Vue 模板难。治理手段：schema 分模块、可视化搭建与代码导出二选一要克制、复杂字段允许 `slot` / 自定义组件逃逸。

口述结构：先讲选型边界，再讲联动与校验，最后讲**逃生舱**——这才像带过项目的人。
:::

**追问：**
1. 表达式用字符串 `eval` 还是 JS Function？安全与 DX 怎么权衡？
2. 后端下发表单 schema 时，如何防恶意 component 名？
3. 和低代码平台的边界你怎么画？

**踩坑：** 把业务规则全写进 schema 字符串，Code Review 形同虚设——规则一复杂就该回到代码。

### Q6. 上传 / 下载在中后台你会怎么设计？大文件和权限怎么讲？

**考察点：** 直传 / 中转、进度与断点、下载鉴权、导出任务化

::: details 参考答案
上传分场景：
- **小文件走业务网关**：简单，便于鉴权与病毒扫描；
- **大文件 / 私有云**：前端直传 OSS（STS 临时凭证）+ 回调业务登记——省带宽、可断点；
- 组件层：`a-upload` 控 `beforeUpload`、文件类型 / 大小、自定义请求、失败重试；别默认把整文件转 base64 塞进 JSON。

下载：
- 有权限的文件用**带鉴权的下载接口**或短时签名 URL，禁止长期公开链；
- Excel / 报表导出：同步下载只适合小结果；超时与大结果必须**异步任务 + 通知 / 轮询**。

口述强调：上传成功只代表对象存储有了，**业务状态要以服务端登记为准**；下载失败要区分网络、权限、文件过期。
:::

**追问：**
1. 图片要压缩再传，你放前端还是网关？
2. `Content-Disposition` 中文文件名乱码你怎么处理？
3. 同一表单多文件与表单字段提交的事务一致性怎么讲？

**踩坑：** 用 `window.open(url)` 下带 token 的文件——token 进 Referrer / 历史；应 blob 下载或短时签名。

### Q7. 按钮级权限你怎么做才不又臭又长？

**考察点：** 指令 / 组件 / 函数式鉴权、与后端码对齐、无权限时隐藏 vs 禁用

::: details 参考答案
三层工具都要，按场景用：
1. **函数** `hasPermission('order:export')`——逻辑分支、组合条件；
2. **组件** `<Auth code="...">`——包一截 DOM；
3. **指令** `v-auth`——简单显隐，注意指令对组件根节点、异步更新的坑。

产品策略：无权限**隐藏**（减少噪音）还是**禁用 + Tooltip 说明**（让人知道有功能但无权限）——需和产品统一，别一页一种。

实现上权限码来自登录态 / 权限接口，放 Pinia；路由 `meta.permission` 与按钮码同一套。禁止硬编码角色名。

十年经验：按钮权限的维护成本在「码表治理」，不在指令写法——码要可检索、可废弃、有负责人。
:::

**追问：**
1. 一个按钮依赖「权限码 + 行状态」双重条件，封装放哪？
2. 指令删除 DOM 与 `v-if` 哪个更稳？SSR / 测试呢？
3. 权限变更后如何热更新，要不要强制重新登录？

**踩坑：** `v-auth` 只 `display:none`——元素还在，爬虫或误点仍可能触发；应移除或真正禁用事件。

### Q8. 菜单、多页签与 `keep-alive` 你怎么一起设计？

**考察点：** 缓存 key、页签关闭、onActivated、内存泄漏

::: details 参考答案
中后台常见「侧栏菜单 + 多页签 + 页面缓存」。模型：
- 路由 `name` 必须稳定且唯一，`keep-alive` 的 `include` 跟页签打开集合走；
- 打开页签 = 加入缓存名单；关闭页签 = 从 include 剔除并删组件实例；
- 同路由不同参数（两个订单详情）要决定：共用一个缓存还是 `key` 到 params——多数详情**不缓存**或按 id 限长 LRU。

生命周期：首次 `onMounted`，回页签 `onActivated`——拉数放哪要约定清楚，避免双请求。离开时重置临时 UI 状态（弹窗、抽屉）防「幽灵弹层」。

口述强调：**缓存是产品体验，不是默认全开**。列表可缓存；巨型报表、带 WebSocket 的页谨慎。
:::

**追问：**
1. 关闭「其他 / 全部」页签时，如何批量清缓存？
2. `keep-alive` 与动态路由 name 不一致导致缓存失效，你怎么查？
3. 缓存页里定时器 / 事件监听漏清，你会在哪一层兜底？

**踩坑：** 用路径当 keep-alive key，query 一变整页重建；或 include 写了组件名但路由 name 不同——缓存静默失效。

### Q9. 主题与布局（暗色、紧凑、多布局）你会怎么做才可维护？

**考察点：** Design Token、CSS 变量、ConfigProvider、布局切换

::: details 参考答案
Ant Design Vue 4 / 现代方案优先 **Design Token + CSS 变量**：通过 `ConfigProvider` 注入算法（默认 / 暗色 / 紧凑），业务少写死十六进制。自研皮肤：在 token 之上再挂一层品牌变量，组件库与业务都读变量。

布局：侧栏、顶栏、混合、内容全屏——用 layout 组件 + 路由 `meta.layout` 切换，别复制四套壳。宽度折叠、固定 Header、内容区滚动容器要统一，否则表格 sticky、弹层定位会到处打架。

持久化：用户主题偏好进 localStorage 或用户配置接口；**首屏要防闪**（先读偏好再绘，或内联脚本设 `data-theme`）。

口述别停在「能切暗色」：要讲**token 单一真相**和**业务自定义样式的逃生方式**（少 `!important` 盖组件）。
:::

**追问：**
1. 图表、地图第三方画布如何跟暗色主题同步？
2. 多品牌白标如何在构建期 / 运行期切换 token？
3. 紧凑模式下表格行高与可点击热区怎么平衡无障碍？

**踩坑：** 全局覆写 `.ant-btn` 颜色「调品牌色」，升级 AntDV 后全站回归——应走 token / 少层包装组件。

### Q10. 字典 / 枚举如何与后端同步，避免前后端各写一套？

**考察点：** 字典服务、缓存、本地兜底、类型生成

::: details 参考答案
原则：**枚举语义以后端 / 数据字典为准**，前端不做第二真相。

常见架构：
1. 启动或首次使用时拉字典（按 type 分批）；
2. Pinia / 内存缓存 + 版本号 / ETag；变更低频可长缓存，变更频繁按 type 失效；
3. 表格 / 表单通过 `valueType: 'dict'` 或组件 `DictSelect` 消费；
4. 编译期：若后端 OpenAPI / 枚举稳定，可 codegen TS 联合类型——运行时仍以后端值为准做校验。

展示层：`code → label`，未知码显示原文 + 打点，别静默成空白。前后端口径冲突时，联调以接口文档与字典服务为准，前端写死常量只做「网络失败兜底」且要可观测。
:::

**追问：**
1. 字典项上百万怎么办？还拉全量吗？
2. 多语言下 label 放前端 i18n 还是字典服务？
3. 后端改了枚举含义但码不变，前端如何发现？

**踩坑：** 前端本地写死一份 statusMap，后端加新状态，线上出现「空白标签 / 筛选不到」——还查不出错。

### Q11. `a-table` 虚拟滚动你怎么用？取舍和坑是什么？

**考察点：** 虚拟列表原理、固定列 / 展开行限制、何时不该上

::: details 参考答案
虚拟滚动只渲染视口附近行，行数上千时主线程与 DOM 压力下降。但代价是：
- 行高最好稳定，动态行高要额外测量；
- 展开行、复杂 rowspan、部分固定列场景支持不完整或行为怪；
- 滚动定位、打印、锚点、「整表 DOM 被爬」类需求会受伤；
- 和自定义 body 插槽、子组件本地状态兼容性要实测。

选型：
- **分页能解决就别虚拟**——产品与后端成本更低；
- 必须「一屏内连续浏览万级」再上虚拟；
- 列极多时虚拟只救行，不救「每行过重」——仍要减单元格复杂度。

口述像老手：先讲收益，再讲**不适用场景**，最后讲你们项目实测的边界（例如超过 N 行才开）。
:::

**追问：**
1. 虚拟滚动下 `rowSelection` 全选是「当前页」还是「全部数据」？
2. 横向虚拟（列很多）你怎么看成熟度？
3. 和自研 canvas 表 / 第三方网格方案怎么比？

**踩坑：** 开了虚拟却每行塞编辑器 / 图表，DOM 少了但 JS 照样炸——虚拟不是免死金牌。

### Q12. 弹窗 Modal 和抽屉 Drawer，中后台 UX 你怎么选？

**考察点：** 信息架构、任务时长、多层叠、表单场景

::: details 参考答案
直觉模型：
- **Modal**：短任务、强聚焦、要明确确认（删除确认、小表单、关键警告）。模态打断主流程，适合「做完再回去」；
- **Drawer**：中长表单、详情对照列表、需要同时瞥见背后上下文。从侧面推入，空间更大，适合「边看列表边改」。

细则：
- 表单字段多、有分步 → Drawer 或独立页，别塞巨大 Modal；
- 危险操作 → 小 Modal 确认，文案讲清不可逆后果；
- 避免 Modal 套 Modal、Drawer 套 Modal 叠罗汉——改为步进或独立路由页；
- 关闭拦截：脏数据要确认；Esc / 遮罩点击是否可关要按表单危险级别定。

十年经验：组件选择是信息架构问题，不是「哪个好看」。面试讲清**任务时长 × 是否需要对照上下文**两个轴就够打动人。
:::

**追问：**
1. 详情既要分享 URL 又要抽屉体验，怎么做？
2. 移动端宽度下 Drawer/Modal 策略如何降级？
3. 全局唯一弹层管理（防多个业务同时弹）你怎么做？

**踩坑：** 列表页每个操作都开全屏 Modal 重型表单——用户失去列表上下文，保存后还要重新找行。

### Q13. 中后台「操作列 / 批量操作」权限与交互怎么设计才稳？

**考察点：** 行操作收敛、批量权限、二次确认、失败部分成功

::: details 参考答案
行操作超过三个就收进「更多」；危险操作（删除、作废、打款）视觉降权并二次确认。批量操作：工具栏按钮受权限码控制，且**以勾选行的实际可操作集合为准**——部分行不满足状态时，要么禁用并提示原因，要么允许提交由后端过滤并返回部分成功报告。

前端要处理：
- 跨页勾选的数据范围提示（当前页 / 全部结果）；
- 批量请求的并发限制与进度；
- 部分失败时的明细展示与可重试。

口述强调：批量是后端事务与幂等问题，前端负责**预期管理**，别假装 100% 成功。
:::

**追问：**
1. 「跨页全选 10 万条」产品坚持要，你怎么技术谈判？
2. 操作列根据行状态动态变化，和按钮权限指令如何组合？
3. 审计日志要记「谁点的」，前端埋点还是纯后端？

**踩坑：** 前端过滤完可操作行再调接口，后端没校验——篡改请求即可越权批量。

### Q14. 表格列的「自定义渲染 / 插槽」泛滥了，你怎么治理？

**考察点：** 列工厂、价值类型、性能与一致性

::: details 参考答案
症状：每个页面复制 `bodyCell` 大段 switch，字典、金额、时间、用户卡片各写一套，样式还不一致。

治理：
1. **valueType 映射**：`money`、`date`、`dict`、`user`、`status` 走统一渲染器；
2. **列工厂函数**：`col.dict('status', STATUS)`、`col.money('amount')`；
3. 真正特殊的业务列才允许页面级 slot，并限制复杂度；
4. 文档化「推荐渲染器清单」，Code Review 盯重复 UI。

性能上：渲染器保持纯函数 / 轻量组件；禁止在 render 里 new 大对象或现场请求。一致性比「这页特别好看」更重要——中后台是效率工具。
:::

**追问：**
1. 渲染器要不要自动加 Tooltip 处理超长文本？
2. 空值显示 `—` 还是空白，如何全局统一？
3. 列渲染与导出 Excel 的字段格式如何复用？

**踩坑：** 在自定义渲染里直接调接口补全字段——表格一翻页请求风暴，应在数据层 join 好。
