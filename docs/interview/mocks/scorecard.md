# 模拟面试评分表

> **怎么用：** 每场模拟结束后立刻打分（搭档评或自评）。只打整数 1～5；先看「描述」再给分，避免全场打 4。配合 [模拟脚本](/interview/mocks/scripts) 使用；弱项回到对应 [题库](/interview/questions/02-vue3) 或 [故事模板](/interview/stories/template) 加练。

**建议：** 保留原五维作为唯一计分维度。架构场新增 4 个观察点，但只用于补充证据，不另算 4 个维度，避免把同一能力重复加分。

## 总分计算与岗位权重

每维评分为 1～5。**总分 = Σ（维度得分 × 岗位权重）**，权重之和为 100%，因此总分仍在 1～5。未明确岗位时使用通用权重；某维未考察时，不得直接填 3 分，应按剩余维度的权重同比归一化。

| 岗位 | 技术深度 | 表达结构 | 决策取舍 | AI 协作 | 前后端闭环 |
| ---- | -------- | -------- | -------- | ------- | ---------- |
| 通用高级前端 | 30% | 25% | 20% | 10% | 15% |
| 微前端 / 前端架构 | 30% | 15% | 35% | 5% | 15% |
| 全栈偏前 / NestJS | 25% | 15% | 20% | 10% | 30% |
| Tech Lead | 25% | 20% | 35% | 10% | 10% |
| 创业 AI | 20% | 15% | 25% | 25% | 15% |

示例：全栈偏前场五维依次为 4、3、4、3、5，则总分为 `4×25% + 3×15% + 4×20% + 3×10% + 5×30% = 4.05`。

### 红线

命中任一红线时，本场不得判定达标；即使加权总分较高，也必须先修复：

- 任一计分维度为 1 分，或岗位最高权重维度 ≤2 分。
- 编造项目、指标、职责或生产经验；无法区分「做过、参与过、了解」。
- 安全与权限问题无边界意识，例如信任前端鉴权、泄露密钥、让 AI 生成代码未经审查直接上线。
- 系统设计完全不问约束，且面对故障没有止损、回滚或降级方案。

## 架构场 4 个观察点

以下观察点不新增分数，分别为原五维补充证据：

| 观察点 | 看什么 | 计入原维度 |
| ------ | ------ | ---------- |
| 架构约束识别 | 是否先问业务目标、规模、团队、合规、存量与成本 | 决策取舍；表达结构仅看澄清是否有序 |
| 原理深度 | 是否解释依赖、隔离、请求链路或运行时机制，并说明边界 | 技术深度 |
| 故障治理 | 是否覆盖发现、止损、降级、回滚、复盘与防复发 | 技术深度；前后端故障协作证据计入前后端闭环 |
| 演进能力 | 是否给出触发指标、迁移步骤、兼容期与退出路径 | 决策取舍 |

记录原则：同一回答只能作为一个主维度的得分证据；其他维度可引用，但不得因同一句话重复抬分。

## 维度一：技术深度

考察：原理与实践是否匹配年限；能否下沉到机制、边界与排查，而不是只报库名。

| 分 | 描述 |
| -- | ---- |
| 1 | 只会名词堆叠；追问一层即卡壳；对所用框架关键机制说不清 |
| 2 | 能讲常用 API 与表面流程；说不清为什么；排查停留在「重启 / 再试试」 |
| 3 | 主栈（如 Vue3 / 工程化 / 中后台）能讲清常见原理与项目证据；次要领域点到为止 |
| 4 | 能对比方案、指出边界与坑；结合项目讲清性能 / 权限 / 构建等至少一块深水区 |
| 5 | 深度与广度平衡；追问仍稳定；能教级讲解且主动标明「我没做过的部分」 |

**观察信号：**

- 正向：主动画时序 / 分层、提到取舍代价、能量化或描述验证方式  
- 负向：全程「我们用了 XX」、回避具体模块归属、原理背诵与项目脱节

---

## 维度二：表达结构

考察：是否结论先行、时长可控、STAR-L 完整；被打断后能否收回主线。

| 分 | 描述 |
| -- | ---- |
| 1 | 无结构，从细节或公司历史扯起；超时严重；听者抓不住结论 |
| 2 | 有片段结构但不稳定；常缺结果或任务边界；「我们」远多于「我」 |
| 3 | 自我介绍与项目能按背景→行动→结果讲述；偶有跑题但可拉回 |
| 4 | 明显结论先行；30s / 2min 档切换自如；追问回答短而完整 |
| 5 | 全程可当范文；主动控时、预埋钩子、复述面试官问题后再答 |

**观察信号：**

- 正向：先答一句结论再展开；用「三点」组织；主动说「我停在这里看你想听哪块」  
- 负向：重复同一句、术语瀑布、答非所问

---

## 维度三：决策取舍

考察：是否呈现方案对比、约束意识、否决理由与演进条件（Lead 面核心）。

| 分 | 描述 |
| -- | ---- |
| 1 | 只有唯一做法，说不清为什么；或一切「听领导的」无自己判断 |
| 2 | 能说出选了什么，但对比弱；不考虑代价、风险或回滚 |
| 3 | 至少给出 2 选 1 的理由，能联系工期 / 复杂度 / 团队能力 |
| 4 | 清晰对比维度（成本、风险、可维护、交接）；承认当时信息差；有兜底 |
| 5 | 决策像方法论：目标→约束→选项→标准→复盘；能指导他人做同类判断 |

**观察信号：**

- 正向：「没选 B 是因为…」「若指标到 X 会升级方案」  
- 负向：事后诸葛式完美叙事、从不承认坑、一切都是最优解

---

## 维度四：AI 协作成熟度

考察：是否把 AI 当产能工具且有质量边界；而非「会用 ChatGPT」或「完全不用装清高」。

| 分 | 描述 |
| -- | ---- |
| 1 | 否认任何 AI 使用却答不出传统路径；或声称全自动生成从不审查 |
| 2 | 只会「用 AI 查报错 / 写片段」；无流程、无审查清单、无责任意识 |
| 3 | 能说明典型使用场景（样板、单测草稿、重构建议）并提到人工把关 |
| 4 | 有可复述的工作流：契约 / 提示粒度 / 审查清单 / 测试；清楚不信任点（安全、权限、复杂业务） |
| 5 | 能定团队级规范（何时用、何时禁、CR 看什么）；把 AI 纳入质量门禁叙事 |

**观察信号：**

- 正向：主动讲「AI 写了什么、我改了什么」；提到越权与校验  
- 负向：神秘化提示词、或道德审判式「我们不用 AI」却无替代产能说明  

**场次说明：** 业务型中小厂若几乎未涉及 AI，本维可标「未考察」不计入均分；创业 AI / 相关深挖场必评。

---

## 维度五：前后端闭环

考察：接口契约、联调排障、错误处理、简单后端或协作深度；符合「全栈偏前」边界。

| 分 | 描述 |
| -- | ---- |
| 1 | 只认前端页面；接口问题一律「后端的锅」；说不清自己如何联调 |
| 2 | 会调接口、贴字段；不懂错误码 / 鉴权 / 环境；Java 或后端叙事空洞 |
| 3 | 能讲清契约、联调步骤、常见 401/403/校验失败处理；知道前后端责任分界 |
| 4 | 能独立扛或讲清简单 Spring Boot CRUD 闭环；统一响应、校验、权限有实践细节 |
| 5 | 闭环质量意识强（可观测、可回滚、可交接）；在边界内深度足够，且不越界吹微服务 |

**观察信号：**

- 正向：主动提契约先行、失败路径、小范围验证  
- 负向：大谈分布式事务 / JVM 却答不清一个列表接口的分页与权限  

**叙事对齐：** 评分时对照 [总览 · Java 叙事边界](/interview/00-overview)——越界吹深度反而扣「决策取舍 / 表达」可信度。
