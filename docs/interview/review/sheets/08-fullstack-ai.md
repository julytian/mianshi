# 全栈、数据与 AI 速记

> **真源：** [07 Java 全栈](/interview/questions/07-java-fullstack)、[13 NestJS](/interview/questions/13-nestjs)、[15 数据库 / Prisma](/interview/questions/15-database-prisma)、[09 AI 编程](/interview/questions/09-ai-vibe-coding) 为唯一真源；冲突时以题库为准。
>
> **用法：** 面试前遮住口述稿先自讲，再对结论卡与追问速答。证据坑位请填入你自己的项目指标，勿背他人数字。

## 一句话定位

本域讲清「前后端契约与鉴权闭环 + Nest / 数据访问边界 + 索引事务与 Prisma 迁移 + AI 辅助交付的责任边界」。资深面试要的是**可联调、可回滚、可审查**，不是背框架注解。你应能在五分钟内把错误码、JWT 刷新、N+1、expand-and-contract 与 AI 审查清单串成故事，并分清服务端权威与前端体验控制，避免把演示成功说成生产就绪。

## 核心结论卡

1. **结论：** 后端分层 Controller / Service / 持久化，避免上帝类；统一响应体与错误码是前后端契约核心。  
   **边界：** 业务拒绝与系统故障分码；前端按码决定提示、登录态与是否重试。  
   **证据坑位：** 〔填〕错误码表与一次联调扯皮复盘。

2. **结论：** RESTful 服务资源，前端好用靠稳定字段、分页约定与可演进筛选，而不是堆动词 URL。  
   **边界：** 复杂查询可 RPC 风格，但要版本与文档。  
   **证据坑位：** 〔填〕列表筛选参数演进一次兼容发布。

3. **结论：** JWT：短 access + 可轮换 refresh；前端优先 HttpOnly Cookie / BFF，少把长期 Token 塞 `localStorage`。  
   **边界：** 刷新要防重放与并发 single-flight；登出撤销会话族。  
   **证据坑位：** 〔填〕刷新失败态与强制下线验收。

4. **结论：** 权限码菜单 / 按钮 / 接口对齐；Redis 适合会话、热点、限流与锁，但要讲失效与一致性。  
   **边界：** 缓存与 DB 一致性口语要分场景，不装「永远强一致」。  
   **证据坑位：** 〔填〕一次缓存脏读或击穿治理。

5. **结论：** 幂等与防重复：前端防抖 + 后端幂等键；事务边界在一致性用例内，不含外部 HTTP。  
   **边界：** 重复点击不是靠前端 disable 单独解决。  
   **证据坑位：** 〔填〕创建类接口幂等键设计与重放测试。

6. **结论：** Nest 中 Module 控制可见性；Middleware → Guard → Interceptor(入) → Pipe → Handler → Interceptor(出) → Filter。  
   **边界：** request scope 会扩散，默认保持 singleton，请求信息显式传参。  
   **证据坑位：** 〔填〕一次 Guard / Pipe 顺序相关的鉴权 bug。

7. **结论：** DTO + ValidationPipe 守输入；输出用明确模型，敏感字段不靠「忘记返回」碰运气。  
   **边界：** Swagger / versioning 与 DTO 共同构成契约，要有弃用周期。  
   **证据坑位：** 〔填〕API 版本弃用公告与兼容窗口。

8. **结论：** 分页：深 offset 伤大表，在线浏览优先游标；导出变后台任务分批写对象存储。  
   **边界：** 不稳定排序会导致翻页重复 / 漏行。  
   **证据坑位：** 〔填〕大表列表与导出任务的方案对照。

9. **结论：** 联合索引按查询模式设计，不是按字段列表猜；`EXPLAIN` 看访问类型、key、rows、Extra。  
   **边界：** 最左匹配、覆盖索引、回表要能一口举例。  
   **证据坑位：** 〔填〕一条慢 SQL 的前后计划对比。

10. **结论：** 事务与隔离级别对应脏读 / 不可重复读 / 幻读；库存扣减要让「校验并更新」成为原子写入。  
    **边界：** 死锁看等待环与重试边界，不看报错字符串。  
    **证据坑位：** 〔填〕一次死锁复现与重试策略。

11. **结论：** Prisma：`select` / `include` 控制形状；治理 N+1；批量事务短小，外部调用移出事务。  
    **边界：** 迁移用 expand-and-contract，库变更与应用发布是多版本共存。  
    **证据坑位：** 〔填〕一次兼容迁移的发布顺序清单。

12. **结论：** 连接池按实例数 × 池上限对数据库预算；Serverless 要额外考虑代理与爆发。  
    **边界：** 池耗尽≠ CPU 高；先找长事务与泄漏。  
    **证据坑位：** 〔填〕池配置与一次耗尽告警处置。

13. **结论：** AI 任务要拆段、给验收与非目标；审查清单含越权、注入、幻觉 API、密钥与竞态。  
    **边界：** Rules / Skills 非强制安全边界；高后果任务可不用 AI。  
    **证据坑位：** 〔填〕一次幻觉拦截与返工记录。

14. **结论：** 上下文 / 规则 / 技能 / 工具职责分离；MCP 与宿主沙箱两层最小权限。  
    **边界：** 输出视为不可信，不能直接当命令执行。  
    **证据坑位：** 〔填〕团队 AI 规范与工具权限表。

15. **结论：** 前后端联调方法论：固定复现包 → 分层定位 → 一次一假设 → 留下根因。  
    **边界：** 别让 AI 在排障时顺便重构。  
    **证据坑位：** 〔填〕一次联调时间线与根因归类。

16. **结论：** TypeORM vs Prisma 看团队、迁移、复杂 SQL 与可观测，不看语法短。  
    **边界：** 模块化单体要执行依赖约束，不靠文档。  
    **证据坑位：** 〔填〕数据访问选型 ADR。

17. **结论：** 文件上传：前端体验校验 + 服务端重验类型与大小；对象键随机，下载带正确 MIME 与 `nosniff`。  
    **边界：** 预签名 URL 与权限过期要设计；导出任务可恢复。  
    **证据坑位：** 〔填〕上传链路权限与一次恶意类型拦截。

18. **结论：** 多租户访问必须以服务端可信身份定租户，禁止只信客户端传来的 `tenantId`。  
    **边界：** 参数化防注入 ≠ 防越权；原生 SQL 仍要资源级授权。  
    **证据坑位：** 〔填〕一次跨租户越权复测记录。

## 高频追问速答

1. **统一错误码怎么设计才少扯皮？**  
   约定 envelope：业务码、HTTP 状态、可读消息、可选细节。业务可预期拒绝（校验、权限、冲突）与系统故障分开；前端据此决定 Toast、跳登录还是重试。码表进仓库与 OpenAPI，变更有兼容窗口。联调时先对码再对字段，避免「后端说失败、前端当成功」。权限拒绝不要只靠文案模糊处理，要可机读。

2. **刷新 Token 并发怎么收？**  
   多请求同时 401 时，客户端 single-flight：只发起一次刷新，其余排队，成功后重放，失败则统一登出。服务端 refresh rotation：旧 refresh 失效，疑似重放可撤整族会话。Cookie 方案注意 CSRF；纯 SPA 用 PKCE 且不放 client secret。面试要讲清「谁存 Token、如何轮换、如何强制下线」，而不是只说用了 JWT。

3. **Nest 五类组件别放错什么？**  
   Middleware 偏通用前置；Guard 做授权门禁；Pipe 做转换与校验；Interceptor 做切面映射、缓存、超时；Filter 做异常到响应的最后翻译。业务规则不进 Middleware 糊成脚本。request scope 仅在确有请求态依赖时使用，否则保持 singleton 并显式传参，避免依赖树被意外放大。顺序记错会导致「校验前就进业务」或「异常格式不统一」。

4. **Prisma N+1 你怎么证明和修？**  
   用查询日志或 Trace 看「父记录数增长则同类 SQL 次数增长」。修复用 `include` / 批量查询 / 限制字段，目标是有界查询次数与数据量，不是强行一条巨型 JOIN。列表接口尤要防循环里按 id 查详情。验收看一次请求的 SQL 条数与耗时，而不是只看功能正确。

5. **迁移为何要 expand-and-contract？**  
   数据库与多版本应用会短暂共存：先加兼容列 / 表，再发布可双读双写或兼容旧读的应用，回填校验后切流量，最后删旧结构。把 breaking 迁移与应用发布绑成瞬时动作，回滚会卡在不可逆结构。前端发版不同步时，后端兼容窗口就是安全带。

6. **库存超卖一句话怎么防？**  
   让「剩余量足够才扣减」在数据库层原子完成，并用影响行数判断成功，而不是先查后改。是否加悲观锁取决于后续是否必须基于锁住行做多步。前端防重复点击只是体验，真正防超卖在事务与约束。高并发还可引入预扣、队列或分桶，但面试先把原子更新讲清楚。

7. **AI 一天半交付你怎么控场？**  
   先人工定表结构、接口表、DoD 与非目标；再竖切后端可运行与种子数据，前端对齐登录与请求封装；然后列表表单与权限，补越权测试；最后空错态与演示脚本。全程禁止无审查合入，发现幻觉 API 立即停。演示成功不等于可上生产：还要日志、权限与回滚。边界不清时宁可缩范围。

8. **什么时候明确不用 AI？**  
   高不确定架构决策、高后果安全变更、复杂性能根因、以及需要法律责任的变更，应人工主导。AI 适合样板、测试草稿、解释与局部重构，但净收益要看返工与缺陷，不是生成行数。团队规范要风险分级与例外流程。把模型输出当不可信输入，才能避免 prompt injection 与误执行。

## 反例 / 红线

- 前端 disable 当唯一防重复；Token 默认长期存 `localStorage`。
- 事务里打外部 HTTP；迁移与应用同一秒 breaking。
- 循环里 Prisma 查询却声称「ORM 很慢」了事。
- AI 输出未审越权 / 幻觉直接合主干。
- 错误码靠中文消息匹配；Swagger 与真实行为长期漂移。
- 多租户只信前端传来的租户字段；上传只做客户端类型校验。
