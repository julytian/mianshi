# 后台与业务前端速记

> **真源：** [04 中后台 Ant Design Vue](/interview/questions/04-admin-antdv)、[05 H5 Vant](/interview/questions/05-h5-vant) 为唯一真源；冲突时以题库为准。
>
> **用法：** 面试前遮住口述稿先自讲，再对结论卡与追问速答。证据坑位请填入你自己的项目指标，勿背他人数字。

## 一句话定位

本域讲清「中后台权限 / 表格 / 配置化表单交付」与「H5 适配 / 弱网 / WebView 返回栈」两条业务前线。资深面试要的是**可验收的列表页与移动链路**，不是组件 API 背诵。你应能在五分钟内把 RBAC、ProTable 边界、虚拟化、安全区与 Bridge 串成交付故事。

## 核心结论卡

1. **结论：** 中后台权限至少对齐菜单、路由、按钮与接口；前端隐藏不是授权，服务端必须再鉴权。  
   **边界：** RBAC 讲到角色—权限—资源够用；数据范围与审计要单独闭环。  
   **证据坑位：** 〔填〕一次越权复测：藏按钮仍调接口被拒。

2. **结论：** 动态路由由后端菜单生成可访问表，前端做组件映射与 404 / 403 兜底，不信任纯前端路由表。  
   **边界：** 刷新白屏常是动态路由注册时机或组件路径映射错误。  
   **证据坑位：** 〔填〕菜单 → 路由 → 组件的映射约定与一次白屏修复。

3. **结论：** 类 ProTable 封装查询、表格、分页、列设置；边界停在「标准列表页」，复杂定制走插槽扩展而非无限配置。  
   **边界：** URL 同步查询条件，处理请求竞态：旧响应不得覆盖新筛选。  
   **证据坑位：** 〔填〕标准列表页复用率与一次竞态 bug。

4. **结论：** 大表卡顿按序查：渲染行数、列渲染成本、响应式深度、请求与排序。  
   **边界：** `a-table` 纵向滚动 ≠ 真正虚拟化；万级行要虚拟滚动并守住键盘 / 复制等边界。  
   **证据坑位：** 〔填〕行数阈值、虚拟化前后交互可用性验收。

5. **结论：** Schema 表单适合字段多、变化快的标准 CRUD；强交互或特殊布局宁可手写 Form。  
   **边界：** 配置要版本化与校验，避免「字段数组」长成无法测试的业务脚本。  
   **证据坑位：** 〔填〕Schema 与手写表单的选型表及一次配置事故。

6. **结论：** 上传下载要分权限、大小、类型与异步任务；百万行导入导出做成可恢复任务，而不是浏览器硬扛。  
   **边界：** 前端校验只改善体验，服务端必须再验。  
   **证据坑位：** 〔填〕大文件上传断点 / 导出任务状态机。

7. **结论：** 按钮级权限用指令或组件收口，避免每个页面手写 `v-if` 散落；操作列与批量操作要统一无权限降级。  
   **边界：** 无权限是隐藏还是禁用要产品一致，并写审计。  
   **证据坑位：** 〔填〕权限码命名规范与批量操作鉴权用例。

8. **结论：** 多页签 + `keep-alive` 要白名单与 `max`；缓存身份用稳定 key，滚动与草稿策略显式设计。  
   **边界：** 切走不卸实例，定时器与请求要挂激活生命周期。  
   **证据坑位：** 〔填〕页签关闭清理与内存上限策略。

9. **结论：** 字典 / 枚举与后端单一真源，前端缓存可失效；主题走 Token，避免二次封装双 API 锁死升级。  
   **边界：** 旧字典语义带到线上比「少一次请求」更致命。  
   **证据坑位：** 〔填〕字典版本失效策略与主题 Token 表。

10. **结论：** H5 适配先定 viewport 与基准；`rem` / `vw` / 动态视口单位选一种主策略并与组件库一致。  
    **边界：** 安全区用 `env(safe-area-inset-*)`，不是全局加一大圈 padding。  
    **证据坑位：** 〔填〕刘海机与横条机的适配验收截图。

11. **结论：** 滚动穿透要锁背景滚动并恢复位置；软键盘优先让浏览器滚到聚焦控件，确需再上 Visual Viewport。  
    **边界：** 弹层、列表手势与返回栈要当成可恢复状态机，而不是散落 `overflow: hidden`。  
    **证据坑位：** 〔填〕遮罩打开 / 关闭后滚动位置恢复用例。

12. **结论：** 弱网要可重试、可取消、防重复提交；离线草稿与提交幂等一起设计。  
    **边界：** 「能演示的骨架屏」不等于弱网可完成关键任务。  
    **证据坑位：** 〔填〕弱网提交不重复的验收与幂等键。

13. **结论：** H5 首屏抓关键请求、图片与桥调用；整站性能另算。列表用分页 / 虚拟化，图片懒加载要占位防 CLS。  
    **边界：** Vant List / PullRefresh 要处理空态、错误态与竞态。  
    **证据坑位：** 〔填〕首屏关键接口列表与低端机滚动帧率观察。

14. **结论：** WebView Bridge 要版本协商、能力探测、来源校验与可追踪调用；返回栈要与原生协议一致。  
    **边界：** 浏览器与 App 内返回行为不同，不能只测系统浏览器。  
    **证据坑位：** 〔填〕Bridge 协议字段与一次返回栈错乱修复。

15. **结论：** 埋点不阻塞关键路径；采样与隐私合规要产品确认。  
    **边界：** 埋点脚本可毁 CWV；要预算与失败降级。  
    **证据坑位：** 〔填〕埋点对 LCP / INP 的影响评估。

16. **结论：** Modal 适合短确认，Drawer 适合长表单与详情；移动端优先全屏或底部面板。  
    **边界：** 无障碍：焦点陷阱、Esc、与读屏标签不能省。  
    **证据坑位：** 〔填〕关键流程的弹层选型与键盘走通记录。

## 高频追问速答

1. **前端藏菜单算权限做完了吗？**  
   不算。前端路由与按钮控制的是体验与误操作面，真正授权在服务端接口与数据范围。完整模型至少对齐菜单、路由、按钮码与 API；敏感操作还要审计。面试应能讲一次「界面无入口仍直接调接口被拒」的复测，以及角色变更后前端如何失效本地缓存并重新拉权限。

2. **ProTable 封装边界画在哪？**  
   标准查询、列、分页、选择与导出适合收进封装；强定制单元格、跨表联动、特殊编辑器应通过插槽或业务层扩展，而不是把所有 UI 做成无限 JSON。查询条件建议与 URL 同步，便于分享与刷新；并发请求要丢弃过期响应。配置项要有类型与默认值，避免每个页面一份隐性约定。

3. **表格很卡你怎么排？**  
   先看是不是一次渲染过多 DOM，再看列里有没有重组件、深响应式大对象、同步排序过滤。确认后再谈虚拟滚动、列懒渲染、浅响应式与服务端分页。注意普通纵向滚动不等于虚拟化；上了虚拟化还要验收键盘、选中、合并单元格与导出。用 Performance 与行数量级对照，避免凭感觉加 `v-once`。

4. **H5 滚动穿透怎么根治？**  
   打开遮罩时固定背景滚动并记录位置，关闭后恢复；只靠 `overflow: hidden` 在 iOS 上经常失效。弹层自身滚动要与页面滚动隔离，手势冲突要明确哪个容器接管。和软键盘一起出现时，优先保证聚焦输入可见，再处理可视视口变化。把打开、滚动、关闭写成可测状态，而不是每个弹窗复制粘贴一段 hack。

5. **弱网提交如何防重复？**  
   提交按钮进入 pending、生成幂等键、失败可恢复草稿，成功以服务端结果为准。重试要区分网络错误与业务拒绝；返回或杀进程后恢复要能识别「可能已成功」。离线队列要有上限与过期。演示用的乐观 UI 若不能在失败时回滚，就不要在面试里说成已交付能力。

6. **Bridge 调用失败你怎么排？**  
   先确认容器、协议版本与能力探测结果，再看调用是否在用户手势内、参数是否通过校验、回调是否超时。日志要带 trace id，两端都能关联。安全上校验来源与权限，不信任页面任意调原生。返回栈问题要同时看 Web 路由与原生栈，是否重复 push、是否拦截物理返回。只在系统浏览器通不够，必须真机 WebView 复现。

7. **Schema 表单什么时候不该用？**  
   当字段间存在复杂联动、逐步向导、强自定义布局或需要细粒度性能控制时，手写 Form 往往更可控。Schema 适合中低频变更的标准 CRUD，并且配置要可校验、可版本、可测试。若配置里开始写大量表达式脚本，说明抽象泄漏，应拆回业务组件，而不是继续加解释器。

8. **字典缓存脏了怎么办？**  
   字典必须有版本或更新时间；发布语义变更时要失效前端缓存，不能只靠长时间本地存储。启动与关键页可拉取，后台变更走通知或短 TTL。展示层不要把旧文案长期留给用户决策。比「多打一次字典接口」更贵的是错误枚举导致的错误业务操作，所以失效策略要写进发布清单。

## 反例 / 红线

- 只做前端菜单隐藏，宣称权限已完成。
- 无竞态处理的筛选 / 分页；用 index 当表格行身份。
- 把普通滚动表格说成虚拟列表；万级数据浏览器一次拉齐。
- H5 只测 Chrome 桌面，不测刘海、安全区与 App WebView。
- Bridge 无版本协商与来源校验；埋点阻塞首屏无 kill switch。
- Schema 配置变成不可测脚本引擎。

## 5 分钟口述稿

「业务前端我分中后台与 H5 两条线。中后台先讲权限闭环：菜单、路由、按钮、接口，前端隐藏不等于授权。列表页用 ProTable 思想收口标准能力，URL 同步查询，请求要防竞态；大表按 DOM 与响应式成本排，虚拟化要守交互边界。表单能配置则配置，复杂联动就手写；上传导出走任务化。多页签缓存有白名单，字典有版本失效。

H5 先定适配基线与安全区，滚动穿透与软键盘当状态机处理。弱网要幂等与可恢复，首屏抓关键请求与图片。在 App 里还要讲 Bridge 版本、安全与返回栈。最后用一次越权复测、一次大表治理和一次 WebView 真机问题收口。」
