# 模拟面试脚本

> **怎么用：** 找搭档或自学计时，严格按「流程 + 建议耗时」走完；项目深挖用 [故事示例](/interview/stories/examples)；模块题从题库抽，先口述再对 [参考答案](/interview/questions/02-vue3)；结束后用 [评分表](/interview/mocks/scorecard) 打分，反问环节用 [反问清单](/interview/mocks/reverse-questions)。

**通用规则：**

1. 每场选定一种脚本，不要中途换公司类型。
2. 模块题「抽 2～3 题讲透」优于「扫 10 题标题」。
3. 面试官角色可打断；候选人被打断后用「先结论后细节」接回去。
4. 全程录音或记关键词，复盘只改 Top 3 弱项。

## 脚本一：业务型中小厂（可抽查 Java 联调）

**画像：** ToB / 业务系统；看重稳定交付、中后台与工程化；可能问接口联调，不深挖微服务。  
**建议总时长：** 60～70 分钟  
**主故事：** [示例 A 管理后台](/interview/stories/examples#示例-aant-design-vue-管理后台)；备用一句带过 [示例 C](/interview/stories/examples#示例-cai--java-spring-boot--vue-全栈快速交付)。

| 阶段 | 建议耗时 | 面试官做什么 | 候选人目标 |
| ---- | -------- | ------------ | ---------- |
| 0. 开场与材料 | 2 min | 确认岗位、是否录屏 | 放松，确认计时 |
| 1. 自我介绍 | 3～5 min | 「做个自我介绍」 | 30～60s 人设 + 1 个代表项目钩子 |
| 2. 项目深挖 | 15～20 min | 围绕管理后台追权限 / 表格 / 性能 | 2 min 开场后进入 5 min 深度；用预埋追问 |
| 3. 模块题抽查 | 15～20 min | 从下方题库抽 2～3 题 | 每题 3～5 min，结论先行 |
| 4. 系统设计或协作 | 10～12 min | 偏业务协作 / 中后台设计 | 讲清约束、方案、取舍 |
| 5. 反问 | 5～8 min | 回答候选人问题 | 问 2～3 个有信息量的问题 |
| 6. 复盘打分 | 5 min | （搭档）填评分表 | 只记 3 条改进 |

### 阶段细则

**1. 自我介绍（3～5 min）**

- 结构：年限与主栈 → 业务领域 → 代表项目（钩子）→ 为什么看这个岗位。
- 控制在 2 分钟内讲完核心；留时间给面试官打断。

**2. 项目深挖（15～20 min）**

建议追问顺序（面试官按表点名）：

1. 权限模型与动态路由  
2. 表格性能或封装边界  
3. 一次线上问题或联调冲突  

候选人对照示例 A 的预埋追问作答。

**3. 模块题抽查（15～20 min）— 抽题指引**

从下列模块各抽 **至多 1 题**，合计 2～3 题：

| 优先级 | 模块 | 链接 |
| ------ | ---- | ---- |
| 必抽 | Ant Design Vue | [04-admin-antdv](/interview/questions/04-admin-antdv) |
| 必抽 | Vue3 或工程化 | [02-vue3](/interview/questions/02-vue3) · [03-engineering](/interview/questions/03-engineering) |
| 选抽 | Java 联调（接口 / 错误码 / 鉴权） | [07-java-fullstack](/interview/questions/07-java-fullstack) |
| 弱化 | 手写、过深原理 | 本场可跳过 |

**4. 系统设计或协作（10～12 min）**

选题（二选一）：

- 中后台「可配置列表 + 权限」怎么设计（可对照 [前端系统设计](/interview/questions/11-frontend-system-design)）  
- 和后端约定接口时冲突（字段变更、延期）你怎么推进  

考察：约束澄清、方案分层、风险与降级，而不是画一堆框。

**5. 反问（5～8 min）**

从 [反问清单](/interview/mocks/reverse-questions) 选「团队现状 / 业务 / 工程化」类；避开标注「慎问」且无铺垫的问题。

## 脚本二：创业 / AI 产品（加重 vibe coding + Java）

**画像：** 节奏快、要闭环；关心 AI 协作方式与全栈偏前能不能扛简单后端。  
**建议总时长：** 55～65 分钟  
**主故事：** [示例 C AI + Java + Vue](/interview/stories/examples#示例-cai--java-spring-boot--vue-全栈快速交付)；用 [示例 A](/interview/stories/examples#示例-aant-design-vue-管理后台) 或 [B](/interview/stories/examples#示例-buni-app--小程序跨端) 证明前端基本功（各 30～60s）。

| 阶段 | 建议耗时 | 面试官做什么 | 候选人目标 |
| ---- | -------- | ------------ | ---------- |
| 0. 开场 | 2 min | 说明本场偏产品与交付 | 对齐预期 |
| 1. 自我介绍 | 3～4 min | 听差异化（AI / 闭环） | 人设里主动点出 vibe coding 边界 |
| 2. 项目深挖 | 18～22 min | 深挖 AI+Java 故事；追审查与质量 | 讲清契约、审查清单、不做清单 |
| 3. 模块题抽查 | 12～15 min | AI + Java + Vue 各偏一题 | 展示「前端主身份 + 后端够用」 |
| 4. 系统设计或协作 | 10～12 min | 快速 MVP 架构或协作节奏 | 单体优先、可演进、质量闸 |
| 5. 反问 | 5～8 min | 偏业务与 AI 使用 | 摸清真实节奏与技术债态度 |
| 6. 复盘打分 | 5 min | 重点看「AI 协作」「前后端闭环」两维 | — |

### 阶段细则

**1. 自我介绍**

必须包含一句边界：

> 我主业是前端；用 AI 辅助 Spring Boot 做简单后端是为了交付效率，审查和线上责任仍在我。

**2. 项目深挖**

建议追问顺序：

1. 哪些交给 AI、哪些必须手写？  
2. 怎么防 AI 引入安全问题（越权、校验缺失）？  
3. 和「专职后端」的交接边界在哪？  
4. （可选）若需求膨胀，何时停手不上微服务？

**3. 模块题抽查 — 抽题指引**

| 优先级 | 模块 | 链接 |
| ------ | ---- | ---- |
| 必抽 | AI / vibe coding | [09-ai-vibe-coding](/interview/questions/09-ai-vibe-coding) |
| 必抽 | Java 全栈偏前 | [07-java-fullstack](/interview/questions/07-java-fullstack) |
| 必抽或强相关 | Vue3 | [02-vue3](/interview/questions/02-vue3) |
| 选抽 | 工程化（CI、环境、门禁） | [03-engineering](/interview/questions/03-engineering) |

**4. 系统设计或协作**

选题（二选一）：

- 「两周做一个内部管理工具」你怎么拆前后端与里程碑（对照系统设计题库里的 MVP 思路）  
- 产品天天改需求，你如何用契约 / 开关 / 分期保护交付  

**5. 反问**

优先「业务」「AI 使用」「成长空间」；可问模型、内部工具、技术债是否允许还。慎问融资与加班（见反问清单标注）。

## 脚本三：Lead 面（分工、质量、技术选型）

**画像：** 考察带人、决策、质量门禁、排期取舍；技术题服务于「你怎么判断」。  
**建议总时长：** 60～75 分钟  
**主故事：** 示例 A 或 C 任选一条讲透「决策」；穿插带人与门禁，不必三条故事全讲。

| 阶段 | 建议耗时 | 面试官做什么 | 候选人目标 |
| ---- | -------- | ------------ | ---------- |
| 0. 开场 | 2 min | 说明偏管理与技术决策 | 调整口吻：少背题，多讲判断 |
| 1. 自我介绍 | 4～5 min | 听管理半径与技术深度平衡 | 年限、带过人规模、代表决策 |
| 2. 项目深挖 | 15～18 min | 追取舍、冲突、事故复盘 | 用 STAR-L 的 L；给方案对比 |
| 3. 模块题抽查 | 12～15 min | Lead / 架构题为主 | 答「原则 + 例证」 |
| 4. 系统设计或协作 | 15～18 min | 选型 / 分工 / 质量体系 | 含「是否上 Java 单体」类题 |
| 5. 反问 | 5～8 min | 团队阶段、期望 Lead 产出 | 摸清权责与成功标准 |
| 6. 复盘打分 | 5～8 min | 五维里加重「决策取舍」 | — |

### 阶段细则

**1. 自我介绍**

建议包含：带过几人、是否扛过排期、一次你否决的技术方案（一句话钩子）。

**2. 项目深挖**

建议追问顺序：

1. 当时有哪些方案、为何选这个？  
2. 如何给同学拆任务与做 Code Review？  
3. 质量门禁（lint / 单测 / 发布）你守哪几条红线？  
4. 前后端分工争议如何收口？

**3. 模块题抽查 — 抽题指引**

| 优先级 | 模块 | 链接 |
| ------ | ---- | ---- |
| 必抽 | 架构 / Lead | [08-architecture-lead](/interview/questions/08-architecture-lead) |
| 必抽 | 工程化 | [03-engineering](/interview/questions/03-engineering) |
| 选抽 | 前端系统设计 | [11-frontend-system-design](/interview/questions/11-frontend-system-design) |
| 选抽 | AI 协作下的质量 | [09-ai-vibe-coding](/interview/questions/09-ai-vibe-coding) |
| 按 JD | Vue3 深度一题 | [02-vue3](/interview/questions/02-vue3) |

**4. 系统设计或协作（本场加长）**

必含一类选型题，例如：

- 新业务后端：继续现有 Java 单体 vs 新起服务 vs 前端 BFF——你怎么定？  
- 前端组 4 人、需求并行，如何排期与降风险？  
- 要引入 AI 编码，你如何定规范而不变成质量事故？

答法结构：**目标与约束 → 选项对比 → 决策 → 回滚 / 演进条件 → 对人的影响**。

**5. 反问**

优先「团队现状」「成长空间」「工程化」；问清 Lead 的成功指标（交付、质量、还是带人）。涉及编制、薪资结构标「慎问」的，本场若无 offer 阶段可跳过。

## 单人自测版（无搭档时）

| 步骤 | 做法 |
| ---- | ---- |
| 1 | 手机定时，按阶段闹铃 |
| 2 | 自我介绍与项目对镜子或录音 |
| 3 | 模块题：随机打开题库一题，盖住答案讲 4 分钟再对照 |
| 4 | 系统设计：只写 5 行提纲再口述 |
| 5 | 反问：大声读出你选的 3 个问题（练表述） |
| 6 | 用 [评分表](/interview/mocks/scorecard) 自评，凡 ≤2 分的隔日加练 |
