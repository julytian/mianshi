# 模拟面试脚本

> **怎么用：** 找搭档或自学计时，严格按「流程 + 建议耗时」走完；项目深挖用 [故事示例](/interview/stories/examples)；模块题从题库抽，先口述再对 [参考答案](/interview/questions/02-vue3)；结束后用 [评分表](/interview/mocks/scorecard) 打分，反问环节用 [反问清单](/interview/mocks/reverse-questions)。

**通用规则：**

1. 每场选定一种脚本，不要中途换公司类型。
2. 模块题「抽 2～3 题讲透」优于「扫 10 题标题」。
3. 面试官角色可打断；候选人被打断后用「先结论后细节」接回去。
4. 全程录音或记关键词，复盘只改 Top 3 弱项。
5. 标称时长均为**面试净时长**；复盘评分统一另加 5 分钟，不计入面试阶段合计。
6. 九维是完整评分框架；每场至少覆盖 7 维及目标岗位核心维，四个架构维度都必须有可记分问题。

## 脚本一：业务型中小厂（可抽查 Java 联调）

**画像：** ToB / 业务系统；看重稳定交付、中后台与工程化；可能问接口联调，不深挖微服务。  
**面试净时长：** 60 分钟；复盘 5 分钟另计。
**主故事：** [示例 A 管理后台](/interview/stories/examples#示例-a-ant-design-vue-管理后台)；备用一句带过 [示例 C](/interview/stories/examples#示例-c-ai-java-spring-boot-vue-全栈快速交付)。
**计分覆盖：** 技术深度、表达结构、前后端闭环、架构约束识别、原理深度、故障治理、演进能力；按岗位需要补决策取舍或 AI 协作。

| 阶段 | 建议耗时 | 面试官做什么 | 候选人目标 |
| ---- | -------- | ------------ | ---------- |
| 0. 开场与材料 | 2 min | 确认岗位、是否录屏 | 放松，确认计时 |
| 1. 自我介绍 | 4 min | 「做个自我介绍」 | 30～60s 人设 + 1 个代表项目钩子 |
| 2. 项目深挖 | 18 min | 围绕管理后台追权限 / 表格 / 性能 | 2 min 开场后进入 5 min 深度；用预埋追问 |
| 3. 模块题抽查 | 18 min | 从下方题库抽 2～3 题 | 每题 3～5 min，结论先行 |
| 4. 系统设计或协作 | 12 min | 偏业务协作 / 中后台设计 | 讲清约束、方案、取舍 |
| 5. 反问 | 6 min | 回答候选人问题 | 问 2～3 个有信息量的问题 |

### 阶段细则

**1. 自我介绍（4 min）**

- 结构：年限与主栈 → 业务领域 → 代表项目（钩子）→ 为什么看这个岗位。
- 控制在 2 分钟内讲完核心；留时间给面试官打断。

**2. 项目深挖（18 min）**

建议追问顺序（面试官按表点名）：

1. 权限模型与动态路由  
2. 表格性能或封装边界  
3. 一次线上问题或联调冲突  

候选人对照示例 A 的预埋追问作答。

**3. 模块题抽查（18 min）— 抽题指引**

从下列模块各抽 **至多 1 题**，合计 2～3 题：

| 优先级 | 模块 | 链接 |
| ------ | ---- | ---- |
| 必抽 | Ant Design Vue | [04-admin-antdv](/interview/questions/04-admin-antdv) |
| 必抽 | Vue3 或工程化 | [02-vue3](/interview/questions/02-vue3) · [03-engineering](/interview/questions/03-engineering) |
| 选抽 | Java 联调（接口 / 错误码 / 鉴权） | [07-java-fullstack](/interview/questions/07-java-fullstack) |
| 弱化 | 手写、过深原理 | 本场可跳过 |

**4. 系统设计或协作（12 min）**

选题（二选一）：

- 中后台「可配置列表 + 权限」怎么设计（可对照 [前端系统设计](/interview/questions/11-frontend-system-design)）  
- 和后端约定接口时冲突（字段变更、延期）你怎么推进  

考察：约束澄清、方案分层、风险与降级，而不是画一堆框。

**5. 反问（6 min）**

从 [反问清单](/interview/mocks/reverse-questions) 选「团队现状 / 业务 / 工程化」类；避开标注「慎问」且无铺垫的问题。

## 脚本二：创业 / AI 产品（加重 vibe coding + Java）

**画像：** 节奏快、要闭环；关心 AI 协作方式与全栈偏前能不能扛简单后端。  
**面试净时长：** 60 分钟；复盘 5 分钟另计。
**主故事：** [示例 C AI + Java + Vue](/interview/stories/examples#示例-c-ai-java-spring-boot-vue-全栈快速交付)；用 [示例 A](/interview/stories/examples#示例-a-ant-design-vue-管理后台) 或 [B](/interview/stories/examples#示例-b-uni-app-小程序跨端) 证明前端基本功（各 30～60s）。
**计分覆盖：** 决策取舍、AI 协作成熟度、前后端闭环、架构约束识别、原理深度、故障治理、演进能力；按岗位需要补技术深度或表达结构。

| 阶段 | 建议耗时 | 面试官做什么 | 候选人目标 |
| ---- | -------- | ------------ | ---------- |
| 0. 开场 | 2 min | 说明本场偏产品与交付 | 对齐预期 |
| 1. 自我介绍 | 4 min | 听差异化（AI / 闭环） | 人设里主动点出 vibe coding 边界 |
| 2. 项目深挖 | 20 min | 深挖 AI+Java 故事；追审查与质量 | 讲清契约、审查清单、不做清单 |
| 3. 模块题抽查 | 14 min | AI + Java + Vue 各偏一题 | 展示「前端主身份 + 后端够用」 |
| 4. 系统设计或协作 | 12 min | 快速 MVP 架构或协作节奏 | 单体优先、可演进、质量闸 |
| 5. 反问 | 8 min | 偏业务与 AI 使用 | 摸清真实节奏与技术债态度 |

### 阶段细则

**1. 自我介绍**

必须包含一句边界：

> 我主业是前端；用 AI 辅助 Spring Boot 做简单后端是为了交付效率，审查和线上责任仍在我。

**2. 项目深挖**

建议追问顺序：

1. 哪些交给 AI、哪些必须手写？  
2. 怎么防 AI 引入安全问题（越权、校验缺失）？  
3. 和「专职后端」的交接边界在哪？  
4. （可选）若需求膨胀，何时停手不上微服务？

**3. 模块题抽查 — 抽题指引**

| 优先级 | 模块 | 链接 |
| ------ | ---- | ---- |
| 必抽 | AI / vibe coding | [09-ai-vibe-coding](/interview/questions/09-ai-vibe-coding) |
| 必抽 | Java 全栈偏前 | [07-java-fullstack](/interview/questions/07-java-fullstack) |
| 必抽或强相关 | Vue3 | [02-vue3](/interview/questions/02-vue3) |
| 选抽 | 工程化（CI、环境、门禁） | [03-engineering](/interview/questions/03-engineering) |

**4. 系统设计或协作**

选题（二选一）：

- 「两周做一个内部管理工具」你怎么拆前后端与里程碑（对照系统设计题库里的 MVP 思路）  
- 产品天天改需求，你如何用契约 / 开关 / 分期保护交付  

**5. 反问**

优先「业务」「AI 使用」「成长空间」；可问模型、内部工具、技术债是否允许还。慎问融资与加班（见反问清单标注）。

## 脚本三：Lead 面（分工、质量、技术选型）

**画像：** 考察带人、决策、质量门禁、排期取舍；技术题服务于「你怎么判断」。  
**面试净时长：** 60 分钟；复盘 5 分钟另计。
**主故事：** 示例 A 或 C 任选一条讲透「决策」；穿插带人与门禁，不必三条故事全讲。
**计分覆盖：** 技术深度、表达结构、决策取舍、架构约束识别、原理深度、故障治理、演进能力；按场景补 AI 协作或前后端闭环。

| 阶段 | 建议耗时 | 面试官做什么 | 候选人目标 |
| ---- | -------- | ------------ | ---------- |
| 0. 开场 | 2 min | 说明偏管理与技术决策 | 调整口吻：少背题，多讲判断 |
| 1. 自我介绍 | 5 min | 听管理半径与技术深度平衡 | 年限、带过人规模、代表决策 |
| 2. 项目深挖 | 15 min | 追取舍、冲突、事故复盘 | 用 STAR-L 的 L；给方案对比 |
| 3. 模块题抽查 | 13 min | Lead / 架构题为主 | 答「原则 + 例证」 |
| 4. 系统设计或协作 | 18 min | 选型 / 分工 / 质量体系 | 含「是否上 Java 单体」类题 |
| 5. 反问 | 7 min | 团队阶段、期望 Lead 产出 | 摸清权责与成功标准 |

### 阶段细则

**1. 自我介绍**

建议包含：带过几人、是否扛过排期、一次你否决的技术方案（一句话钩子）。

**2. 项目深挖**

建议追问顺序：

1. 当时有哪些方案、为何选这个？  
2. 如何给同学拆任务与做 Code Review？  
3. 质量门禁（lint / 单测 / 发布）你守哪几条红线？  
4. 前后端分工争议如何收口？

**3. 模块题抽查 — 抽题指引**

| 优先级 | 模块 | 链接 |
| ------ | ---- | ---- |
| 必抽 | 架构 / Lead | [08-architecture-lead](/interview/questions/08-architecture-lead) |
| 必抽 | 工程化 | [03-engineering](/interview/questions/03-engineering) |
| 选抽 | 前端系统设计 | [11-frontend-system-design](/interview/questions/11-frontend-system-design) |
| 选抽 | AI 协作下的质量 | [09-ai-vibe-coding](/interview/questions/09-ai-vibe-coding) |
| 按 JD | Vue3 深度一题 | [02-vue3](/interview/questions/02-vue3) |

**4. 系统设计或协作（本场加长）**

必含一类选型题，例如：

- 新业务后端：继续现有 Java 单体 vs 新起服务 vs 前端 BFF——你怎么定？  
- 前端组 4 人、需求并行，如何排期与降风险？  
- 要引入 AI 编码，你如何定规范而不变成质量事故？

答法结构：**目标与约束 → 选项对比 → 决策 → 回滚 / 演进条件 → 对人的影响**。

**5. 反问**

优先「团队现状」「成长空间」「工程化」；问清 Lead 的成功指标（交付、质量、还是带人）。涉及编制、薪资结构标「慎问」的，本场若无 offer 阶段可跳过。

## 脚本四：微前端架构（60 分钟）

**画像：** 多团队、多技术栈或遗留系统渐进迁移；重点验证是否会识别边界、控制架构税并治理运行时故障。
**面试净时长：** 60 分钟；复盘 5 分钟另计。
**达标标准：** 能用业务与组织证据判断「上或不上」，讲清隔离 / 通信 / 共享依赖机制，并给出试点、监控、降级和退出路径。
**计分覆盖：** 技术深度、表达结构、决策取舍、架构约束识别、原理深度、故障治理、演进能力。

| 阶段 | 时间 | 内容 | 面试官观察点 |
| ---- | ---- | ---- | ------------ |
| 开场 | 3 min | 自我介绍，说明主导范围与微前端经验边界 | 是否诚实区分主导、参与和了解 |
| 项目深挖 | 12 min | 发布冲突、边界划分、迁移结果与一次故障 | 是否有基线、量化结果与复盘 |
| 题库抽查 | 12 min | 从 [微前端题库](/interview/questions/12-microfrontend) 抽 2 题 | 原理是否落到运行时证据 |
| 系统设计 | 20 min | 设计 Vue 2 到 Vue 3 的渐进迁移平台 | 约束、选型、契约、灰度、回退 |
| 加压追问 | 8 min | 主应用故障、共享依赖冲突、子应用失联 | 能否定位、止损并设计长期治理 |
| 反问 | 5 min | 团队边界、发布频率、平台责任人 | 是否先验证组织问题真实存在 |

### 面试官提问卡

- **项目深挖：** 当时为何不是 Monorepo、模块化或路由拆包？微应用边界如何验证？上线后发布等待和故障率怎样变化？
- **系统设计：** 要求不停服迁移、统一登录与埋点、子应用独立发布；请比较 qiankun / Garfish / Wujie / Module Federation 的适用边界，不要求背 API。
- **追问：** 样式或全局变量污染如何定位？共享 Vue 版本冲突如何处理？子应用超时、白屏、重复加载时怎样降级？试点失败如何退回单体？
- **反问：** 当前真正的发布冲突是什么？谁维护主应用和契约？故障责任与回滚权限如何划分？

## 脚本五：全栈偏前 NestJS（60 分钟）

**画像：** Vue 主栈，需要用 NestJS 承担 BFF 或中小型后端；不按专职后端的分布式深度考核。
**面试净时长：** 60 分钟；复盘 5 分钟另计。
**达标标准：** 能画清请求链路和模块边界，完成接口、安全、数据与生产治理闭环，并说清与 Spring Boot 的选择条件。
**计分覆盖：** 技术深度、决策取舍、前后端闭环、架构约束识别、原理深度、故障治理、演进能力。

| 阶段 | 时间 | 内容 | 面试官观察点 |
| ---- | ---- | ---- | ------------ |
| 开场 | 3 min | 前端主身份、后端责任边界与代表闭环 | 是否避免把「会调接口」包装成全栈 |
| 项目深挖 | 12 min | Vue + NestJS 项目的契约、鉴权、联调与上线 | 是否覆盖失败路径和责任归属 |
| 题库抽查 | 12 min | 从 [NestJS](/interview/questions/13-nestjs) 抽 2 题，并与 [Java](/interview/questions/07-java-fullstack) 对比 1 题 | 是否理解机制而非机械类比 Spring |
| 系统设计 | 18 min | 设计内部管理系统 BFF | 模块、校验、异常、权限、数据与部署 |
| 加压追问 | 10 min | 慢请求、重复提交、队列失败、发布回滚 | 故障治理与可观测性是否完整 |
| 反问 | 5 min | BFF 权责、Node.js 运维能力、后端协作 | 是否主动确认长期维护边界 |

### 面试官提问卡

- **项目深挖：** 哪些逻辑放 BFF，哪些留在前端或 Java 服务？接口契约如何防漂移？一次 401 / 403 或校验故障如何排查？
- **系统设计：** 为订单管理页设计 NestJS BFF，要求 RBAC、批量导出、幂等提交、审计日志和灰度发布。
- **追问：** Guard、Pipe、Interceptor、Filter 的顺序与职责是什么？Provider scope 选错会怎样？事务边界在哪里？事件循环被阻塞如何发现？何时迁移到 Spring Boot？
- **反问：** 团队是否已有统一日志、链路追踪和发布平台？BFF 是否拥有数据，还是只做聚合？值班和故障责任如何安排？

## 脚本六：高级前端架构（75 分钟）

**画像：** 高级前端、架构师或 Tech Lead；看重约束识别、原理深度、故障治理与持续演进。
**面试净时长：** 75 分钟；复盘 5 分钟另计。
**达标标准：** 先澄清质量属性和组织约束，再比较方案；能解释依赖机制、故障半径、演进触发器，并用项目证据承担决策责任。
**计分覆盖：** 技术深度、表达结构、决策取舍、架构约束识别、原理深度、故障治理、演进能力；按场景补 AI 协作或前后端闭环。

| 阶段 | 时间 | 内容 | 面试官观察点 |
| ---- | ---- | ---- | ------------ |
| 开场 | 5 min | 定位、管理半径、代表架构决策 | 是否用结果而非头衔证明资深度 |
| 项目深挖 | 15 min | 架构背景、备选方案、阻力、事故与演进 | 是否承认代价和信息不完整 |
| 题库抽查 | 15 min | [前端架构](/interview/questions/14-frontend-architecture) D 题 2 道，[架构 / Lead](/interview/questions/08-architecture-lead) 1 道 | 原理、约束与项目是否互相印证 |
| 系统设计 | 25 min | 设计多团队、多端业务平台 | 质量属性、边界、数据、交付、可观测性 |
| 加压追问 | 10 min | 流量突增、依赖故障、团队扩张、预算缩减 | 能否降级、止损并调整演进路线 |
| 反问 | 5 min | 架构权责、成功指标、技术债预算 | 是否判断岗位有无真实授权 |

### 面试官提问卡

- **项目深挖：** 哪项约束决定了架构？没选的方案是什么？最严重的一次故障如何发现、止损和防复发？何时发现原方案需要演进？
- **系统设计：** 设计一个覆盖管理后台与活动 H5、由 4 个团队并行交付的平台；要求核心链路可用、权限一致、独立发布、成本可控，并允许渐进迁移。
- **追问：** 指标没有基线时如何决策？微前端、Monorepo 与模块化如何取舍？共享状态如何约束？AI 生成代码如何进入架构门禁？半年后团队翻倍时先演进哪里？
- **反问：** 架构决策由谁签字并承担结果？稳定性与交付速度如何排序？技术债是否有预算和复审机制？

| 步骤 | 做法 |
| ---- | ---- |
