# 反问清单

> **怎么用：** 每场面试结束前准备 **2～3 个** 问题即可，按公司类型从下列分类里选。标 **慎问** 的题不是永远不能问，而是需要时机、关系与语气；初期面优先选无标注项。配合 [模拟脚本](/interview/mocks/scripts) 练表述。

**反问原则：**

1. 问你**决策需要**的信息（团队、业务、工程、成长），少问能在官网上查到的宣传语。  
2. 每个问题最好能接一句「我问这个是因为…」（与你的经历相关）。  
3. 听答案时可以短追问一次，不要变成第二场面试反过来盘问对方。  
4. 薪资、加班、竞品吐槽等敏感项见「慎问」说明。

---

## 一、团队现状

| 问题 | 备注 |
| ---- | ---- |
| 前端团队大概多少人？怎么分工（业务线 / 基础建设）？ | 常用开场 |
| 这个岗位在团队里最期望解决的前 1～2 个问题是什么？ | 高价值 |
| 目前团队的技术栈与版本大致是怎样的？（Vue 版本、TS 比例、是否 uni-app 等） | 验证匹配度 |
| 跨职能协作上，产品 / 设计 / 后端的对接节奏一般怎样？ | 了解摩擦点 |
| 团队里有没有 Tech Lead 或架构角色？决策一般怎么拍板？ | Lead 面可问 |
| 最近一年人员流动大概什么情况？ | **慎问** — 易显负面试探；若聊到稳定再轻问 |
| 我的前任为什么离开 / 这个坑空多久了？ | **慎问** — 首轮慎开；谈 offer 前后更合适 |

---

## 二、工程化与质量

| 问题 | 备注 |
| ---- | ---- |
| 现在本地开发、联调、预发、生产的发布链路是怎样的？ | 常用 |
| 有没有统一的 lint / CI / Code Review 要求？红线是什么？ | 展现质量意识 |
| 前端监控与报警（错误、性能、业务）目前覆盖到什么程度？ | 资深加分 |
| 多端（H5 / 小程序）若有，构建与发版是否分开验收？ | 对口多端经历时问 |
| 技术债有没有固定还债时间，还是全靠业务缝隙？ | 温和版 |
| 测试同学如何介入前端？有没有 E2E 或主力靠手工？ | 了解质量现实 |
| 你们会不会因为赶工而经常跳过 CR / 直接热修生产？ | **慎问** — 易变指责；可改成「线上热修的流程是怎样的」 |

## 三、业务与产品

| 问题 | 备注 |
| ---- | ---- |
| 这个岗位主要服务哪条业务线？当前最重要的业务目标是什么？ | 常用 |
| 需求通常从哪里来？迭代周期大概多长？ | 了解节奏 |
| 用户是内部员工还是外部客户？对稳定性 / 体验哪个更敏感？ | ToB / ToC 分寸 |
| 接下来半年，产品侧有没有已经拍板的大动作（重构、新端、新市场）？ | 判断挑战 |
| 成功入职 90 天，怎样算「这个人找对了」？ | 高价值 |
| 你们和主要竞品比，当前最大的产品差距是什么？ | **慎问** — 可能触及保密或不适；改问「市场里最在意的差异化」更稳 |
| 业务是否面临收缩或方向未定？ | **慎问** — 易显焦虑或刺探；信息面可从融资新闻侧面了解 |

---

## 四、AI 使用

| 问题 | 备注 |
| ---- | ---- |
| 团队日常开发里，AI 辅助编码是否鼓励？有没有内部规范和审查要求？ | 创业 / AI 面优先 |
| 有没有内部知识库、Copilot / 自建助手之类的落地？ | 了解成熟度 |
| 对「前端用 AI 补简单后端 / 脚本」持什么态度？边界怎么定？ | 对口全栈偏前叙事 |
| 产品本身是否 AI 驱动？前端在模型调用、流式输出、提示配置上参与多深？ | AI 产品公司 |
| 若 AI 生成代码导致线上问题，责任与复盘流程怎么走？ | 展现成熟度；语气要建设性 |
| 你们是否要求用某家模型、数据可否出境？ | 合规向；ToB 有用 |
| 不用 AI 会不会被认为落后？ | **慎问** — 易显抬杠；改为问规范与边界即可 |
| 能不能透露你们用 AI 省了多少人天？ | **慎问** — 像套数据；且对方往往答不准 |

## 五、成长空间

| 问题 | 备注 |
| ---- | ---- |
| 这个岗位的晋升或职级路径大致怎样？评审看重交付、影响力还是管理？ | 常用 |
| 团队是否支持对外分享、开源或内部技术分享？ | 学习氛围 |
| 若我想在〔工程化 / 多端 / 全栈协作〕上加深，会有怎样的发挥空间？ | 结合自身短板问 |
| Lead 方向：带人名额、是否需要从 0 建规范，公司怎么支持？ | Lead 面 |
| 入职后一般谁做我的 buddy / 导师？ | 温和 |
| 培训预算、会议或课程是否支持？ | 可问，别把钱当第一句 |
| 多久能调薪 / 年终怎么算？ | **慎问** — 首轮技术面不宜；放到 HR / offer 谈 |
| 期权 / 股权怎么算、稀释历史如何？ | **慎问** — 仅创业公司 offer 阶段；需懂基本常识再问 |
| 我能不能选更轻松的业务线？ | **慎问** — 易显避难；可问「业务线之间如何轮换」 |

## 六、按公司类型的推荐组合

### 业务型中小厂（脚本一）

1. 岗位最期望解决的前两个问题？  
2. 发布链路与 CR / CI 红线？  
3. 90 天怎样算找对了人？  

可选：Java / 后端协作节奏；慎问流动与加班强度（改问「迭代节奏」）。

### 创业 / AI（脚本二）

1. 产品现阶段最重要的验证指标是什么？  
2. 团队对 AI 辅助编码的规范与边界？  
3. 前端在闭环交付里被期望独立扛到什么程度？  

可选：技术债是否允许还；**慎问**融资细节、期权细节（非 offer 阶段）。

### Lead 面（脚本三）

1. 这个 Lead 角色的成功指标是什么（质量 / 吞吐 / 带人）？  
2. 技术决策如何拍板？我与上级 / 架构的边界？  
3. 团队工程化现状与最想补的一门禁？  

可选：编制与招聘支持；**慎问**前任离职原因（可晚些再问）。

## 七、表述模板（练开口）

**稳妥：**

> 我想了解一下，这个岗位在接下来一个季度最希望接手的人优先搞定哪两件事？我问这个是为了对齐我过往在〔中后台 / 多端 / 闭环交付〕上的经验。

**工程向：**

> 方便介绍一下现在的发布与 Code Review 习惯吗？我比较关心质量红线是怎么守的。

**AI 向：**

> 团队在 AI 辅助开发上有没有约定哪些必须人工审查？我自己用 AI 时会把权限和校验当作必审项，想看看是否和你们节奏一致。

**Lead 向：**

> 对这个角色，三个月后怎样算合格、一年后怎样算出色？我想确认公司更期待交付结果还是组织建设。

## 八、慎问汇总（速查）

以下问题默认 **慎问**——换表述或换到 HR / offer 阶段：

| 原问题倾向 | 更稳妥的替代 |
| ---------- | ------------ |
| 加班多吗 / 是否 996 | 迭代节奏与线上保障方式是怎样的？ |
| 工资多少 / 多久涨薪 | 与 HR 确认带宽；技术面问成长路径 |
| 前任为何走 / 流动率 | 团队最近在扩张还是稳定建设？ |
| 公司是不是快不行了 | （不问）改从业务目标与半年规划了解 |
| 竞品吐槽 / 内幕数据 | 差异化与用户最在意的点是什么？ |
| 期权细节 / 融资条款 | offer 阶段再专项聊 |
| 能不能少干活选轻松组 | 业务线如何分工、是否有轮换 |

## 九、反问禁忌（简记）

- 一上来连续五个薪资福利题  
- 问面试官「我能过吗」  
- 用反问炫耀：把问题变成自己讲 10 分钟  
- 质疑面试官技术水平  
- 打听其他候选人情况  

练熟后回到 [模拟脚本](/interview/mocks/scripts) 整场串连；评分用 [评分表](/interview/mocks/scorecard)。
